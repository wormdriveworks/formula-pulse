# 개선 회차 8 — 결산 화면 주 버튼 마우스 클릭 무반응 (2026-09-07)

> 세션 문서 (개선 모드). 설계 정본 D01~D16 은 참고 자료이며 사용자 요청이 우선한다. 단일 세션 · 주력 GUI 머신(Windows · GDAI).

## 0. 보고와 범위

**사용자 보고:** "레이스 종료 후 화면 우측 하단의 '개러지로', '다음 투어로' 등 다음 화면 이동 역할의 버튼이 마우스 클릭으로 동작하지 않습니다."

**해당 화면 3종 (모두 같은 구조):**

| 화면 | 주 버튼 문면 | 파일 |
|---|---|---|
| RACE-03 그랑프리 결산 | [다음으로] / [투어 결산으로] | `godot/ui/race/gp_result_screen.gd` |
| SET-01 투어 결산 | [개러지로] | `godot/ui/settle/tour_report_screen.gd` |
| SET-02 시즌 결산 | [시즌 오버홀로] | `godot/ui/settle/season_result_screen.gd` |

패드 A · 키보드 Enter 는 정상이었다(포커스 경로). 그래서 회차 1(2026-09-01) 순위표 도입 이후 6일간 실기·검사 모두 잡지 못했다 — 실기는 패드로 진행했고, 검사의 "마우스 경로" 축은 시그널을 직접 쏘았다(§3).

## 1. 원인

세 화면의 `_mount_standings()` 가 코드로 세우는 순위표:

```
Pad(MarginContainer)
 ├ Column(VBox) … Footer(HBox) ─ NextButton   ← 우하단
 └ StandingsPane(Control, IGNORE)             ← Column 뒤에 add_child = 히트테스트 최상단
    └ StandingsTable(VBoxContainer)            ← anchor 0.55~1.0 × 0~1 (offset_top 26/40)
```

- `StandingsTable` 은 **Container 라 기본 `mouse_filter = PASS`** 다. 히트테스트(`_gui_find_control_at_pos`)는 자식을 먼저 훑고 IGNORE 가 아닌 첫 Control 을 돌려주므로, 우하단 주 버튼 위에서는 **표가 잡힌다**.
- PASS 로 잡힌 Control 이 쓰지 않은 이벤트는 **부모 방향으로만** 흐른다(pane → Pad → 화면 루트). 형제 트리에 있는 `NextButton` 에는 영원히 닿지 않는다.
- 부모 `StandingsPane` 을 IGNORE 로 둔 것은 자식을 막지 못한다 — 히트테스트는 자식 우선이고, IGNORE 는 그 노드 자신만 제외한다.

결과: 버튼 위에서 눌러도 hover·press 가 버튼에 도달하지 않는다. 라벨 자식은 기본 IGNORE 라 문제가 없고, 표 컨테이너 한 노드가 원인이다.

## 2. 수정

세 화면 모두 표를 만드는 자리에 한 줄:

```gdscript
table.mouse_filter = Control.MOUSE_FILTER_IGNORE
```

- RACE-03 주석에 기제를 적고 SET-01·SET-02 는 그 주석을 참조한다.
- 씬(`.tscn`) 무접촉 · 스트링 무접촉 · 값 창구 무관.

## 3. 검사 — UISCR 실 히트테스트 축 신설

기존 축 `_mouse_click_paths` 의 "경로 등가" 부분은 `confirm.pressed.emit()` 으로 클릭을 대신했다. **시그널 직접 발화는 포인터 결선의 증거가 아니다** — 버튼 위에 다른 Control 이 얹힌 결함을 원리적으로 못 본다. 그래서 `_settle_next_button_mouse_hit()` 을 신설했다(`godot/tests/test_ui_screens.gd`).

| 요소 | 내용 |
|---|---|
| 소재 | GP 를 실제로 끝낸 세션 3개(`_finished_gp_session` — begin_gp → start_gp → begin_turn/spin/timeout 루프 → close_gp; SET-01 은 +close_tour, SET-02 는 +close_season). 순위표가 서야 재현된다. |
| 마운트 시점 | 프레임 1 (`_settle_next`) — 버튼 rect 는 컨테이너 정렬이 끝나야 값이 있다(§ LAYOUT_SETTLE_FRAMES). |
| 입력 | 뷰포트 `push_input` 에 `InputEventMouseButton` press/release, 좌표 = 버튼 `get_global_rect().get_center()`(캔버스 좌표 · `in_local_coords = true`). |
| 단언 | ⓐ 방어 창(InputGuard 0.4s) 동안 마우스 클릭이 버튼에 닿지 않는다 → 창 `free()` → ⓑ 화면별 4축: 순위표 rect 가 버튼 중심을 덮는 배치(재현 조건) · `pressed` 1회 · `gui_input` 눌림 수신자 == NextButton · 표 mouse_filter == IGNORE. |
| 배치 | **주 프레임 첫 축.** 결산 화면의 InputGuard 는 `_input` 층에서 `ui_accept`·마우스 버튼을 트리 전역으로 삼키므로, 세워 둔 채 뒤 축이 패드 A(= ui_accept)를 `push_input` 하면 죽는다. 창을 걷고 화면을 내린 뒤 나머지가 돈다. |

**선 FAIL → 후 PASS:**

```
수정 전  [FAIL] gp_result_screen.tscn — 마우스 클릭 → 주 버튼 pressed 1회 — presses=0 눌림 수신=["StandingsTable"]
         [FAIL] … 눌림을 받은 Control = 주 버튼 — ["StandingsTable"]
         [FAIL] … 순위표 mouse_filter = IGNORE — mouse_filter=1          (× 3화면 = 9건)
         UI_SCREENS_FAIL failures=9 checks=898
수정 후  UI_SCREENS_PASS checks=898
기준본  HEAD 하네스 + 수정 화면 = UI_SCREENS_PASS checks=874 (ERROR 잡음 3건·!is_inside_tree 2건은 기준본에도 동일 — 기존 음성 축의 정상 출력)
```

## 4. 실기 — 실 창 좌표 프로브

GDAI `simulate_input` 은 액션 전용이라 좌표 마우스 클릭을 넣을 수 없다. 대신 임시 프로브 씬(`tests/_r8_click_probe.*`, 사용 후 삭제)을 에디터에서 `play_scene` 으로 돌려 **실 창 픽셀 좌표**로 `push_input(…, in_local_coords = false)` 했다 — 실 마우스가 타는 역변환(최종 변환) 경로와 같다.

```
R8_TABLE  mouse_filter=2 rect=[P: (349.6, 50.0), S: (266.4, 286.0)]     ← 표가 버튼 중심을 덮는 배치 그대로
R8_BUTTON text=다음으로 canvas=(594.0, 327.0) window=(1782.0, 981.0) window_size=(1920, 1080)
R8_HIT NextButton
R8_NAVIGATE target=RUN-02
R8_PRESSED NextButton
```

캔버스 → 창 배율은 정확 3×(레터박스 0). 버튼이 눌림을 받고 화면이 전이(RUN-02 = 이벤트 발생 분기)를 요청했다. 저장은 `SaveManager.use_test_root()` 격리 루트.

**사용자 실마우스 확인 (커밋 266a839 뒤, 객관식 회신):** 수정본으로 레이스를 끝내고 결산 화면에서 [다음으로]/[개러지로] 를 실제 마우스로 클릭 → **정상 동작(다음 화면으로 이동)**.

## 6. 운영 메모

- **`project.godot` 재직렬화:** 세션 시작 시 작업 트리의 `project.godot` 이 주석 소실·섹션 재배열 상태였다(전 회차 말 복원본이 아님). 에디터 (재)시작 때 GDAI 가 오토로드를 재등록하며 `ProjectSettings.save()` 를 부르는 경로다. 설정 의미는 같고 커밋만 하지 않으면 된다 — 게이트 trap 의 제거식은 재직렬화본에도 그대로 맞았다.
- **`simulate_input` 의 한계:** 액션 이름만 받는다. 포인터 실기는 프로브의 `push_input` 으로 대체한다(§4 좌표 규약).
- **InputGuard 전역 삼킴:** 하네스에서 결산 화면을 세워 두면 다른 축의 `ui_accept` 가 죽는다(§3 배치).
