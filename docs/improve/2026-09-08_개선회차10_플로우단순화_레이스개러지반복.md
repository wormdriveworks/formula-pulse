# 개선 회차 10 — 플로우 단순화: 레이스 ↔ 개러지 반복 (2026-09-08)

> 세션 문서 (개선 모드). 설계 정본 D01~D16 은 참고 자료이며 사용자 요청이 우선한다. 단일 세션 · 주력 GUI 머신(Windows · GDAI).
> **상태: 구현 완료 · 게이트 녹색 · 사용자 실기 확인 대기** (§5 결정 4건 반영 · §6 구현 · §7 검사/게이트/실렌더 · §8 상태).

## 0. 요청

**사용자:** 전체 플로우를 변경한다. 현재는 VN 파트 → 레이스(투어 = 4대회, 대회 사이를 **중간정산**으로 구분) → 개러지 흐름이다. **투어 개념은 그대로 두되, 중간정산 없이 모든 대회 뒤에 개러지로 복귀**한다 — 레이스 ↔ 개러지 반복으로 단순화. 먼저 고려 사항을 확인하고 전체 수정 설계를 세운 뒤, 주요 변경점 확인 후 구현.

**용어 대응 (코드 실측):** "중간정산" = **RUN-01 간이 정산 화면**(`ui/run/run_recap_screen`) — 대회 사이에만 서는 화면으로 필드 정비·소모품 보충·덱 교체 3기능을 인라인으로 갖는다(D07 §1.2 "3종 상한"). 투어 결산(SET-01)은 별개 화면이며 이 요청의 "중간정산"이 아니다.

## 1. 현행 플로우 (코드 실측)

```
SYS-02 신규 ─→ NAR-01 시즌 개막(+캘린더) ─→ [NAR-01 1막·브리핑 사슬] ─→ RACE-01
SYS-02 계속 ─→ resume_route(): 투어 중 = RACE-01 / 투어 마감 저장분 = close_tour→SET-01 / 시즌 마감 = close_season→SET-02

RACE-01 ─close_gp─→ RACE-03 (저장 · settle_gp)
   ├ 투어 내 잔여 GP ──→ judge_event ─→ [RUN-02 이벤트] ─→ RUN-01 간이 정산 ─→ RACE-01      ← 중간정산 구간
   └ 최종 GP / 리타이어 ─→ close_tour ─→ SET-01 투어 결산 (저장 · settle_tour)
                                           ├ 잔여 투어 ─→ [NAR-01 마일스톤] ─→ HUB-01 개러지
                                           └ 시즌 최종 ─→ close_season ─→ SET-02 ─→ HUB-08 ─→ [NAR-01 엔딩] ─→ HUB-01
HUB-01 ─출발(저장)─→ [NAR-01 시즌 개막 — 시즌 첫 투어만] ─→ [NAR-01 브리핑 사슬 — 막 VN + 재회 비트] ─→ RACE-01
```

| 항목 | 실측 |
|---|---|
| 개러지(HUB-01) 진입 빈도 | **투어당 1회**(SET-01 뒤) — 이 불변식 위에 출발 시 브리핑 VN 발행·투어 경계 저장이 얹혀 있다 |
| 소모품 구매 지점 | **RUN-01 이 유일**(`buy_consumable` 화면 소비처 = RUN-01 만) — HUB-02 정비 베이에는 없다(§A-12 는 "소모품 서브 카드"를 규정했으나 미구현) |
| 필드 정비(K2) 지점 | RUN-01 만 (회당 30CH 상한 · 200Cr × 1.5^n 체증 · 복원선 70 까지) |
| 전면 정비(K3) 지점 | HUB-02 만 (20Cr/CH · 100 까지) |
| 덱 교체 | RUN-01 인라인 + HUB-04 전략실 |
| 저장 지점 | RACE-03 진입 · HUB-01 출발 · SET-01 진입 · HUB-08 시즌 전환 |
| 라우팅 대장 | 20 경로 (RUN-01 포함) |

## 2. 목표 플로우

```
RACE-01 ─close_gp─→ RACE-03 (저장 · settle_gp)
   ├ 투어 내 잔여 GP ──→ judge_event ─→ [RUN-02 이벤트] ─→ HUB-01 개러지            ← RUN-01 소거
   └ 최종 GP / 리타이어 ─→ close_tour ─→ SET-01 ─→ (종전과 동일) ─→ HUB-01
HUB-01 ─출발(저장)─→ [개막 — 시즌 첫 GP 만] ─→ [브리핑 사슬 — **투어 첫 GP 만**] ─→ RACE-01
SYS-02 계속 ─→ resume_route(): 투어 중 = **HUB-01**(결정 대기) / 나머지 종전
```

개러지 진입 = **GP당 1회**. 투어·시즌·챔피언십 계층, 투어 포인트 2층 구조, 탈락 규칙, 투어 경계 처리(막 래치·관계 공표·무상 복원선·체증 리셋·스킬 투어 횟수·차지 환전)는 **전부 그대로**다.

### 3.2 세션·서사 (VN 슬롯) — **가장 중요한 결선 지점**

| # | 항목 | 실측·판단 |
|---|---|---|
| B1 | 브리핑 사슬 게이트 **필수** | `take_brief_payload()` 는 "HUB-01 출발 = 투어당 1회" 불변식에 기대어 **게이트가 없다.** 재회 브리핑 비트(`vnbeat_reunion_alta`)는 무대·관계 단계만 보고 `vn_seen` 을 보지 않으므로 알타 리지 투어에서 **매 GP 같은 VN 이 다시 서고**, `trigger_vn` 이 매번 시즌 상한 15 를 소비하며(시즌 1 은 정확히 15 를 채운다 — IMPL-355) 재회 카운터 투어 상한 2 도 첫 두 GP 에 소진된다. **게이트 = `season.race_slot == 1`** (투어 첫 GP 앞의 출발) — `vn_slots.csv` 의 `trigger = tour_start` 문면 그대로다. 세션 창구에 두어 SYS-02 신규 경로(race_slot 1)도 같은 조건을 지난다 |
| B2 | 막 VN 대기열 | `act_vn_pending` 은 `close_tour()` 의 `latch_narrative_act()` 와 커리어 개시에만 채워진다 → 채워지는 시점은 항상 race_slot 1 이라 B1 게이트와 정합. 게이트로 빈 사전을 돌려도 대기열은 남아 다음 투어 첫 출발에 선다 |
| B3 | 시즌 개막 VN | `vn_seen` 시즌당 1회 가드 보유(24차) — 매 GP 출발에도 두 번 서지 않는다. 무변경 |
| B4 | 마일스톤 VN(tour_close) | SET-01 이탈 자리 그대로. 무변경 |
| B5 | 재개 창의 막 VN 재발화 (부수) | `_on_depart` 는 **저장 뒤에** 대기열을 소비한다 → 브리핑 VN~다음 RACE-03 저장 사이에 종료하면 세이브에 대기열이 남아 **다음 출발에 막 VN 이 다시 서고 시즌 상한을 1 더 소비**한다(선재 잠복 — 현행은 다음 투어 출발에 나타난다). 재개 착지를 HUB-01 로 바꾸면 이 재발화가 재개 직후로 당겨져 눈에 띈다. **부수 교정:** `take_brief_payload` 가 막 VN 대기열 중 `vn_seen` 인 id 를 버린다(막 VN 은 정의상 1회 — `act_vn_fired` 가 이미 그렇게 세운다). 재회 비트는 손대지 않는다(무대·단계 재발화가 서사 레인 설계일 수 있다) |

### 3.3 경제·규칙

| # | 항목 | 실측·판단 |
|---|---|---|
| C1 | 필드 정비 vs 전면 정비 | D07 §1.2 는 대회 간 = 필드만 · 투어 간 = 전면만으로 **시점을 갈라** 두 정비를 구분했다. 개러지가 매 GP 서면 그 구분의 근거(시점)가 사라진다. 두 안: **유지** = HUB-02 에 필드 정비 카드를 추가(복원선 70 까지 30CH·체증, 그 위는 전면 20Cr/CH — 규칙·코어·TC-O 검사 무변경, 화면만 추가) / **폐지** = 전면 정비만(K2 규칙·파라미터 4행·TC-O 검사 9건·러너 정책이 사문화 → 별도 정리 회차 필요). §5 Q2 |
| C2 | 투어 경계 처리 | `outgame.begin_tour()`(체증 리셋·스킬 투어 횟수 리셋·무상 복원선) · `settle_tour`(S3·S4·차지 환전) · 막 래치·관계 공표 — 전부 `close_tour()` 경유로 **무변경**. 투어 개념 유지의 실체 |
| C3 | 축적형 Sink 접근 빈도 | 튜닝·스킬 해금·시설·스폰서 계약이 투어당 1회 → **GP당 1회** 접근. 규칙·가격 무변경, 소비 기회만 4배. 수입은 GP 정산(S1·S2)이 GP 마다 들어오므로 "번 돈을 바로 쓰는" 리듬이 된다 — 사용자 의도의 귀결 |

| C5 | 스폰서 정산 | `settle_sponsors()` 는 **게임 코드 어디서도 호출되지 않는다**(검사에서만) — S8 정기 수입 미결선은 선재 공백. 본 회차 범위 밖(기록만) |

### 6.3 설계에서 실행으로 옮기며 확인한 것

- **브리핑 게이트는 세션 한 곳이다.** SYS-02 신규 경로(race_slot 1)와 HUB-01 출발이 같은 창구를 지나므로 화면은 조건을 모른다. 조건 밖에서 대기열을 소비하지 않는 것이 요점 — 소비해 버리면 다음 투어 첫 출발에 막 VN 이 서지 않는다.
- **막 VN `vn_seen` 중복 제거는 재개 착지 HUB-01 의 짝이다.** 착지가 개러지로 바뀌면서 "저장 뒤 대기열 소비" 순서의 재발화 창이 재개 직후로 당겨진다 — 막 VN 은 1회성이라 버려도 손실이 없고, 재회 비트는 서사 층 설계(무대·단계 조건)라 손대지 않았다.
- **라우팅 대장 하한.** 종전 UISCR ⑳ 전제가 `>= 19` 였고 RUN-01 을 빼면 18 이다 — 대장 실물이 18 이므로 하한을 18 로 내렸다(검사가 "화면이 사라졌다"를 잡아내는 것은 ⓕ 축의 몫이다).
- **HUB-02 소모품 버튼은 실 클릭으로 잰다.** 코드 생성 Container 의 기본 mouse_filter PASS 함정(회차 8)이 있는 화면 계열이라 `pressed.emit()` 이 아니라 뷰포트 `push_input` 으로 버튼 중심을 누른다. 구매 뒤 목록이 재생성되므로 포커스 복귀와 보유 표기까지 같은 축이 본다.
