# 개선 회차 9 — 듀얼 표시 재배치: 릴 존 합체 + 씬 패널 캡션 띠 (2026-09-08)

> 세션 문서 (개선 모드). 설계 정본 D01~D16 은 참고 자료이며 사용자 요청이 우선한다. 단일 세션 · 주력 GUI 머신(Windows · GDAI).

## 0. 보고와 결정

**사용자 보고:** 레이스 중 듀얼이 모달로 뜨는데 조작 버튼은 본 화면에 있어 모달 뒤에 가려진다. 키보드로는 되지만 직관적이지 않고 마우스 사용자는 아무 조작도 할 수 없다. 모달 위치도 애매하다(화면 중심도 아니고 의도가 안 느껴짐). 제안 = 기본 스핀 자리를 덮는 위치 + 딤 제거 → 최소 수정으로 마우스 조작 확보 + "기본 스핀이 듀얼 스핀으로 변한" 시각 효과. 더 좋은 방안이 있으면 제안 요청.

**실측 (수정 전 · 캔버스 640×360):**

| 항목 | 값 | 의미 |
|---|---|---|
| `DuelOverlay/Dim` | 전면 · mouse_filter **STOP** | 아래 버튼 전부 마우스 차단 — 보고의 직접 원인 |
| `DuelFrame` | P(320,180) S(300×111) · 앵커 0.5·오프셋 0·성장 기본값 | **좌상단 모서리가 화면 정중앙** → 우하단으로 흘러 로그 피드를 덮음 (배치 결함 · UISCR ⑫ 미포착) |
| 엔진 게이트 | `hold_respin()` 듀얼 무게이트 · 차지 개입 허용 · 듀얼 전용 스킬 3종 | 듀얼 턴에도 홀드·리스핀·차지·스킬이 **정규 조작**인데, 듀얼 릴엔 홀드 칸이 없고 기본 홀드는 딤 아래 → 마우스로는 홀드도 불가 |
| 릴 존 세로 예산 | ReelColumn 187px 중 여유 = 스페이서 16px | O6(타이머 수치) 켜짐 → 0 · SH3 스냅숏 행 → 0 |

**객관식 결정 (사용자):**
1. 방안 = **A. 릴 존 합체** (B 원안 그대로 · C 최소 교정 대비) — 듀얼 릴 3기를 기본 릴 프레임 자리에 그대로, 홀드 생존.
2. 딤 = **완전 제거**.
3. 대치 표기·부스트 줄 자리 = **씬 패널 하단 캡션 띠** — A 안 초안의 "홀드~베인 빈 띠"는 위 세로 예산 실측으로 성립하지 않아 재질문(씬 패널 상단 띠 · 빈 띠 유지 대비).
4. 듀얼 릴 프레임 표식 = **핑크(SYMBOL_CHANCE #FF4FB0) · 2px** — 패드 커서 강조(시안)와 색이 갈려 듀얼 중 커서 이동이 표식을 지우지 않는다.

## 1. 구조

```
[수정 전]                                   [수정 후]
DuelOverlay (STOP)                          DuelOverlay (IGNORE · 전면 · 비가시 기본)
 ├ Dim (전면 · STOP · 45% 검정)               └ DuelBar (PanelContainer · IGNORE) ← 씬 패널 하단에 코드 배치
 └ DuelFrame (중앙 앵커 결함)                    └ Row (HBox · IGNORE · 가운데 정렬)
    ├ VersusRow (No.13 · 종류 · 상대)               PlayerLabel · KindLabel · OpponentLabel
    ├ DuelReels (전용 릴 3기 44px)                  BoostStack · BoostButton (유일한 포인터 수신자)
    ├ BoostRow (◇◇◇◇ · 부스트 투입)                ResultLabel (결과 국면에만)
    └ ResultLabel
릴 표시 배열: 듀얼 중 오버레이 릴로 스왑          릴 표시 배열: 항상 기본 릴 (스왑 없음) — 프레임 테두리만 듀얼색·2px
```

- **띠의 자리는 노드를 따라간다.** `DuelOverlay.place_over(host)` 가 씬 패널 호스트(`%E15ScenePanel`)를 받아 그 실 rect 의 하단·폭 전체에 띠를 앉히고, 호스트 `item_rect_changed` 와 띠 `minimum_size_changed` 에 재배치를 건다. rect 스냅숏 초판은 정렬 전에 불리면 0 폭을 박제했다(하네스 실측 §3) — 그래서 노드 추종으로 바꿨다. 앵커·오프셋을 쓰지 않으므로 ANCH 규약 밖이고, 레이아웃 비율(좌열 6:4)에 묶이지 않는다.
- **씬 패널이 자리인 이유.** 비인터랙티브(`ScenePanel` 전 노드 IGNORE)라 무엇을 덮어도 조작을 막지 않고, 릴 존 세로 예산과 무관하게 늘 100px 이 있다. 릴 바로 위라 "대치 → 릴 → 홀드 → 액션"이 한 덩이로 읽히고, 듀얼 대치 컷의 자막처럼 보인다(릴 국면엔 패널이 감광 상태라 가독 양호). 덮는 것은 컷 하단 20px.
- **릴 프레임 표식은 `_refresh_reel_frames()` 의 세 번째 채널이다.** 감광(홀드 = modulate) · 색(커서 = 시안) · 두께+색(듀얼 = 2px 핑크). 세 채널이 서로를 지우지 않는다. 기본 두께는 씬 스타일에서 읽어 둔다(`_reel_frame_border_base`) — 코드에 적지 않는다. `DUEL_FRAME_BORDER = 2` 는 종전 듀얼 프레임 스타일(씬 2px)의 승계.
- **표시 배열 스왑 제거.** `_base_reel_icons`·`reel_icons()` 삭제. SEAL-E(`_screen._reel_icons`)·캡처 하네스는 같은 배열을 계속 본다 — 이제 그 배열이 실제 릴이라 봉인 검사가 보는 것과 화면이 갈릴 여지가 없다.
- 씬 `.tscn`: `Dim`·`DuelFrame`·`DuelReels`·셀 3기 삭제, 셀 스타일 3종 삭제, `StyleBoxFlat_1d076` 을 띠 스타일(BG_PANEL 알파 0.86 · 상단 1px 핑크 · 여백 6/1)로 재정의. 라벨 unique name 은 전부 유지(G4W·문면 소비부 무접촉).
- 부수 1건: `_ensure_default_focus()` 에 `is_inside_tree()` 가드 — 릴 공개 코루틴이 화면 언마운트 뒤 재개되며 `get_viewport()` null 로 `gui_get_focus_owner` 스크립트 에러를 내던 종료 잡음(UISCR 로그 실측). 거동 무변경.

프레임 1 에 `_settle_race` 에 듀얼을 강제해 두고(띠·버튼 rect 는 정렬 뒤에 값이 있다) 주 프레임에서 잰다:

## 6. 운영 메모

- **오버레이 배치를 rect 스냅숏으로 하면 하네스 프레임 1 에서 0 폭이 박힌다** — 노드를 넘겨 `item_rect_changed` 를 따라가면 정렬 시점과 무관하다. 실기(턴 개시)에서는 두 방식이 같지만, 검사가 강제하는 문맥까지 같은 코드로 서는 쪽이 옳다.
- **릴 존 세로 예산은 꽉 차 있다(187px).** 스페이서 16px 은 O6·SH3 가 먹는다 — 릴 존 안에 새 행을 얹는 제안은 이 실측을 먼저 본다.
- UISCR 종료 시 `gui_get_focus_owner` 스크립트 에러 = 언마운트된 레이스 화면의 코루틴 재개(포커스 가드로 해소). `!is_inside_tree()` 2건·음성 축 push_error 3건은 기준본 동일 잡음.
