# 개선 회차 17 — 개러지 복귀 자동 저장 (2026-09-11)

> 세션 문서 (개선 모드). 설계 정본 D01~D16 은 참고 자료이며 사용자 요청이 우선한다. 단일 세션 · 주력 GUI 머신(Windows · GDAI).
> **상태: 구현 완료 · 게이트 녹색 · 사용자 확인 대기.** §4 검사·게이트 · §5 상태.

## 0. 요청 (사용자 · 2026-09-11)

> 개러지에서 각 하위 메뉴로 진입해 작업 후 다시 개러지로 돌아올 때 자동 저장되도록 해 달라.

## 1. 선재 상태

| 항목 | 실측 |
|---|---|
| 저장 지점 (종전) | RACE-03 진입(`gp_result_screen._on_bound`) · 투어 경계(SET-01 `_on_bound`) · 시즌 경계(HUB-08 `_leave`) · **개러지 출발 전**(`garage_screen._on_depart`) — D09 §2.4 대장 |
| 하위 스테이션 작업 | HUB-02 정비·소모품 · HUB-03 튜닝 · HUB-04 덱 편성 · HUB-06 스폰서 체결 · HUB-07 시설 확장 — 전부 **인메모리에만** 남고 "다음 대회 출발"까지 디스크에 닿지 않았다 |
| 복귀 경로 | `HubScreen` 공통 — 뒤로 버튼(`_fill_common_bar`)과 Esc·패드 B(`_unhandled_input`) 두 자리에서 각각 `go("HUB-01", {})` |
| 실측 재현 (실 라우터 워크) | 잔액 1000 → 정비 베이에서 소모품 구매 → 인메모리 625 · **디스크 1000**(구매 직후). 이 상태에서 종료하면 구매가 사라진다 |

회차 15(시즌 엔딩 VN 기록 소실)와 같은 형태의 창이다. 그때는 VN 발생 기록, 여기는 아웃게임 상태이고, 둘 다 "게임을 끄기 자연스러운 정지점이 저장 지점이 아니다"가 원인이다.

## 2. 결정 (라운딩 판단 — 문의 없음 · §5 객관식으로 확인)

- **저장 시점 = 나가는 쪽**(스테이션의 복귀 경로). 개러지 도착(`_on_hub_ready`)에 두면 레이스·이벤트·시즌 체인에서 들어온 도착까지 함께 저장하는데, 그 경로들은 이미 자기 저장 지점을 지나온 뒤라 같은 상태를 두 번 쓴다. 스테이션을 떠나는 자리가 "작업이 끝난 지점"과 정확히 겹친다.
- **창구 1개.** 뒤로 버튼과 Esc·패드 B 가 `HubScreen._return_to_garage()` 하나로 모인다 — 경로가 둘이면 한쪽만 저장하는 결함이 조용히 생긴다.
- **조건 없이 저장한다.** "작업이 있었을 때만"은 변경 추적(dirty)이 필요한데, 추적이 한 지점만 빠져도 그 작업이 조용히 사라진다. 열람만 한 기록실(HUB-05) 복귀도 같은 상태를 다시 쓸 뿐이라 손해가 없다.
- **개러지 자신은 제외**(`_saves_on_return()` 재정의 = false) — 돌아올 자리가 아니고, 뒤로 버튼도 숨긴다.
- **저장 실패는 조용히 넘기지 않는다** — `push_error` + 저장 표시(app_root)는 실패에 뜨지 않는다(기존 계약 그대로).

## 3. 구현

```
종전: 스테이션 작업 → 뒤로 → HUB-01 (저장 없음) → … → "다음 대회 출발" 에서 첫 저장
회차 17: 스테이션 작업 → 뒤로/Esc → _return_to_garage(= save_progress → go HUB-01) → 개러지에 저장 표시
```

## 5. 정본 대비

- D09 §2.4 저장 지점 대장에 **"개러지 복귀"가 추가된다.** 정본은 이 자리를 저장 지점으로 열거하지 않았다(회차 10 에서 이미 대장이 한 번 움직였다 — 간이 정산 소거·개러지가 GP 마다 서는 구조). 사용자 요청이 우선하며, 세이브 파일 형식·마이그레이션과는 무관하다(같은 `serialize()` 를 쓴다).
- D12 §6.4 재로드 리롤 무효 — RNG 상태는 세이브에 직렬화되므로 저장 지점이 늘어도 리롤 창이 생기지 않는다. 스테이션에는 난수 소비가 없다.
