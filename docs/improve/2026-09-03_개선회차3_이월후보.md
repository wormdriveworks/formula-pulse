## 1. 소형 코드 2건

### 1.1 결산 오입력 방어 창 (회차 1 이월)

- **증상**: 레이스 끝까지 확정 키(Space·Enter·A)를 연타하던 손이 RACE-03 에 그대로 닿으면 결산이
  읽히기 전에 지나간다(회차 1 실측 — 배치 입력이 결산을 지나침). SET-01·SET-02 도 같은 계열.
- **수정**: `godot/ui/com/input_guard.gd` 신설 — 화면 **자식 노드 1개**로 붙는 방어 창.
  `_input` 층(GUI 입력보다 앞)에서 `ui_accept` 액션·마우스 버튼만 삼키고, `remaining` 이 0 이 되면
  스스로 사라진다. Esc·일시정지·포커스 이동은 지나간다 — 방어 대상은 '진행'이지 '조작'이 아니다.
- **왜 자식 노드인가**: 베이스(FlowScreen)에 `_input`/`_process` 를 두면 같은 이름을 정의한 화면
  (race_screen)에서 조용히 죽는다(GDScript 자동 super 없음 — flow_screen.gd `_shortcut_input` 주석과
  같은 사유). 자식 노드는 상속 계층과 무관하다.
- **값 창구**: `core_params.csv` `param_settle_input_guard_sec = 0.4` 신설(수치 코드 기입 금지 규율 유지 —
  D13 대장 밖 신설분, 이 문서가 근거). 소비처 = RACE-03·SET-01·SET-02 3화면.

### 1.2 H5 — HUB-08 시즌 체인 무후보 출구

- **증상(에지)**: 후기 시즌에 전 오버홀(12종)을 보유하면 `draw_overhaul_candidates` 가 후보 0 을 돌려주고
  화면은 전 보유 목록을 비활성으로 그린다. 시즌 체인은 뒤로가 숨겨져 있어 **고를 것도 나갈 곳도 없다.**
  슬롯 0(등급표 밖 rank)도 같은 상태. 부수: 화면에 **초기 포커스가 없어** 시즌 체인에서 패드·키보드로는
  어느 버튼에도 닿을 수 없었다(회차 1·2 포커스 계열 동형).
- **수정** (`overhaul_screen.gd`):
  - `_selectable_count()` — 헤더·목록과 같은 원천(`_shown_candidates`)에서 선택 가능 후보를 센다
    (종전 `_has_selectable_candidate` 는 추첨 배열만 봐서 폴백 목록에서는 늘 0).
  - 선택 가능 0 또는 잔여 슬롯 0 → `_arm_pass_through()`: 확정 버튼을 **[오버홀 없이 진행]** 으로 바꾸고
    목록 머리에 사유 안내 1줄(`ui.overhaulScreen.noCandidates`). 출구는 설치 확정과 같은 `_leave()`
    (엔딩 VN → 다음 시즌 → 저장).
  - `_focus_initial()` — 첫 선택 가능 후보 → 확정/통과 버튼 → 뒤로 순으로 초기 포커스.
- 스트링 2키 신설 (ko/en/ja).

## 3. SET-01 투어 결산 조판

- **증상**: 좌정렬 라벨 6행 나열 — 화면 절반이 빈 채로 P{n} 한 줄. 기능 정상.
- **수정**:
  - 상단 헤더 행(RACE-03 동형): 표제 + **탈락 배지**(사실 표기 한 단어 — 소프트 실패 문면 유지) + **저장 배지**
    (SET-01 도 저장 지점인데 표시가 없었다) · 부제 `시즌 {season} · 투어 {tour}` (마감 투어 번호는 리포트가 쥔 값 —
    시즌 층은 이미 다음 투어로 넘어가 있다).
  - **투어 종합 순위 값 = 표제 계열(Galmuri14 · 14px) + 강조색(C3)** — 화면의 주역.
  - **우측 절반 = 투어 순위표** (전 16대 · 플레이어 행 강조) — RACE-03 순위표와 같은 앵커 문법.
    소재 = `close_tour()` 리포트에 `tour_points` 스냅숏 신설(`begin_tour()` 가 누계를 비우기 전 값).
    표기명 = `FlowScreen.entrant_name()` (SET-02 전용 함수를 베이스로 끌어올려 두 화면이 공유).
- 스트링 5키 신설. 씬 편집 = `tour_report_screen.tscn` (헤더 행·부제·순위 값 서체/색).

## 4. E13 소모품 패드 열 — 현행 패드 맵 조사

| 버튼 | 공통 층 | RACE-01 컨텍스트 층 |
|---|---|---|
| A(0) | 확인·진행 | 스핀 = 확정 |
| B(1) | 취소·닫기 | — |
| X(2) | — | 짧게 = 리스핀 · **홀드 + 십자키 ← → → A = 릴 홀드 토글** |
| Y(3) | 상세 정보 | **차지 개입** (상세는 LB 홀드 + Y 로 재배치) |
| LB(9) / RB(10) | 탭 전환 | LB 홀드 + Y = 상세 · **RB 홀드 + 십자키 → A = 스킬 슬롯 1~5** |
| Start(6) | 일시정지 | 일시정지 |
| 십자키·좌스틱 | 포커스 이동 | 포커스 이동 (X·RB 홀드 중은 조합 커서) |
| **미사용** | Back(4) · Guide(5) · L3(7) · R3(8) · **LT/RT(축 4·5)** · 십자키 ↑↓(조합 내) · 우스틱 | |

- 소모품 2슬롯 후보:
  - ⓐ **LB 홀드 + 십자키 ← → → A** — 스킬(RB 홀드) 문법의 거울. LB 는 상세(LB+Y)만 쥐고 있어 충돌 없음.
    조작표 문면 "LB 홀드 + 십자키 → A". 신규 문법 0.
  - ⓑ **LT / RT 트리거 = 슬롯 1 / 2 직결** — 단발·가장 빠름. 축 이벤트 임계 판독(0.5 교차) 신설 필요,
    조작표에 트리거 열 신설.
  - ⓒ **LB 홀드 + A / LB 홀드 + B** — 조합 2종 직결(커서 없음). 신규 문법.
- 권고 = ⓐ (기존 조합 문법 재사용 · 커서 = 포커스 링 · 테스트 하네스 `_pad_event` 로 검증 가능).
