## 1. 조사 (재현 2단)

### 1.1 실화면 사슬 (헤드리스 · 세션 + 화면 인스턴스 · 테스트 루트)
GP 20 회 자동 주행으로 시즌 1 을 끝낸 뒤 SET-01 → (마일스톤 VN) → SET-02 → HUB-08 포기 확정(다이얼로그) → 출구.

| 관측 | 값 |
|---|---|
| HUB-08 `_leave()` 출구 | NAR-01 · `vn_id = vn_season_close_s1` · 3라인 — **엔딩은 정상 발행된다** |
| `_leave()` 안 시즌 경계 저장분 | `close_s1` **없음** · 저장된 시즌 = 2 |
| NAR-01 마운트 뒤 메모리 | `close_s1` 있음 · `season_vn_count` 1(**새 시즌** 계수) |
| 개러지 도착 시점 저장분 | `close_s1` **없음** (개러지 도착은 저장 지점이 아니다) |
| "다음 대회 출발" 뒤 저장분 | `close_s1` 있음 (여기서야 남는다) |
| 경계 저장분으로 재개 | 착지 HUB-01 · 시즌 2 · `close_s1` 없음 · `season_close_payload` 는 이제 s2 를 가리킴 → **s1 은 영구 회복 불가** · 개막 s2 는 출발 때 정상 발행 |

### 1.2 실 라우터 워크 (`app_root` · 실창 · 화면마다 1장)
시즌 최종 SET-01 진입 저장분을 테스트 루트 프로필 1 에 심고 SYS-01 계속 → SYS-02 슬롯 1 → (`resume_route` → close_season) SET-02 → HUB-08 포기 → 다이얼로그 OK 버튼 → **NAR-01 엔딩(화면으로 선다 — 정비대 바탕 · 지문 1라인)** → HUB-01. 관측값은 1.1 과 동일: VN 시점 `save_has_close=false` · 개러지 시점 `save_has_close=false`. 6장(`r15/walk_01~06`).

### 1.3 결론
- 엔딩 VN 은 **발행·표시된다.** 결함은 **저장 순서**다 — HUB-08 확정의 시즌 경계 저장이 엔딩 화면보다 앞이고, 엔딩 발생 등재는 화면이 하므로 저장분에 없다. 엔딩 VN 도중 또는 개러지 체류 중(시즌이 끝난 자연스러운 정지점)에 종료하면 다음 저장 전이라 기록이 사라지고, 엔딩 id 가 떠난 시즌의 것이라 재개가 다시 만들지 않는다 → **아카이브 영구 소실.** 실 프로필 2벌 · 전환 4회 · 0건은 이 창에 전부 걸렸다는 뜻이다(개막은 출발 때 다시 서므로 남는다 — 두 프로필의 비대칭이 그 증거).
- 사용자가 엔딩을 기억하지 못하는 것은 장면 자체가 개러지 바탕 + 지문 1라인으로 시작해 "시즌 엔딩"으로 인지되기 어려운 문면이라는 점과 겹친다(문면 판단은 D04 트랙 몫 — 기록만).
- **부수 결함:** 엔딩 발생 계수가 `begin_next_season()` 뒤 화면에서 일어나 **새 시즌의 상한 15 를 1 소모**했다(`overhaul_screen._leave` 주석 "엔딩은 떠나는 시즌의 것"과 반대).
