## 0. 배경 — 사용자 보고 2건 + 규칙 결정 1건 (2026-09-17)

| # | 보고·지시 | 처리 |
|---|---|---|

## 1. 확인 ① — "전방 +5" 는 참이고, 같은 턴에 저항이 더 크게 깎는다

정산 8단계(불변규칙 3)는 그대로다. 관련 자리만 적으면:

```
④ 전진·공략   슬립스트림 +24/56/95 · 라인 +11/22/36 · 찬스 +40/80 · 모멘텀 +5  ← 로그 "전방 +5" 는 여기
⑤ 만충 판정   앞차 저항 −(3.0 + 앞차 페이스 × 1.5)  · 뒤차 압박 +(2.0 + 뒤차 공격성 × 2.2) × 소속 계수   ← 로그 없음
              0~100 절단 → 만충 판정(상대가 있어야 예약)
```

앞차 저항은 D13 별첨A §2.1 의 값(필러 7.5 · 로렌츠 10.8)이고 배치(⑤ 직전)는 IMPL-010 [가안]이다. **모멘텀 +5 만 있는 턴은 어떤 앞차 상대로도 순감**이라 0 에서 출발한 전방은 0 에 머문다(절단). 슬립스트림 1개(+24)가 함께 나와도 순증은 +13~+16 이라 표시된 +24·+5 보다 작게 움직인다. 즉 ①은 **계산 오류가 아니라 저항이 로그에 없는 것**이다 — 매뉴얼 표(전방 게이지 행)에는 "매 턴 앞차 저항만큼 깎임"이 적혀 있으나 화면 로그는 말하지 않는다. 어떻게 보일지는 설계 층 판단이라 객관식으로 올린다(§7 Q1).

검사 근거: TC-C7 이 이 산술(표값 − 저항 · 배틀 존 계수)을 이미 단언하고 있고, `_neighbor_passive_runtime` 이 디아스 압박 16.9 를 실측한다.

## 2. 확인 ② — 후방이 일찍 꽉 차는 두 형태

| 형태 | 기제 | 판정 |
|---|---|---|
| **뒤차가 없는 자리의 죽은 누적** | 첫 GP 는 P16 고정(D13 별첨A §6.3)이고 이후에도 최후미가 잦다. 뒤차 압박(⑤)만 `rear_target` 을 봤고 **트러블의 후방 가산(①)은 상대 없이도 쌓였다.** 만충 판정은 `rear_target != ""` 를 요구해 듀얼로 터지지 않고, 이웃이 바뀌지 않으니 리셋도 없어 **레이스 내내 꽉 찬 채 굳는다.** 뒤차가 전원 리타이어한 뒤도 같다 | **결함 형태 → ③으로 해소** |
| 뒤차 있는 첫 스핀의 고점 | 트러블 3매치 +48 + 디아스 압박 16.9 = 64.9 · 배틀 존 ×1.5 면 **97.4** — 첫 스핀에 "꽉 찬" 것으로 보인다(3매치 확률 0.58%/스핀) | 설계값 그대로 — 무접촉 |

## 3. 구현 — 후방 가산 창구

| 파일 | 변경 |
|---|---|
| `godot/core/state/race_engine.gd` | `_add_rear_gauge(delta)` 신설 — **양수 delta 는 `rear_target == ""` 이면 버린다.** 후방 대입 4경로(①트러블 · ③브레이킹 · ④라인 · ⑤뒤차 압박)가 전부 이 창구를 지난다. 감산은 통과(0 하한 절단이 받는다). 8단계의 순서·구성 불변 — 각 단계 안의 대입이 창구를 거칠 뿐이다 |
| `godot/tests/test_tc_c.gd` | 축 `_rear_gauge_needs_target()` ⓐ~ⓔ (§5) · 부수 교정 2건 (§5) |

정본과의 관계: D05 §4.2 는 후방 게이지를 "뒤차의 압박으로 **상대 측에** 축적", §5.2 트러블 효과를 "후방 게이지 **상대** 가산"으로 적는다 — 상대가 없는 축적은 대상이 없는 값이라 **충돌이 아니라 미규정 자리의 사용자 결정**이다(불변규칙 9 해당 없음 · impl_log 등재).

**전방의 대칭** — 선두(P1)면 `front_target == ""` 인데 슬립스트림·모멘텀·찬스는 그대로 전방을 올리고, 만충 판정은 상대를 요구해 터지지 않으며 리셋도 없어 같은 형태로 굳는다(찬스 3매치 "즉시 듀얼"도 선두에서는 만충만 남는다). 지시 ③의 범위가 후방이라 건드리지 않았다 — §7 Q2.

**부수 교정 2건 (검사 증거 규칙).** 새 규칙이 두 기존 프로브의 전제를 드러냈다:
- `_insure_outcome`(SI2/SI3 대조군) — 최후미 격리로 트러블의 후방 가산을 재고 있었다. 새 규칙에서는 0 이 되므로 **뒤차 1명(최후미)을 두고 압박을 계산해 뺀다.** 세 프로브의 뒤차 불변 전제를 추가.
- `_rear_pressure`(OV-S3 대가 ×1.1) — 같은 최후미 격리라 뒤차 압박 자체가 0 이었고 **0 == 0 × 1.1 을 통과시키고 있었다** (종전부터 · 이번 규칙과 무관한 공검사). 뒤차 1명을 두고 "기저 압박 > 0" 전제를 추가 — 이제 실측 8.6 × 1.1 을 잰다.
- `_expected_rear_pressure` 는 기저 2.0 만 돌려주던 미사용 헬퍼였다 — 엔진이 읽는 **시드 공격성**(`_flatten_neighbors` 가 눕히지 않는 값)으로 계산하도록 고쳤다.

## 7. 상태

- 구현 완료 · **사용자 확인 대기.** 실기: 최후미(P16)에서 트러블이 나와도 후방이 0 에 머무는가 · 뒤차가 있으면 종전대로 오르는가 · 뒤차가 리타이어해 뒤가 비면 그 뒤로 오르지 않는가.
- **객관식 2건 — 답 수령 (2026-09-17) → 회차 31 (IMPL-530) 에서 구현.** Q1 = **매 턴 로그 1줄** · Q2 = **같은 규칙 적용**. 질문 원문:
  - **Q1** ① 의 가독 — 앞차 저항·뒤차 압박을 화면에 어떻게 보일지: ⓐ 매 턴 로그 1줄(저항 −n · 압박 +n) ⓑ 확정 직후 게이지 옆 **순변화 플로트**(전방 ±n · 후방 ±n — D09 §3.4 모멘텀 플로트 규격의 확장) ⓒ 그대로(매뉴얼 표기만).
  - **Q2** 전방의 대칭 — 선두(앞차 없음)에서도 전방이 오르지 않게 같은 규칙을 둘지.
- 매뉴얼 4차 개정(아티팩트 v5): 후방 게이지 행에 "뒤에 아무도 없으면 오르지 않습니다" · 매스트헤드·푸터.
