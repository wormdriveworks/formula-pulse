## 0. 문서 목적·범위

본 문서는 《Formula Pulse: Spin the Grid》의 **기술 아키텍처·데이터 구조·플랫폼 연동의 구현 규격**을 확정하여, D13(데이터 테이블 & 밸런스)이 값을 채울 스키마와 D14(QA)가 실행할 검증 게이트를 제공한다. 선행 문서가 확정한 규칙·구조·기준값을 **재정의하지 않고 구현 층으로 번역**하는 것이 본 문서의 역할이다.

**범위 가드 (결정 로그 #1):**

| 본 문서 소관 | 타 문서 소관 |
|---|---|
| 엔진·스택 선정, 아키텍처, 상태 머신, 데이터 스키마(필드·타입·구속), RNG·세이브, 스트링 키 구조, 렌더·오디오·광고 SDK의 구현 구조, 검증 게이트 정의 | **수치·확률·기본값의 실제 값 = D13** (본 문서는 필드의 존재·상한의 존재만 규정 — D09 결정 #5 전례) / 화면 배치·문면 = D09·D09-2 / 아트 실규격 = D10 / 사운드 목록·규칙 = D11 / 광고 규칙 층 = D16 / QA 시나리오 = D14 / 실코드 미작성 (설계 전속) |

## 3. 턴제 상태 머신 (D05 §2~§3 1:1 — DoD #3)

### 3.1 상위 상태 계층 (확정)

```
[BOOT] → [TITLE] → [PROFILE_LOAD]
   → [HUB] (개러지·시설 — D07/D09 §4 화면군)
   → [SEASON_FLOW] (캘린더·이벤트 슬롯·VN 재생 — D08 §2·§7)
   → [GP] (그랑프리 상태 머신 — §3.2) → [RESULT] (정식 저장 지점 — §7.2)
   → (시즌 결산 — 에필로그 판정 D08 §8.9) → HUB 복귀
```

- 화면 25종(+모바일 27종)의 명칭·전이는 **D09 §8.1 대장·D09-2 플로우맵이 정문** — 본 절은 상태 층 골격만 규정하며 화면 목록을 복제하지 않는다(§0.7-5).
- 모바일 광고 노드(AD-01/AD-02)는 상태 머신의 노드가 아니라 **RESULT→HUB 전이 훅의 플랫폼 어댑터 호출**(§11)이다 — 코어 상태도 무접촉.

### 3.2 GP 상태 머신 (D05 §3 다이어그램 1:1 — 폐쇄성 검증)

`GP_START → LAP_LOOP → SECTOR_TURN(T1~T6) → {DUEL 복귀 | RETIRE | 다음 SECTOR_TURN} → 랩 종료 분기 → GP_FINISH → RESULT`

- **폐쇄성 검증 (확정):** 전 상태·전이는 D05 §3 다이어그램으로 폐쇄 — 고아 상태 0·미정의 전이 0. 구현은 명시적 상태 enum + 전이 표(데이터가 아닌 코드 상수 — 규칙 층은 데이터 교체 대상이 아님).
- 실시간 처리·물리 판정 부재(D01 §8-2) — 프레임 의존 로직 금지, 전 판정은 턴 이벤트 구동.

### 3.3 턴 시퀀스 T1~T6 (D05 §2.3)

| 단계 | 구현 요지 |
|---|---|
| T1 섹터 개시 | 섹터 속성 로드·상황 표시 이벤트 발행. 레조넌스 섹터 진입 시 **발동 공표 이벤트**(D08 §3.7 — 위치 정보는 이 시점까지 비노출, §6.3) |
| T2 스핀 | 플레이어 입력 대기(시간 제한 없음 — D05 §7.1) → 릴 RNG 스트림 소비(§6.1) → 순차 정지 연출 |
| T3 잠정 결과 | 정지 결과 = 전개 후보 상태 보관 |
| T4 개입 창 | 소프트 타임 리미트 타이머 가동(배율 옵션 D09 §6.2 연동). 홀드/리스핀(턴당 1회 한도 카운터)·스킬·차지 개입·확정 — 각 개입은 커맨드 큐로 직렬 처리 |
| T5 확정·번역 | 결과→중계 로그 **텍스트 키 발행** (D05 §2.3 — 실텍스트 풀은 D04 트랙, 키 구조 §8.1) + 씬 컷 매핑 평가(§5.9) |
| T6 적용·정산 | §3.4 파이프라인 |

- 릴 국면(T1~T4) / 전개 국면(T5) / 시스템(T6)의 화자·연출 분리는 D05 §2.3·D04 §8.1 정문 — 구현은 국면 태그를 이벤트에 부여해 화자 라우팅.

### 3.4 정산 파이프라인 — 8단계 고정 (D05 §5.3 · **C-2 구속 승계 — P-3, DoD #14**)

T6 정산은 코드 고정 순서 **①위험(트러블) → ②자원(펄스) → ③방어 → ④전진·공략 → ⑤게이지 만충 판정 → ⑥듀얼 발동 → ⑦순위 갱신 → ⑧백그라운드 AI**로 구현한다.

- **C-2 구속 명문:** 레조넌스 정산은 위 8단계의 **내부 데이터(단계별 파라미터 필드)로만** 구현한다. **신규 단계·신규 타이밍 창의 추가를 금지**한다 — 파이프라인 단계는 데이터가 아닌 코드 상수로 고정하여 데이터 층에서의 단계 신설을 구조적으로 차단한다(§5.5).
- ⑧백그라운드 AI = 플레이어 비인접 구간 AI 간 순위 스왑(확률 판정 — ai 스트림 §6.1, 수치 D13).

| 구조·계층 데이터 (이벤트 인스턴스·매핑·조건) | **JSON** | 중첩 표현. 스키마 검증 용이 |
| 스트링 테이블 | **CSV** (키 행 × 언어 열) | 번역 왕복 표준 |

- 콘텐츠(서킷·이벤트·스킬·라이벌·심볼 인스턴스)는 전량 데이터 정의 — 코드는 타입·규칙만 보유. 심볼 종수 확장(D05 §5.2 "분류 6종 안에서의 인스턴스 추가")·이벤트 교체가 코드 무변경으로 성립.
- 테이블 ID 규칙 (확정): `snake_case`, 도메인 접두(`skill_`, `event_`, `circuit_` …), 전역 유일 — **스트링 키(§8.1 camelCase·`.` 파싱 대상)와 별개 체계**(결정 #9·#10: 테이블 ID는 `.` 미사용 정적 데이터라 혼선 벡터 부재).

## 5. 데이터 스키마 상세 (구조 전속 — 값 전량 D13)

> 표기: 필드의 **존재와 구속**은 확정, 필드 명명은 구현 시 §4.1 규칙 내 조정 가능. 값·개수는 D13.

### 5.1 스킬·덱 (D07 §4)

- `skill`: id / 명칭 키 / **스킬 티어**(1~3 — T-1 완칭 구속, §8.3) / 개입 훅 타입(개입 창 효과·상시 등 — D07 §4 분류) / 효과 파라미터(타입+값 참조) / 비용(펄스 차지)·횟수 필드.
- `deck`: 슬롯 수 2→5 해금 상태는 세이브 소관(§7.1) — 덱 구성 = 스킬 id 배열, 슬롯 상한 검증 V1.

### 5.2 크루·관계 상태 (D07 §5.5 — 형식 2종, DoD #10)

- `crew`: id / 직능(1:1 매핑 — D07 §5.1) / 영입 상태·조건 참조.
- **형식 A — 사건 연동:** `relation_transition_a`: 이벤트 ID → (축, 목표 상태) 매핑 테이블. **전이 판정 = 이벤트 '발생(도달)' 기준 — 열람·스킵 여부를 조건으로 삼지 않는다** (D07 v1.1 §5.5 구속 명문). 아카이브 재열람 재발화 없음 = 전이 처리의 멱등 플래그(이벤트 ID당 1회 소비).
- **형식 B — 누적 카운터:** `relation_counter`: 카운터 정의(듀얼 수행·선착·인접 완주 등) + 임계값 테이블(값 D13). **카운터 감소 없음**(후퇴 전이 없음 — D04 §4 전진형 승계, 감산 API 미제공으로 구조 보장). **전이 공표 스냅**: 임계 도달은 상시 판정, 상태 공표(파일 갱신·변형 풀 교체)는 다음 이벤트 슬롯/대회 경계에 지연 커밋(D07 §5.5) — 펜딩 큐 필드.
- 저장 위치 = 라이벌 파일 데이터(세이브 §7.1). 축 비대상 네임드 3인은 상태 필드 없음(프로필·전적만 — D07 §5.5).

### 5.3 스폰서 계약 (D07 §7)

`sponsor_contract`: 계약 인스턴스 id / 조건(형식 B 카운터 재사용) / 보상(Source 참조 — D06 §2.1 S1~S10 외 신설 금지, V2가 Source enum 검증) / 기간·상태.

### 5.4 이벤트 (D08 §7.3 변형 태그 · §2.3 앵커 결속 — DoD #13)

- `event`: 기본 인스턴스 id / **변형 조건 태그 배열**(막·무대·관계 상태·순위 인접 |Δ|≤2 등 — D08 §7.3) / VN·보상 참조 / **재출현 쿨다운 = 동일 인스턴스 3회 판정 간격**(카운터 세이브 저장).
- **앵커 필드(확정 구속):** `anchor_type ∈ {milestone_act, stage, tour_slot}` + `tour_slot ∈ {1, 5}만 허용` — **중간 슬롯(2~4) 결속은 V5가 빌드 차단** (D08 §2.3의 기계적 이행).
- 변형 조건식은 **제한 조건 DSL** (확정: 필드 비교·AND/OR 한정, 스크립트 임베드 금지 — 데이터에 로직 침투 차단).

### 5.5 레조넌스 (D08 §3.7 — **C-2 구속**, DoD #14)

- `resonance`: 섹터 슬롯 속성 플래그 + 정산 파라미터 필드(3매치 성공률 보정·보너스 규모 — **§3.4 기존 8단계의 해당 단계 내부 파라미터로만 소비**, 값 D13 R5).
- 추첨(R6): 투어 개막 시 1회 — resonance 스트림(§6.1)으로 (서킷 슬롯 × 섹터 슬롯) 추첨·세이브 저장. **위치 필드 = UI 비노출 마킹**(진입 시 발동 공표까지 비공개 — D08 §3.7).

### 5.6 칭호·업적 플래그 (D08 §8.9 — DoD #13)

- `title_flag`: 보유 칭호 상태(예: '더블 챔피언' — 병립·박탈 없음, D04 §9) → **중계 텍스트 변수 분기 입력**(§8.2). 스트링 키 = **키 단위 치환 전속**(T-1 — §8.3).
- 업적: 정의 테이블(달성 조건 참조·히든 플래그) → IAchievement 매핑(§7.4). Steam 히든 플래그 1:1(D09 §5.5).

### 5.7 베인 대사 풀 3단계 교체 (D03 파생 — DoD #11)

- 베인 대사 키에 `stage ∈ {1,2,3}` 필드 — **키·풀은 불변, 선택 계층이 현 단계로 필터**(풀 스왑 = 필터 전환, 데이터 복제 없음). 단계 임계 = 주행 데이터 누적 총량 연동(D07 §5.6 — 0.35×E1/1.0×E1 구조, 절대값 D13).
- 단계 전이 커밋 = 대회 경계 스냅(D06 §5.4 베인 경계 스냅 승계 — 레이스 중 톤 급변 방지).

### 5.8 연출 등급 L0~L3 데이터 구조 (D04 §5.5 — DoD #12)

- 결과·이벤트 인스턴스에 `grade ∈ {L0..L3}` 필드. 등급→채널 매핑(로그/SFX/진동/씬 컷)은 D04 §5.5·D11 §2.5 확정 표를 **매핑 테이블**로 데이터화.
- **L2+ 그랑프리당 상한 카운터** 구현(상한의 존재 확정 — D04 §5.5, 값 D13). 채널 감쇠(D09 §6.3 옵션 연동)는 출력 단계에서 채널별 마스킹 — **등급 판정 자체는 불변**(감쇠는 표현 층).

### 5.9 씬 컷 매핑 테이블 (D09 §3.1.1 · D10 §6.2 — DoD #15)

- `scene_cut_map`: 상황 id / 매칭 조건(확정 결과 태그 — D01 §8-3 '확정 결과→상황 컷' 정합) / **평가 우선순위**(D10 §6.2 확정 우선순위의 데이터화) / 컷 id(≤10F 시퀀스 참조) / 정지 폴백 프레임 지정(O12 — 대표 1프레임).
- 평가기: 우선순위 정렬 → 첫 매치 1건 재생 (동순위 시 스트림 무관 결정적 타이브레이크 — id 순, 확정). 컷 재생 파라미터(컷당 fps·완급 비트 가산 ≤ 상한)는 값 D13(D09 §3.1.1 C-A 계열).

### 5.10 이벤트-사운드 매핑 테이블 (D11 §8.1 — DoD #16)

- `sound_map`: 게임 이벤트 id → SFX id(+우선순위 P1~P3·채널·햅틱 플래그). **D11 §1.4 이벤트 결속 원칙의 구조 보장** — 사운드는 본 테이블 경유로만 발화(씬 컷 전용 발화 경로 자체가 부재, C-A2 정합). 커버리지(화면·턴 시퀀스 공백 0)는 D11 확정 — V2가 이벤트 id 전수 참조 검증.

### 5.11 광고 규칙·기준값 테이블 (D16 §8.2-⑧ — DoD #17, [모바일] 소비 전속)

- `ad_config`: cooldown_min=8 / onboarding_races=4 / exchange_rate=3 / tour_boundary_exempt=4 / hold_sec=30 (전부 D16 확정 기준값 — **테이블 등재·값 창구 D13**, 구조·규칙·상한의 존재 불변) + load_timeout_sec = 10 (확정 기준값 — §11.3).

### 5.12 AI 파라미터·조건 분기 (D08 §6.1~6.3 — DoD #13)

- 5층 합성 구현: `팀 기본 프로파일 → 개인 시드 오버라이드 → 무대 보정 → 그리드 레벨 보정 → 슬롯 진행 보정` — 각 층 = 독립 테이블, 합성 = 고정 순서 함수(D05 §4.6 파라미터 5축 위).

### 6.2 저장·스커밍 방어 (확정 — 결정 #6)

- 소비 시점 규정: reel 스트림은 **스핀 커밋(T2 입력) 시점 소비** — 서스펜드 스냅샷(§7.2) 복원 후에도 동일 잠정 결과 재현.

### 6.3 봉인 규칙 정합 (D02 §4 — 확정)

- 결과의 내부 선계산은 허용하되, **정지 연출 완료 전 어떤 출력 경로(UI·로그·사운드·햅틱·디버그 오버레이)에도 결과·결과 상관 신호를 노출하지 않는다** — D11 층위 원칙(정지 전 결과 암시음 금지)의 시스템 측 대응. 출시 빌드의 디버그 결과 표시 전면 제거는 D14 체크 항목으로 인계(§12).

### 8.1 키 체계 (확정 — 텍스트 하드코딩 금지)

### 10.1 미들웨어·버스·옵션 (확정)

- **미들웨어 = 엔진 내장, 외부 불채택**(결정 #3 — FMOD/Wwise 불채택: 요구 전 항목 내장 충족·이벤트 저작의 이중 관리 회피). 버스 3계: **Master / BGM / SFX** — **O13~O15 직결**(D09 v1.2 §6.1: 0~100·기본 80·즉시 반영 — 기본값 창구 D13). 슬라이더→감쇠 매핑 (확정 기준값): 0 = 뮤트, 100 = 0dB, 지각 선형 로그 커브(커브 세부 조정 D13).
- 포맷 (확정 기준값): SFX = WAV/PCM 44.1kHz 16bit(16비트 질감은 **에셋에 베이크** — D11 저작 층 소관, 런타임 가공 없음) / BGM = OGG Vorbis 44.1kHz(품질 ~q0.7) / 임포트 루프 포인트 메타 지원.

### 10.2 보이스 매니저 (D11 §6.3 — 확정)

- **가상 채널 상한 12** — 자체 보이스 매니저: 우선순위 P1~P3, 초과 시 **P3부터 컬링**(D11 확정). **재트리거 최소 간격 0.05초** = 디스패처 게이트(값 D13). 발화는 §5.10 매핑 테이블 경유 전속(이벤트 결속 원칙의 구현 — C-A2 정합).

### 10.3 덕킹·BGM 2레이어 동기 (D11 §6.3·§4 — 확정)

- 덕킹: L2·L3 스팅·징글 재생 중 BGM 버스 −6dB·복귀 0.3초(값 D13) — 버스 볼륨 자동화.
- **BGM 2레이어 봉인(기본+긴장 — D11 K2-B):** 동일 클럭 동기 재생(AudioStreamSynchronized 계열 — 확정) + 레이어 볼륨 크로스페이드 0.8초(값 D13). 트랙 간 전환 크로스페이드 동일 창구.

### 10.4 백그라운드/광고 뮤트·햅틱 이원 출력 (D11 · D09-2 §7.3 — DoD #29)

- [모바일] 백그라운드 진입 = 전 버스 뮤트(§2.4 훅) / **광고 재생 구간 = 게임 오디오 전량 뮤트**(광고 오디오와 혼합 금지 — F2 표현 층 전속·D11 확정) — IAdService 상태 연동.
- **햅틱 단일 규격·이원 출력**(D11): 진동 이벤트 정의 1원(강도·길이 — 값 D13, 감쇠 배율 D09 §6.3 연동) → IHaptics 어댑터 2구현([데스크탑] 패드 진동 / [모바일] 기기 진동 API). 채널 감쇠 옵션과의 곱 적용 순서: 이벤트 강도 × 옵션 배율.

### 10.5 타이핑 블립 (**결정 K7-c — 판정: 채택**, D11 §2.10 V-b — DoD #30)

- **판정 (확정 — 결정 #8):** 대사 **문자 단위 스트리밍 표시 채택** + 블립 = **큐음의 반복 재생(신규 에셋 0 — D11 확정 구조)** + 탭/클릭 즉시 완성. **신규 옵션 0** — 속도 옵션 불신설(D09 옵션 체계 무접촉), 소거 경로 = O15 SFX 볼륨.
- 스트리밍 속도 = 30자/초 (확정 기준값 — 값 창구 D13). 블립 발화도 §5.10 매핑 경유(재트리거 게이트 적용 — 연타 소음 방지).

## 11. 광고 SDK 연동 (결정 K3 — [모바일] 전속, DoD #32~#35)

### 11.1 SDK·어댑터 층 (확정)

- **Google AdMob 단일 — 미디에이션 불채택**(결정 #4). 근거: D16 노출 설계 극소(전면 = 대회당 1회 + 보상형 오퍼 2종) — 수익 이득 < SDK 비대·고지 표면. 동의 관리 = UMP 단일 계열(GDPR — 고지 준비물은 D15).
- **자체 광고 어댑터 인터페이스(IAdService)** 뒤로 격리 — 소프트 런칭 후 미디에이션 승격 시 코어·UI 무접촉 교체 경로 보존. 데스크탑 = 널 구현(§2.2).
- SDK 최소 OS 요구는 §1.2와 착수 시점 동기(상향 시 §1.2 갱신 — 총괄 인지 보고).

### 11.2 에러 코드 분기 (**판정 집행 — D16 §8.2 ②·보완 ①의 "기술적으로 가능하다면" 조건 해소**, DoD #33)

- **판정 (확정 — 결정 #4): 구분 가능.** AdMob 로드 실패 콜백의 표준 에러 코드가 **No-fill(재고 없음)과 네트워크 계열 오류를 상호 배타로 구분**한다 — 분기 구현: No-fill → **즉시 통과** / 네트워크·타임아웃·기타 로드 에러 → **30초 홀드**(D16 §3.4 1:1). **폴백 규정(즉시 통과 측 병합 — D16 §8.2) 불발동 종결.** 미분류 신규 코드의 안전측 기본값 = 홀드 측 (확정 — 어뷰징 벡터 보수 처리) → v1.0 발신문에 판정 보고 동봉.

### 11.3 홀드·타임아웃·상태 머신 (D16 §3.4 — DoD #34)

- 광고 어댑터 상태: `IDLE → LOADING → READY → SHOWING → CLOSED / FAILED{nofill|network}` — HOLD는 어댑터가 아닌 **UI 흐름 상태**(홀드 화면 규격 = D09-2 정문).
- **30초 홀드 = 실재 재시도 창:** 홀드 중 로드 루프 지속, **성공 시 즉시 재생·홀드 종료 / 30초 만료 시 통과**(D16 확정). 로드 타임아웃 = load_timeout_sec 10초 (확정 기준값 — §5.11, 값 창구 D13).
- 쿨다운 8분·대회당 1회·온보딩 4대회 카운트 = **모노토닉 시계 기준** (확정 — 시계 조작 어뷰징 차단, 벽시계는 보조). 상태는 프로필 저장(§7.1)에 지속.

### 11.4 백그라운드 중 광고 상태 (D09-2 §7.1 결정 #7 — DoD #35)

- **홀드 중 전환: 복귀 시 홀드 잔여부터 재개 — 백그라운드 경과 시간 홀드 미산입**(D09-2 확정 — 시간 비용 등가화 취지 보존): 홀드 타이머는 포그라운드 경과만 적산.
- SHOWING 중 전환: SDK 수명주기 위임 + 복귀 시 상태 조회로 CLOSED/미완 판별 — **보상형 미완 = 보상 미지급**(SDK 표준·D16 §3.4). 면제권·노출 카운트 커밋은 **콜백 확정 시점 원자 처리**(전환 중 이중 지급/유실 0 — 카운트 정합 D09-2 §9.2 이행).

### 11.5 계측 이벤트 (D16 §8.2 ⑤ — DoD #34)

- **자체/서드파티 분석 SDK 불채택 (확정 — 결정 #10:** 개인정보 표면 최소·D15 고지 부담 절감**).** 노출·완료율 = **AdMob 리포팅으로 충족**(소프트 런칭 재보정 — D16 §8.3 입력 가능 판정) + 로컬 디버그 카운터(원격 전송 없음).
- 이벤트 정의(어댑터 내부 — 확정): request / loaded / show / complete / fail{원인} / hold_start / hold_recover / hold_expire / offer_shown / offer_result / exemption_{grant|consume}.

### 11.6 결제 모듈 미탑재 확인 (D16 §8.2 ⑦ — DoD #35, 확정)
