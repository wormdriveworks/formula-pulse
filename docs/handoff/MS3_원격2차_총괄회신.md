## 1. 판정 A — **D13 v1.5로 전사했다** (사용자 승인 2026-08-16 · 결정 #15)

원문 3개소를 대조했다: D11 §6.3에 두 값 다 **'확정 기준값' 명문 실재** · D12 §10.2가 **'값 D13' 지목** · D13 별첨A §8.3(9항)에 **부재**. 보고대로 **결정 #14 ④(햅틱 지속)와 정확히 동형**이다.

**집행 완료 (총괄):** 별첨A §8.3 +2행(9→11항) · §10 D11 행 +2항 · 본문 §5 대장 **93→95항**(채택 94/조정 1) · 결정 로그 #15 · 판번 7지점 동기(파일명 `v1_5` 포함) · CLAUDE.md 불변규칙 2 계수 동기.

**"중단 대신 진행" 판단 = 적법 승인.** 불변규칙 2의 중단 조건은 "필요한 값이 D13에 **없으면**"이다. 이 건은 값이 정본(D11)에 확정으로 있고 **창구만 어긋난** 경우이며, D11 원문 그대로 `core_params`에 넣고 값을 발명하지 않은 처리가 정확하다. 코드가 이미 데이터 경유라 D13 전사로 즉시 정합 — 코드 무변경.

## 2. 판정 B — FONT는 **차단형**이다

제시한 4축이 결론을 이미 담고 있다. 판정 근거를 총괄 문면으로 확정한다:

- **V7이 경고형인 이유는 '경고형이 기본값'이어서가 아니라 판단 주체가 기계가 아니어서다**(작법 = D04 소관). FONT는 "폰트를 지정했는가"라는 문법 수준 기계 판정이라 그 사유가 적용되지 않는다 — 성격상 V4(하드코딩 검출)의 축이다.
- 오검출 0 실측 + 놓칠 비용 = 레이아웃 파손 + **눈 검증 무력이 37건으로 실측**됐다. 경고형은 "경고가 쌓여도 빌드가 초록"이라 이 검사의 존재 이유를 스스로 무른다.
- **명칭 FONT 승인** — 'V9'가 D12 §4.2 정본 확장을 함의한다는 판단이 정확하다. MIX0·ARCH 전례 그대로.
- **경고형 대기 처리 자체가 모범이다** — "검증기 성격을 구현이 정했다는 사실을 되돌리기 어렵게 만든다"는 문장은 이 프로젝트 검증기 운영의 원칙 문면으로 삼을 만하다. CLAUDE.md 불변규칙 7에 신설 검사의 성격 판정 = 총괄 경유를 명문화했다.

**집행 = 원격** (§4-①): `_warn` → `_fail` 전환 + 돌연변이 FONT 2건이 차단 경로로도 검출되는지 재확인.

## 3. 판정 C — P1~P3 배정 **승인**

P1 6행을 D11 §6.3 명문 예시와 전건 대조했다 — 타이머 3(SE-T01/02/03) · 레조넌스 공표(SE-RS1) · 듀얼 예고(SE-D01) · 섀시 경고(SE-D06). **명문 4범주 전부 커버 · 임의 확대 0.** 6+28+52 = 86 검산 일치. "배정이 틀려도 게임 규칙 무영향(컬링·P1 보호 한정)"이라는 범위 한정도 정확하다. [가안] 유지 불요 — **배정 확정**으로 전환하라.

**② 상세:** `season_state.gd`의 `finish_tour()`가 여전히 `order.find(PLAYER_ID) + 1` 무절상이다(시즌 쪽만 교정됨). 소비처 `record_tour_result()`가 `position <= 1`로 투어 우승을 세므로, 0 도달 시 **무순위가 투어 우승으로 계상**되는 역전 — 교정 전 오버홀 건과 정확히 같은 유형이다. 시즌과 같은 방식(find 실패 시 `_grid_size()` 절상)으로 통일하고 회귀 검사 1축을 추가하라. 도달 가능성이 시즌 건과 마찬가지로 희박하나, **같은 판정을 받은 같은 패턴을 한쪽만 고치면 반쪽 집행**이다.
