## 1. 작업 ① — attr `_16` 6종 결선 (창구 공유)

발신이 지목한 위험이 정확했다. `_icon_texture()` 를 **릴 심볼(32 무배율)과 섹터 속성(16)이 함께 쓴다.**

**해법: 치수 축을 창구에서 빼고 소비 지점에 뒀다.**

```gdscript
func _icon_texture(asset_id: String, variant: String = "") -> Texture2D   # 기본값 = 32
_reel_icons[i].texture = _icon_texture(String(provisional[i]))              # 릴 — 무인자
_e02_attr.texture = _icon_texture(main_attr, ATTR_VARIANT)                  # 속성 — "_16"
```

창구 안에서 치수를 판단하면 두 소비부가 서로의 규격을 밟는다. 세 가지를 함께 고정했다:

- **이름 순서 `<id>[_alt][_16]`.** O9 색각 대체는 *도상* 축, 치수는 *치수* 축이라 서로 독립인데, 순서를 정하지 않으면 같은 파일을 두 이름으로 찾게 된다.
- **`_16` 부재 시 32 로 되돌리지 않는다.** 되돌리면 비정수 축소가 **조용히** 되살아난다 — Zone A 가 정확히 그 상태였다(8차 §5-③ `RENDER_SCALE=0.5000`). 없으면 보고한다.
- **데이터는 접미 없는 base id 를 그대로 유지.** `circuit_*.json` 의 `main_attr` 는 `attr_straight` 다. 치수는 표시 층 사정이므로 데이터에 새기지 않았다 — 새기면 16px 이 데이터 계약이 되어 다음 치수 변경이 데이터 개정이 된다.

**릴 32 유지 확인:** 검사가 릴 심볼 6종이 접미 없는 32×32 파일을 쓰는지 매 주행 대조한다(§6).

## 2. 작업 ② — 파편 재판정 (원도 위생 축)

축 전환을 받아들여 **"원도에 남겨 둘 것인가"** 로 다시 봤다. 먼저 전제 하나를 실측했다.

**32px 원본의 렌더 소비부가 0 이 됐다.** `attr_*` 32px 는 Zone A 가 유일한 소비처였고 이번 회차로 `_16` 으로 옮겼다. `speaker_filler` 32px 는 로그 피드가 `_16` 을 쓰고 발화원도 없다. 즉 두 파일의 남은 역할은 **기록 원본**이며, 기록 원본의 위생은 표시되지 않는다고 느슨해지는 것이 아니라 **다음 재파생의 출발점이므로 오히려 엄해진다**(§9-⑮ 의 "고립 픽셀 0" 오보가 그 실패 사례다).

### ⚠ 먼저 — 대장 ⓑ 기술이 색을 잘못 지목하고 있다

대장 §9-⑭ 는 ⓑ 를 *"`attr_hazard` 2px **`#5B646F`** @(17,20)-(18,20)"* 로 적었다. **`#5B646F` 는 23px 짜리 큰 성분이다.** 색 성분을 전수 분해한 실측:

| 색 | 픽셀 | bbox | 좌표 |
|---|---|---|---|
| `#3FE0F5` | 77 | (8,9)-(23,22) | 주 시안 |
| `#12A6C4` | 26 | (8,9)-(23,21) | 시안 베이스 |
| `#5B646F` | **23** | (8,13)-(23,22) | 회색 — **대장이 지목한 색이지만 큰 성분이다** |
| `#6FA8FF` | 15 | (8,9)-(23,20) | |
| `#2E6FA8` | **6** | (17,16)-(23,23) | **(17,16),(21,20),(22,20),(23,20),(19,23),(20,23) — 4곳으로 흩어진 성분** |

검사가 내는 FRG 2건(`4px (19,22)-(20,23)` · `2px (17,20)-(18,20)`)의 좌표는 **`#2E6FA8` 과 `#5B646F` 에 걸쳐 있다.** 즉 **소거 대상은 `#5B646F` 가 아니다** — 그 색을 지우면 도상의 회색 음영 23px 이 통째로 날아간다. 집행 전에 대장 문면 교정이 필요하다.

### 판정

**ⓐ `speaker_filler` (20,13) 1px `#424A54` = 소거 권고.**
`#424A54` 는 40px 성분이고 (20,13) 은 그 성분에서 gap 2 로 떨어진 낱개다. 16px 판은 **정면 재작화**라 좌표 대응이 아예 없고(색 구성도 다르다 — 32px `#424A54`·`#4A545D`·`#9EA7B1` ↔ 16px `#2B3239`·`#242A33`), 32px 자체는 렌더 소비부 0 이다. **기록 원본에 낱개 1px 을 남길 이득이 없고, 그 1px 이 이미 한 번 오보를 만들었다.**

**ⓑ `attr_hazard` = 소거 권고 · 다만 범위를 `#2E6FA8` 6px 로 잡아야 한다.**
근거 둘:
1. **흩어짐이 음영으로 설명되지 않는다.** `#2E6FA8` 6px 이 (17,16) / (21~23,20) / (19~20,23) **3덩이로 갈라져** 있다. 음영은 면을 따라가고, 이것은 따라가지 않는다.
2. **16px 재작화가 스스로 버린 톤이다.** `attr_hazard_16` 은 **`#3FE0F5` + `#5B646F` 2색뿐**이다 — `#12A6C4`·`#6FA8FF`·`#2E6FA8` 47px 을 전부 버렸다. 즉 현행 아트 디렉션의 판단이 이미 "이 톤들은 없어도 된다"이고, `#2E6FA8` 은 그중 가장 흩어진 것이다.

> **집행 권한은 에셋·총괄에 있다** — 소거는 도상 조정이므로 판정을 경유한다(IMPL-162→165 전례). 위 셋 중 **대장 문면 교정이 먼저**다.

## 3. 작업 ③ — `achv_garage_16` 재판독: **추인 권고 (8차 반대 의견 철회)**

세로 렌치 재작업분은 **공구로 읽힌다.** 8차에 올린 반대 의견을 철회한다.

- 상단의 **양갈래 오픈엔드 스패너 머리**가 또렷하고, 수직 샤프트가 공구 비례를 준다. 하단 블록이 작업대/베이스로 받쳐 "개러지"의 문맥까지 선다.
- 8차 판(2개 교차)이 **얇은 X 표시**로 읽혔던 것과 대비가 확연하다 — 잉크 68px · bbox 10×13.
- 같은 목록의 이웃 5종(월계관·마주 보는 헬멧·스티어링 휠·캐비닛·? 배지)과 실루엣이 겹치지 않는다.

보고문이 말한 "렌치 1요소"가 실물로 구현된 것이고, 8차의 지적("보고문과 실물이 어긋난다")이 이번에 닫혔다.

즉 `anchors_preset` 전환도 런타임 앵커 값이 동일하고, 줄 순서 변경도 적재 결과가 같다. 7차 색 치환분이 그대로 살아 있음도 이 대조에 포함된다.

## 5. 작업 ⑤ — 실기: Zone A ✅ · **저장 표시에서 위치 결함 발견·교정**

### ① Zone A `_16` — 확인 완료

RACE-01 A존에서 속성 도상이 **16px 등배로 또렷하게** 뜬다. `attr_straight` 의 파선 중앙선이 깨끗한 블록으로 살아 있다 — 8차까지 1/2 축소가 지우던 디테일이다. 릴 심볼(32)과의 크기 위계도 의도대로 읽힌다: A존 표지는 작고 릴은 크다.

부수 관측 하나 — **`attr_hazard_16` 이 6종 중 유일하게 의미가 즉시 서지 않는다.** 블록 격자로 읽혀 "노면 요철"까지는 가지만 "해저드"로 바로 오지 않는다. 나머지 5종(사다리꼴 도로·S자·호·양방향 화살표·오름 막대)은 즉시 판독된다. 비차단 소견이다.

### ② 저장 표시 — **좌상단에 뜨고 있었다. 교정했다.**

**실기 스크린샷으로는 못 잡았다.** 표시 시간이 `param_fx_save_hold_sec = 2.0` 인데 GDAI 스크린샷 왕복이 2~5초라 **창을 한 번도 못 잡았다** — GP 1회 완주 + 투어 결산 + 개러지 진입까지 저장 지점을 3번 밟았으나 전부 놓쳤다. 도구 한계다.

그래서 화면을 실제 트리에 세워 rect 를 재는 방식으로 바꿨고, 거기서 결함이 나왔다.

```
parent_size=(640, 360)
anchors L=1.00 R=1.00   offsets L=-640.0 R=-608.0
rect=[P: (0,0), S: (32,32)]   →  우측 여백 608.0 · 상단 여백 0.0
```

**원인:** `_ready()` 가 크기 설정 **전에** `set_anchors_preset(PRESET_TOP_RIGHT)` 를 부른다. 이 호출은 기본값 `keep_offsets=false` 에서 **현재 rect 를 보존하도록 오프셋을 역산**하는데, 그 시점 rect 는 아직 `(0,0,0,0)` 이다. 그러면 우측 앵커에 0폭 rect 가 보존돼 `offset_left = -부모폭` 이 되고 — **아이콘이 좌상단에 뜬다.** D09 §181 은 우상단 명문이다.

**교정:** 앵커만 세우고 오프셋을 도상 크기로 직접 적어 순서 의존을 없앴다. 이 결함은 **8차 IMPL-218 이 심은 것**이고, 원격이 `configure()` 를 물릴 때 배치는 재확인 대상이 아니었다.

### ③ 값·거동 실측 (교정 후)

| 축 | 실측 |
|---|---|
| 위치 | 우측 여백 **0** · 상단 여백 **0** (우상단) |
| 회전 주기 | 0.25s 경과 시 **정확히 90.0°** ⇒ `param_fx_save_spin_sec = 1.0` 정합 |
| 표시 시간 | 2.05s 누적에서 `visible=false` ⇒ `param_fx_save_hold_sec = 2.0` 정합 |
| 실패 저장 | `progress_saved(false)` → **뜨지 않는다** ✓ |
| 회전 축 | 피벗 = 도상 중심 (16,16) ✓ |

**회전 "감각"은 미판정으로 남긴다** — 2.0s 창을 육안으로 못 봤다. 1.0s 주기 × 2.0s = **2회전**이라는 것은 산술로 확정됐으니, 그 2회전이 "저장 중"으로 읽히는지는 실물 빌드에서 사람이 볼 일이다.

### ④ 부수 — 실기에서 함께 확인된 것

- **재화 16px 결선** — 개러지 공통 바에 금색 코인(600)·시안 카트리지(32)가 16px 등배로 뜬다. 실루엣 1차 구분이 16px 에서도 유지된다.
- **필러 `{number}` 치환** — 듀얼 오버레이에서 **"No.28 머신"·"No.22 머신"** 으로 정상 표시된다(원격 IMPL-210~212 in-situ 확인).
- **활성 탭 표시**(8차분) — LB/RB 로 돌리면 포커스 링은 남고 활성 표시만 이동한다.

## 6. 검사 2군 신설 — 돌연변이 5건 전건 검출 (130 → 138)

**⑫ 도상 치수 2규격 공존.** 창구 하나를 두 규격이 지나므로 그 밟힘을 고정한다 — 속성 6종이 `_16` 파일·16×16 인지, **릴 6종이 접미 없는 32 를 유지하는지**, A존 실배치가 등배인지, 캐시 키가 치수로 갈리는지. **파일명과 실 rect 를 함께 본다**: 슬롯 크기만 보면 두 규격이 우연히 맞는 경우를 통과시키고, 상수만 보면 창구가 그것을 쓰는지 알 수 없다.

**저장 표시 위치 3축.** **앵커가 아니라 부모 폭 기준 실 rect 로 본다** — 이번 결함은 앵커가 정상(L=R=1.0)인데 오프셋이 어긋난 형태였고, **앵커만 보는 검사는 그것을 통과시킨다.**

| 돌연변이 | 검출 |
|---|---|
| 창구가 치수를 스스로 정함(릴까지 `_16`) | ✅ 릴 6건 + 캐시 키 FAIL |
| 속성 호출부가 접미 미전달 | ✅ **`scale=0.5000`** — Zone A 회귀를 정확한 수치로 |
| `_16` 부재 시 32 폴백 | ✅ 3축 FAIL |
| 위치 결함 되돌림(preset 역산) | ✅ **`우측여백=608.0`** |
| 회전 피벗 0 | ✅ 피벗 FAIL |
