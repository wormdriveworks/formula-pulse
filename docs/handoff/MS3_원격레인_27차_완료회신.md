## 1. 재검 벽두 — 총괄 재계수가 맞다. 그리고 **분할로 21이 됐다.**

내 재계수도 20이다: 리터럴 **15** + `_skill_precondition` 고유 반환 **5**(`already_hold`·`already_mod`·`duel_turn`·`sector_turn`·`no_provisional` — `effect`·`respin_cap` 은 리터럴과 겹친다).
26차 회신의 미고지 8종에서 **`limit`·`no_snapshot` 2종이 빠져 있었다** — 처리 실물은 코드와 일치했고
**대장만 틀렸다.** 지적 그대로다.

### 1.1 `limit` 판정 재검 — **도달 가능하다. 2분할 + 고지 편입.**

같은 자리의 두 상한이 하나는 소리 내고 하나는 침묵하던 근거를 실독했다.

```
_on_respin():  if not _timer_active or _revealing: return   ← hold_used 를 보지 않는다
버튼:          _e08_respin.disabled = … or engine.hold_used  ← 버튼만 막혀 있다
입력 경로:      키·패드 액션이 `_on_respin()` 을 직접 부른다  ← 버튼 disabled 를 우회한다
```

**⇒ `limit` 은 리스핀 키를 두 번 누르면 도달한다.** 버튼 비활성은 마우스만 막는다.
`respin_cap`(합산 상한)과 **같은 성격의 규칙 거부**이므로 침묵할 근거가 없다.

**다만 `limit` 은 한 이름으로 두 사실을 말하고 있었다** — `hold_respin` 의 턴당 1회(D05 §5.4)와
`add_duel_boost` 의 부스트 상한. `already` 2분할과 같은 근거로 **`limit_hold` / `limit_boost`** 로 갈랐다.
`limit_hold` 는 고지 편입 대상이며 **문면 1키 대기**다(키가 오면 대장에 한 행).

`no_snapshot` 은 **도달 불가**다 — `choose_snapshot` 의 유일 호출부가 `_on_snapshot_revert` 이고
그 버튼은 `visible = pending` 이라 대기가 없으면 존재하지 않는다. 관측으로 대장에 남긴다.

### 1.2 **대장을 산문에서 코드로 옮기고 원본과 기계 대조한다**

*"대장이 정확해야 침묵이 판정이 된다"* — 그렇다면 대장은 산문이면 안 된다. 산문은 또 틀린다.

`RaceEngine.SKILL_ERROR_CODES` 신설 + TC-C 가 **원본을 훑어 양방향 대조**한다:
`"error": "…"` 리터럴 + `_skill_precondition` 반환을 모아 대장과 맞추고, **어느 방향이든 어긋나면 실패**한다.
계수 핀(21)은 *양쪽에서 함께 사라지는 것*을 잡는다. 화면 층 분류가 대장을 정확히 분할하는지도 함께 본다.

**현행 = 21종 · 고지 7 · 침묵 3 · 미고지 11.** (26차 20 + `limit` 2분할 −1+2)

### 1.3 부수 교정 — 거부에 확인음이 나고 있었다
`_on_boost` 가 상한에 걸린 투입에도 `boost_spend` 를 울려 **"썼다"는 거짓 확인**을 줬다.
소리는 결과를 말해야 한다 — 거부는 `input_rejected` 로 바꿨다.

## 3. 마일스톤 VN 발화 결선

### 3.1 트리거 = **세 열, 각기 다른 표를 참조**

`trigger_milestone`(fk_optional:milestones) · `trigger_crew`(fk_optional:crew) · `trigger_act`(int:0,4).

문자열 한 열로 두지 않은 이유: **어느 표를 가리키는지 검사가 못 보고 오타가 조용히 통과한다.**
22차에 V2 가 표 열의 참조를 절반만 보고 있던 것을 겪은 뒤라 더욱 그렇다.
반증 K4(트리거 오타)가 V2 에서 걸린다.

### 3.2 **이월에 대기열을 두지 않았다 — 도출이 대기열이다**

정본의 이월은 *"동일 투어 경계에 2건 이상 몰릴 경우 … 잔여분은 차기 경계로 이월"* 이다.
**자격을 상태에서 도출**하면 이월이 저절로 성립한다 — 밀린 비트는 다음 경계에도 여전히
자격을 갖고 같은 정렬이 다시 고른다.

대기열은 **직렬화해야 하고 실제 상태와 어긋날 수 있다.** 도출은 어긋날 수가 없다.
*대기열이 없다는 것은 잃어버릴 대기열도 없다는 뜻이다.*

실측 사슬: 크루(2) → 단서(3) → 성취(4) 가 세 경계에 걸쳐 순서대로 선다.

자격 = 트리거 성립 ∧ 미발생(`vn_seen` — **스킵도 발생**). 트리거 미선언 = **미발화**
(조용한 상시 발화를 막는다). 발화 지점 = `tour_report_screen._on_next` — `slot_kind = tour_close` 의 그 자리다.

### 3.3 형식 B 카운터 — **5축 중 셋이 0이었다**

`counter_source` 가 레이스 중 조건을 기술하는데 아무도 세지 않아 **주드·비앙카·로렌츠 축이 영구 0**이었다.
코드가 축 이름을 알지 않고 **표가 선언한 산식 종류를 읽는다** — 축이 늘어도 함수가 그대로다.

| 산식 | 계수 |
|---|---|
| `beat_and_duel` | 그 라이벌 선착 + 그 라이벌과의 듀얼 |
| `duel_with_lorentz` | 듀얼만 (왕좌는 대결의 축이다 — 선착은 세지 않는다) |
| `adjacent_finish_and_duel` | 인접 완주 + 듀얼 (**별개 사건이므로 더한다**) |

실측: 로렌츠 듀얼 1 → 왕좌 +1 · 비앙카 선착+듀얼 → 계승 +2 · 주드 인접 완주 → 동기 +1.
검사가 **축 id 리터럴 0**까지 본다(들어오면 축이 늘 때마다 함수가 자란다).

## 4. 조립 키 계약 (배지 — 27차 확정 · 내러티브 즉납 요청)

```
ui.race.actionWithUses   ← {label} · {cost} · {left}
```

- **`actionWithCost` 의 확장형**이다(`{label}`·`{cost}` 동일 + `{left}` 추가) — 새 문형이 아니라 한 인자가 는 것이라 번역이 기존 행을 따라간다.
- `{left}` 는 **잔여 횟수 정수**다. **−1(투어 무제한)일 때는 이 키를 쓰지 않고** `actionWithCost` 로 남는다 — 0 은 '소진'이고 무제한과 같은 값을 쓸 수 없다는 20차 계약이 표시로 나온 것이다.
- 폭: 슬롯 버튼은 고정 폭 선언이 없다(행 총폭 구속) — 자수는 `ui.race.` 일반 규칙을 따른다.
- 유입되면 `_refresh_skill_slots` 한 줄이다.

`ui.race.skillRejectedLimitHold` (§1.1) 도 함께 요청한다 — 유입 시 `SKILL_REJECT_KEYS` 한 행.

## 5. 반증 10종 — 전건 검출 · 초판 미검출 4종이 **전부 같은 계열**

| # | 주입 | 검출 |
|---|---|---|
| K1 | 우선순위 정렬 무력화 | 크루(2) vs 단서(3) — **id 순과 반대인 짝** |
| K2 | `vn_seen` 가드 제거 | 이월 사슬 |
| K3 | 트리거 미선언 상시 발화 | **자격자 0 상태**에서 잰 프로브 |
| K4 | 트리거 표 오타 | V2 선택형 FK |
| K5 | 투어 종료 발화 지점 제거 | 원본 축 |
| K6 | 형식 B 산식 1종 소거 | **거동 축**(계수 실측) |
| K7 | 오류 대장에서 1종 제거 | 원본↔대장 양방향 |
| K8 | 침묵 사유를 고지로 편입 | 고지 ∩ 침묵 = 0 |
| K9 | `limit` 2분할 되돌림 | 대장→원본 방향 |
| K10 | 표제 해소 순서 뒤집기 | **거동 축**(대입 후 순서 실측) |

**초판 미검출 4종의 성질이 하나다 — 축이 우회로를 봤다.**

- **K1** — 고른 짝이 우선순위 순과 **id 순이 같아서** 정렬을 통째로 지워도 통과했다. 짝을 **어긋나게** 골라야 정렬이 관측된다.
- **K3** — 우선순위가 높은 비트가 있으면 미선언 행이 자격을 얻어도 뽑히지 않는다. **자격자가 0일 때** 재야 그 분기가 보인다.
- **K6·K10** — 원본에 이름이 있다는 것과 **그것이 일하는 것**은 다른 사실이다. 분기는 남기고 본문만 비우면 문자열 검사는 통과한다. 거동으로 바꿔 닫았다.

## 6. 보고 3건

### ① 내러티브 9차 편입 완료 + **트립와이어 위치 정정 접수**

커밋(`a5fcbe4`)이 서서 회차 안에서 편입했다: `title_key` **8행 기입** · 성취 3행 `line_count` 8→9 ·
라인 3행 추가(`line_order 9` · 마르타) · `ui.vnTitle.` 자수 규칙 등재.
**성취 대사 7 → 8 이 되어 표준형 하한을 넘는다** — 판정 요청 ①이 문면으로 해소됐다(관측 0건).

**26차 §4.2 의 *"문면이 들어오면 축이 실패한다"* 는 오기였다.** 그 축은 `title_key` **열의 공란 수**를
세지 `strings.csv` 를 보지 않는다 — 문면이 도착해도 조용하고 **열을 채우는 순간** 붉어진다.
즉 `TITLE_PENDING` 은 *문면 대기 값*이 아니라 **열 기입과 같은 커밋에서 함께 움직여야 하는 값**이고,
지금 0 으로 갱신해 **회귀 가드**가 됐다(표제를 지우면 걸린다). 정정 접수한다.

### ①-b [자기 발견] `string_key_optional` 이 **V6 에서 빠져 있었다**

`title_key` 8행을 채웠는데 **V6 고아 경고가 그대로 8건**이었다. V6 의 참조 수집이
`== "string_key"` 정확 비교라 26차에 내가 신설한 선택형이 들어가지 않았다 —
**새 타입을 한 검사에만 넣고 다른 검사에 넣지 않은 것**이고, 22차 V2 표 열 구멍과 같은 형태다.
수집에 편입했다(`warnings` 10 → 2).

### ② 마일스톤 슬롯의 시즌 상한 소비가 이제 실재한다
`trigger_vn` 의 `milestone_cap`(8)이 26차까지 **소비되지 않는 상한**이었는데(발화 경로 부재),
이제 실제로 소비된다. 시즌 상한 15 안에서 마일스톤 8이 차지하는 몫이 실기 밸런스 관측 대상이 됐다.

### ③ `_on_respin` 의 액션 경로가 버튼 `disabled` 를 우회한다 (§1.1)
`limit` 도달 가능의 원인이며, **같은 형태가 다른 액션에도 있는지는 보지 않았다** — 화면 층 전수는 주력 몫이다.
