## 2. 판정을 어떻게 계상으로 옮겼는가

**계상 = [가안] 신설** (A-UI-28·29). 업적 6종 P-9 와 같은 절차이며 **D10 차기 개정 계상 동기**로 등재했다. 근거는 판정 ⑧ 이 확인한 것 그대로 — D10 §5.5 C-B2 의 *"화자 아이콘 2종 고정·신설 금지"* 는 **UI 아이콘 트랙의 수량 통제**이고, 이 둘은 D09 §3.3 이 **초상·배지**로 규정한 축이라 그 조항의 대상이 아니다.

### 2.1 배지가 8파일인 이유 = 위계다

```
D09 §3.3 도상 위계:  초상(크루) > 넘버 배지(네임드) > 공용 헬멧(필러)
필러 표기:           공용 헬멧 아이콘 1종 + 카 넘버(텍스트)
                     ↑ 번호 없는 배지를 쓰면 네임드도 "판 + 번호(텍스트)" 가 되어
                       표기 구조가 같아지고 위계가 3층 → 2층으로 붕괴한다
```

번호 출처 = **D03 결정 #13** (1·2·18·81·5·51·24·77). 필요한 숫자 원도는 **1·2·4·5·7·8 여섯 자**뿐이다.

### 2.2 판 기하는 8종 공유이고 번호만 갈린다

판 x1..14 · y2..13 · 상하단 모서리 1px 컷 · 숫자 5×8. **2자리는 `5+2+2+5 = 12` 로 판 내부를 꽉 채우고 대칭축 7.5 에 정확히 걸린다.** 1자리(1·2·5)는 x5..9 로 **0.5px 좌편향**한다 — 짝수 판에 홀수 폭 글립을 넣으면 피할 수 없고, 폭을 4나 6으로 바꾸면 2자리 판과 글립이 갈린다. 도트 관용 범위로 두고 적어 둔다.

### 2.3 파일명이 데이터 id 키인 것도 판단이다

`speaker_rival_ai_lorentz_16` 이지 `speaker_rival_01_16` 이 아니다. 대장 §4.5 리버리 전례(`ai_maro`·`team_silvertrail` — *"엔트런트 데이터에서 리버리 경로를 바로 유도할 수 있다"*)를 그대로 따랐다. **번호를 파일명에 쓰면 번호가 바뀔 때 파일명이 거짓이 된다** — 번호는 도상의 *내용*이고 id 는 도상의 *주소*다.

### 2.4 광량으로도 위계가 선다

바탕 N03 대비: 초상 얼굴 **11.24:1** > 배지 판면 **7.11:1** > 필러 헬멧 본체 **~2.2:1**. 판면을 N16(11.09:1)이 아니라 **N14** 로 둔 이유가 그것이다 — 164px 판이 98px 얼굴과 같은 밝기면 피드에서 배지가 초상보다 크게 읽혀 **위계가 광량에서 뒤집힌다.** 초상만 피부색을 쓰는 것도 같은 축이다(D09 §6.6 — 0.1초 판독에서 색이 형태보다 먼저 잡힌다).

## 3. 시안 원장은 비웠고 기제는 남겼다

4항을 유입 원장으로 옮기고 `docs/assets/시안/` 의 화자 PNG 4개를 지웠다 — **배지 A안(무지 플레이트)은 이 판정에서 부결분**이다.

`icon_draw.js --proposal` 은 **빈 원장을 오류로 죽지 않게** 고쳤다:

```
$ node tools/assets/icon_draw.js --proposal
판정 대기 도상 없음 — 시안 원장이 비어 있다.
ICON_DRAW_PROPOSAL PASS icons=0
```

> **두 경우를 갈라 다룬 것이 요점이다.** 시안 원장이 빈 것은 *상태*(판정 대기 도상 없음)이고 **유입 원장이 비는 것은 여전히 사고**다 — 후자는 그대로 `FATAL` 로 둔다. 한 조건문으로 뭉치면 "아이콘이 다 사라졌는데 통과"가 가능해진다.

## 4. 계상 누락을 검사가 잡았다

매니페스트 기입 **전에** `icon_check` 를 돌렸더니 9파일을 전부 차단했다:

```
✗ DIM  speaker_rival_ai_lorentz_16.png: 16×16 != 선언 32×32   (×9)
ICON_CHECK FAIL checks=9781 fails=9
```

IMPL-215 가 `size` 필드를 두며 적은 설계 의도 — *"새 치수는 반드시 여기 적어야 통과한다. 임의 치수가 조용히 들어오는 길을 막는다"* — 가 **실제로 물린 사례**다. 계상 후 `PASS checks=9790 fails=0 warnings=0`.

## 5. 결선 인계 — `ICON_BY_SPEAKER` 는 배지를 담을 수 없다

발주가 결선을 화면 층 몫으로 명기했으므로 **구조적 제약 1건**을 인계에 남긴다.

```gdscript
const ICON_BY_SPEAKER := {          # Speaker 열거 → 단일 asset id
    Speaker.RELAY: "speaker_relay_16",
    Speaker.FILLER: "speaker_filler_16",
}
```

**이 표에 배지를 넣을 수 없다.** `Speaker.RIVAL` 하나에 8개 자산이 대응하기 때문이며, 근본 이유는 **라이벌이 화자 *종류*가 아니라 *특정 인물***이라는 것이다. 호출부가 `char_id` 를 함께 넘겨야 한다.

- **텍스트 폴백 경로는 유지해야 한다** — `log_feed.gd` 주석이 이미 적어 둔 대로다. 적재 실패와 **미지 라이벌**(데이터에 없는 id)이 같은 자리로 떨어져야 한다.
- 크루는 제네릭 1종이므로 `Speaker.CREW: "speaker_crew_16"` 한 줄로 끝난다.
