# UI 폰트 계열 배정 — 총괄 판정 회신 (2026-08-16)

> 작성: 총괄(사용자 지정 세션 — 마스터플랜 §0.8.1) · 대상: `UI폰트계열_총괄발신.md` (주력 GUI 레인)
> 절차: §0.8.2 — ①접수 ②원문 대조 ③파급 조사 ④판정 ⑤회신(본 문서)
> **판정: ② 해당하지 않는다 — 현행(본문 계열 9px) 유지가 정본 정합.** 정본 개정 불요.
> **단, 발신문의 전제 1건이 원문 대조에서 뒤집혔다 (§C).** 조정 레버는 폰트가 아니라 아이콘이다.

---

## A. 판정 — ② 해당하지 않는다

**질문:** D10 §5.7 대형·VN 계열의 적용 대상 "VN 대사창·선택지·**헤더**·결산" 중 '헤더'에 HUB 상단 공통 바가 해당하는가?
**판정: 해당하지 않는다.** 근거 4건, 전부 원문 실측이다.

### A-1. 명명 대조 — 정본은 이것을 '헤더'라 부른 적이 없다

| 출처 | 원문 |
|---|---|
| D09 §4.1 표 행 | `상단 공통 바 \| 재화 2종(§5.2 표기 규격) + 시즌·투어 진행 + 다음 일정 — 전 HUB 화면 공통 상속` |
| D09 별첨A 서두 (공통 상속) | "전 HUB·SET 화면은 **상단 공통 바**(본문 §4.1 …)를 상속한다" |
| D09 별첨A 와이어프레임 | `┌─ 공통 바: 재화2종 · 시즌/투어 · 다음 일정 ─┐` |

D09 계열 3개소가 일관되게 **'상단 공통 바'**다. 같은 프로젝트 어휘 체계를 공유하는 D10이 이 요소를 지칭하려 했다면 그 이름을 썼을 것이다.

### A-2. '헤더'의 실제 용례 — 화면 내부의 섹션 제목이다

D09 계열에서 UI 요소로서의 '헤더'는 **상시 바가 아니라 그룹 제목**을 가리킨다:

- 별첨A §A-14 HUB-04 — "미개방 스킬 티어 **헤더**" (스킬 그룹의 제목 행)
- 별첨A 업적 화면 — "달성률 요약 **헤더**" (화면 내 요약 섹션)

구현이 화면 제목을 대형 14px로 쓰고 있는 것(발신문 실측 13px)은 이 용례와 정합한다.

### A-3. 계열 성격 — 대형·VN은 '서사·결산의 집중 텍스트' 계열이다

적용 대상 4종 중 나머지 3종(VN 대사창 · 선택지 · 결산)은 전부 **읽는 순간 시선을 고정하는 텍스트**다. '헤더'도 그 결에서 화면·섹션 제목으로 읽는 것이 자연스럽다. **상시 노출되는 HUD 수치는 이 계열의 성격이 아니다.**

### A-4. 반대편 문면이 더 맞는다

본문·로그 계열 적용 대상 = "레이스 로그·메뉴·**라벨**·툴팁". 아웃게임 상시 바의 재화 수치는 '라벨'에 자연스럽게 든다.

> **귀결: 현행은 정본 위반이 아니었다.** 구현 레인은 폰트를 변경하지 않는다.

## B. 부대 판정 — D10 §5.7 적용 대상 표 개정: **불요 (비권고)**

- §A-3 그대로, 상시 HUD를 서사·결산 계열에 편입하는 것은 계열 정의를 흐린다.
- 발신문 §D **안 2(본문 base 9→10 전역)** 는 발신문 자신의 분석에 동의한다 — 로그 존 22자 여유가 6px만 남고 **O7 3단(100/115/130%)을 소진**한다. O7이 아직 미결선(IMPL-087)이라 지금 안 보일 뿐, 결선 시점에 막힌다. **국소 문제를 전역 구조 소진으로 푸는 안이므로 배제.**
- 본 판정으로 안 1·안 2 모두 종결된다.

## C. 총괄 발견 — **발신문의 전제가 뒤집힌다** (§0.8.2-② 원문 대조의 산물)

발신문은 *"폰트가 조정 레버이고 아이콘은 손댈 수 없는 확정값"* 이라는 구도 위에 서 있다. **정본은 정반대다.**

| 대상 | 정본 지위 | 조정 창구 |
|---|---|---|
| **폰트 계열·단** | D10 §5.7 확정 기준값 + **D13 별첨A §10 전사 "채택"** | **D13** (불변규칙 2 — 값의 유일 창구) |
| **재화 아이콘 크기** | **정본 규정 없음** | 구현 실기 |

근거 실측:

- **D10 §5.2(재화·상태 아이콘)에는 크기 규정이 아예 없다** — 실루엣 층위(원형/사각/육각)만 확정한다.
- **D10 §5.1의 32×32는 심볼 전속이다** — 원문이 "셀 원도 32×32px … 표시 96×96px. **릴 존 규격 내** 판독 여유 포함"으로 릴에 귀속한다.
- **D13 별첨A §10의 전사가 이를 못박는다** — `D10 §5.1 | **심볼** 셀 원도 | 32×32px (표시 96×96) | 채택`. 대장은 **심볼**이라고 적었지 '전 아이콘'이라 적지 않았다.

→ 현행 재화 아이콘 32px는 **`이미지에셋_제작사양서_v1.1` §6.1의 '전 아이콘 준용'** 이라는 구현 문서 층 확장이다(총괄 확정분 — IMPL-099). 구현 문서 층 확정 기준값이므로 **조정 창구 = 실기**이며 **D10·D13 무접촉으로 바꿀 수 있다.**

**즉 시각 균형 조정의 정본 비용은 아이콘 측이 압도적으로 싸다.** 발신문이 폰트를 레버로 삼은 것은 이 비대칭을 반대로 본 결과다.

### C-1. 사용자 배제(안 3)의 근거도 달라진다

발신문 §D 안 3은 **"32×32 원도를 강제 축소"** 하는 안이었고, 그래서 `expand_mode` 변경 → ÷2 다운샘플 → 디테일 절반 소실이라는 대가가 붙었다. 배제는 타당했다.

그러나 **재화 전용 소형 원도(예 16×16)를 두는 것은 다른 안이며 그 손실이 없다.** 게다가:

- 아이콘 16종은 **전량 플레이스홀더**다(IMPL-071·075). 실물 발주 전인 **지금이 규격 변경 비용의 최저점**이며, 발주 후에 바꾸면 재작업이 된다.
- 경로가 이미 문서에 있다 — 제작 사양서·에셋 배치 대장 §4.1이 재화 전용 원도를 언급한다.
- 산술: 16×16 원도(잉크 ~13px) 대 본문 9px = **≈1.5 : 1**. 대형 계열 안(2.1 : 1)보다 균형이 낫고 정본을 건드리지 않는다.

→ **배제 결정의 전제가 바뀌었으므로 사용자 재확인 대상으로 올린다.** 총괄이 뒤집지 않는다.

## D. 처리 지시

| 대상 | 지시 |
|---|---|
| 구현 레인 (주력) | **현행 유지.** 공통 바 폰트 변경 금지 — 판정 ②로 정본 정합이 확인됐다. 발신 §E의 판정 ① 처리분은 **불집행**. |
| D10 · D13 | **무접촉.** 개정·전사 신설 0. |
| 제작 사양서 | **문면 교정 1건 이월** — §6.1 "32×32px 확정 (D10 §5.1 — 심볼 기준·**전 아이콘 준용**)"의 귀속 표기를 **"심볼 = D10 §5.1 확정 / 그 외 = 구현 준용(조정 창구 실기)"** 로 분리한다. **값은 무변경**, 바뀌는 것은 *누가 바꿀 수 있는가*다. 트리거 = 사양서 차기 개정(아이콘 규격 결정 시 동시 집행 — 이중 개정 회피). |
| 사용자 | **시각 균형을 계속 원하는지, 원한다면 재화 전용 소형 원도를 채택할지** 확인 (§C-1). 원하지 않으면 본 안건은 여기서 종결된다. |

## E. 부기 — 판정이 만든 이득

이 판정은 "폰트를 키우지 마라"로 끝나는 게 아니다. **정본을 한 줄도 건드리지 않고 더 나은 균형(≈1.5:1 대 2.1:1)에 도달하는 경로**를 열었고, 그 경로는 아트 실물 발주 전이라는 시간 창이 닫히기 전에만 싸다. 발신 레인이 단독 판단하지 않고 올린 것이 옳았다 — 단독 처리했다면 확정 기준값(폰트)을 만지면서 정작 자유로운 값(아이콘)은 그대로 뒀을 것이다.
