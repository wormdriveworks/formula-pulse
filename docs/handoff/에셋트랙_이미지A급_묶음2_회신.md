## 2. RD 파일럿 — 9패치는 확산 모델의 표현력 밖이다

발주가 "RD 파이프라인 재개"이므로 **RD 로 먼저 시도했다.** 운용지침 §9-④ 가 이 지점을 *"실기 (첫 배치 대조)"* 로 남겨 둔 [가안]이었고, 그 대조가 이 회차다.

### 2.2 그런데도 9패치 3축이 전건 미달이다

9패치는 **기하 계약**이다. ①코너가 규격 px 여야 하고 ②변 가운데는 늘어나는 축으로 균일해야 하며(늘리면 변화가 드러난다) ③코너 4개가 같은 규격이어야 한다.

| 축 | ⓒ 최선작 실측 | 요구 |
|---|---|---|
| 좌우 대칭 | **불일치 1584px** | 0 |
| 상하 대칭 | **불일치 2250px** | 0 |
| 변 가운데 늘림축 균일 | **불균일 106~114px / 1024 = 10~11%** | 0 |

**원인은 품질이 아니라 표현력이다.** 확산 모델에는 *"정확히 16px"* 이나 *"이 열은 저 열과 같다"* 를 표현하는 층위가 없다. 이것은 아이콘 축약이 기각된 것과 **같은 축**이며(사양서 §6.8.3 — *"새 도상은 만들 수 있으나 축약은 못 한다"*), **RD 가 새 도상에 강하고 기하 계약에 약하다**는 판단의 3번째 확인이다(1차 IMPL-162 · 2차 IMPL-214).

### 2.3 [가안] 3건 종결 — 그중 하나는 지침 자신이 틀렸다

| # | 종결 |
|---|---|
| **④ 9패치 생성 경로** | **RD 기각 · 파라메트릭 채택.** 두 경로(원도 직접 / 축소) 다 못 낸다 — ⓐ가 원도 직접의 실패이고 ⓑⓒ가 축소 경로 입력의 실패다(축소는 시도할 값도 없다) |
| **⑤ `remove_bg` 추가 과금** | **무과금.** `remove_bg=true` 로 호출해 잔액 델타 = **$0.034**, `remove_bg` 없는 추정치와 완전히 같다. **부수로 지침의 지시가 교정된다** — 초판은 *"호출 전 `estimate_inference_cost` 로 확인"* 이라 적었으나 **추정 도구 스키마에 `remove_bg` 필드가 없다.** 그 축은 추정으로 확인할 수 없고 **잔액 전후 대조가 유일한 창구**다 |
| **⑥ `bypass_prompt_expansion`** | **기하 지시가 있는 호출에서 켠다.** 확장은 프롬프트를 그림 설명으로 부풀리며 **배치 지시를 소재 묘사로 희석한다** — "edge to edge" 는 확장을 통과하면 사라진다(외곽 링 0.0% → 100.0% 가 그 차이다). 소재 표현이 주인 호출(캐릭터·머신·씬)은 켠 채로 둔다 |

> **⑥ 부작용 관측 1건 — 검수 항목이 늘어난다.** 확장을 끈 2장 중 1장이 **숫자 글립("40.98" 형상)을 그려 넣었다.** 계기반 소재를 직설하면 모델이 계기 표시까지 그린다. 텍스트가 원도에 구워지면 D12 §8.1(전 표시 문자열 = 키 참조)과 어긋나고 **기계 게이트가 없다**(네거티브 프롬프트 필드 부재 — 지침 §9-⑦). 그래서 육안 검수의 배제 항목에 **"베이크된 글자·숫자"** 를 추가했다.

### 2.4 RD 산출물은 버리지 않았다

ⓑ의 **의장이 좋았다** — 관제 계기반 베젤, 앰버 눈금, 시안 림. 그것이 현행 프로파일(**외곽 암선 → 금속 상단광 → 베젤 본체 → 내측 그림자**)의 출처다. `docs/assets/시안/rd_frame_시안1_계기반베젤.png` · `rd_frame_시안2_변끝닿기.png` 로 승계했다. **RD 는 최종물이 아니라 시안 도구로 값을 했다** — 지침 §5.2 가 B급에 대해 내린 판정("RD가 최종물을 주지 않는다 — 시안 도구로 쓴다")이 9패치에도 그대로 적용된다.

## 3. 파라메트릭 생성 — 보장을 구성으로 옮긴다

`tools/assets/frame_gen.js` + `frame_spec.json` 신설.

```
렌더   node tools/assets/frame_gen.js            → FRAME_GEN OK frames=11 ninepatch_audited=10
대조   node tools/assets/frame_gen.js --check     → FRAME_GEN PASS frames=11 ninepatch_audited=10
```

**동심 링 + 코너 4방 미러**가 설계의 전부다. 링은 캔버스 경계로부터의 체비셰프 거리로 칠하므로 **4방 대칭이 공짜**이고, 변 가운데는 링 프로파일 그 자체라 **균일이 정의상 성립**한다. 표식은 좌상 코너 좌표로만 받아 4방으로 미러하므로 **대칭이 깨질 방법이 없다.**

### 3.2 눈금을 코너에만 둔 것은 9패치 계약이 강제한 배치다

D10 §5.4 는 릴 프레임에 **눈금·상태 램프**를 요구한다. 그런데 9패치에서 변 가운데는 **늘어난다** — 거기 눈금을 두면 늘어난 만큼 번지거나 반복된다. 코너 구역은 늘어나지 않으므로 눈금(3+3)과 상태 램프(2×2 시안)의 자리는 **코너**다. **타협이 아니라 규격이 정한 자리다.**

같은 정합이 하나 더 있다. `focus_ring_9p` 는 사양서 문면이 **"모서리 꺾쇠"**(corner chevrons)인데, 전 링이 투명이고 코너에만 ㄱ자를 두는 그 구성이 **9패치와 정확히 맞는다** — 꽉 찬 테두리로 만들면 늘릴 때마다 두께가 흔들린다. 규격이 이미 답을 적어 둔 셈이다.

### 3.3 색은 새로 정하지 않았다

프레임 팔레트 16키 전건 **조달 대장 소재**(master_60 + 정본 §5). 생성기는 **색값을 하나도 갖지 않고** `master_60.gpl` 과 정본 §5 를 파싱해 대장을 만든 뒤 스펙의 키→색이 대장 안인지 본다 — `icon_check.js`·`swatch_gen.js` 와 같은 규율이다. 대장 밖 색을 쓰면 렌더 전에 즉사한다(돌연변이 실측 — `#FFBF3D` → `#FFBF3E` 로 1 틀리자 `FATAL`).

버튼 4종의 설계 판단 2건을 남긴다.
- **강조·기본의 면은 같은 N05 다.** 갈리는 것은 테두리뿐이다 — 면까지 시안으로 채우면 9px 라벨의 대비가 무너진다.
- **비활성은 외곽 암선까지 N01 → N02 로 올렸다.** 비활성은 *"어두워지는 것"* 이 아니라 **대비가 사라지는 것**이다. 면과 테두리를 같은 N04 로 붙여 형태가 흐려진다.

### 3.4 검사 — 그리고 검사가 못 하는 것

`--check` 2축: ⓐ정의↔실물 바이트 대조 ⓑ**9패치 적합성 재측정**(대칭·변 균일·중앙 면 균일). **생성기가 보장한다고 믿지 않는다 — 보장의 근거는 코드이고 검사의 근거는 출력이다.**

돌연변이 3종 전건 검출:

| # | 변조 | 검출 |
|---|---|---|
| 1 | 스펙 표식 좌표 1개 이동 (8,10,12 → 8,10,13) | `✗ DEF … 정의와 다르다` |
| 2 | 실물 PNG 중앙 면 **1픽셀** 변조 | `✗ DEF … 바이트 1개 어긋남` |
| 3 | 팔레트 색 1비트 변조 (`#FFBF3D`→`#FFBF3E`) | `FATAL: 조달 대장 밖` (렌더 전 차단) |

> **검증한 척하지 않는다 — 축 ⓑ는 오늘 유효한 스펙으로는 물리지 않는다.** 동심 링과 4방 미러가 대칭·균일을 구성으로 보장하므로 **정상 스펙에서 NP-SYM·NP-TILE 을 깨는 방법이 없다.** 그럼 그 축은 무엇의 증거인가: ①앞으로 링 아닌 그리기 원시(사선·그라디언트·비대칭 표식)가 추가될 때의 안전선 ②그리고 **오늘의 발화 증거는 RD 산출물이다** — 같은 산술을 RD 6장에 적용해 1584px / 10~11% 를 얻었다. 즉 축은 실재하고, 다만 현행 생성기가 통과하는 것이 정상이다.
>
> 도구가 **보지 않는 것**도 적어 둔다: 도상이 보기 좋은지(눈 소관) · `texture_margin_*` 이 코너값으로 세워졌는지(씬·테마 층 — 아래 §3.5).

### 3.5 결선은 주력 몫이다 (⚙ 유지 — 유입만으로는 화면이 안 바뀐다)

`ui/frames/` 의 **코드 소비부는 현재 0건**이다. 화면은 전부 `StyleBoxFlat`(절차)과 `UiPalette` 색으로 서 있다(`race_screen.gd:_reel_frame_styles` 가 그 실례). 9패치는 `StyleBoxTexture` 의 `texture_margin_*` 를 **코너값(16 / 12 / 8)** 으로 세워야 발동하고, 그 값은 원도에 적을 수 없으므로 씬·테마 층에서 선언된다.

**즉 스토어 스크린샷의 전제는 유입이 아니라 결선이다.** 발주 §우선순위 2 의 근거(*"이 화면이 실물로 서야 ⑥ 스토어 준비물이 착수 가능"*)는 주력 결선까지 가야 성립한다 — 파일은 준비됐다.

첨부 `프레임_늘림검수.png` = 각 행 **왼쪽 원도 / 오른쪽 실기 치수 늘림 결과**(릴 64×62 · 패널 120×64 · 버튼 56×20 · 툴팁 90×28). **원도만 보고 판정할 수 없다** — 9패치의 요점은 늘어난 뒤의 모습이고, 늘림 시뮬레이션이 그것을 보여 준다.

## 4. 게이지 7파일 — 원도를 만들면 깨진다 (판정 요청)

운용지침 §5.3 은 RD 불가(높이 <16px)를 근거로 *"수작업 또는 런타임 렌더"* 두 길을 열어 두었다. 소비부를 실독하니 **수작업 쪽도 성립하지 않는다.**

| # | 근거 | 실측 |
|---|---|---|
| ⓐ | **`_fill` 에 색을 구우면 상태 전환이 죽는다** | `race_screen.gd:_refresh_resources()` 가 섀시 필 `bg_color` 를 매 갱신 `gauge_danger()` / `CHASSIS_OK` 로 갈아 끼운다. 게다가 `gauge_danger()` 는 색각 모드에서 `ALT_GAUGE_DANGER` 를 돌려준다(정본 §6 · O9). 색을 PNG 에 구우면 **경고 상태와 색각 대체가 함께 죽는다** |
| ⓑ | **펄스 세그먼트는 64px 에 균일 정수 분할이 없다** | 세그먼트 수 = `param_charge_cap` = **10**(D13) · 규격 폭 = **64**(사양서 §7 A-FR-17 확정 기준값). 테두리 2 + 안쪽 62 에 10칸 + 9칸막이 → 칸 폭 **5.3px**. 균일하게 하려면 폭이나 상한 중 하나를 바꿔야 하고 **둘 다 확정 기준값**이라 에셋이 못 바꾼다 |
| ⓒ | **D13 값을 이미지에 굽는 것 자체가 불변규칙 2 저촉** | 10칸을 PNG 에 고정하면 `param_charge_cap` 이 바뀔 때 **이미지가 조용히 데이터와 어긋난다.** 수치의 유일 창구는 D13 이고 원도는 창구가 아니다 |

## 8. 자수 — 광역 텍스트 치환이 타 레인 파일을 삼켰다

재번호(306 → 308) 때 `grep -rln "IMPL-306" docs/ tools/ | xargs sed -i` 를 돌렸다. **내 문서 4개와 함께 타 레인 문서 2건 + `impl_log` 의 타 레인 행 1건이 같이 바뀌었다** — 그쪽의 `IMPL-306` 은 정당한 자기 번호였다. 편집으로 즉시 원복했고(`git checkout` 금지 규약 준수) 실피해는 0이다.

**규약 5항의 사각이다.** 광역 스테이징(`git add -A`)을 막는 이유가 *"한 벌 트리에서 광역 조작은 남의 것을 삼킨다"* 인데, `grep -rl | sed -i` 는 **인덱스를 거치지 않고 작업 트리를 직접 광역 조작**하므로 그 규약이 닿지 않았다. 그리고 `IMPL-###` 는 전역 유일 식별자라 **재번호가 곧 남의 이력 변조**가 된다.

**교정 = 재번호는 대상 파일 명시 열거로 한다.** 2차 재번호(308 → 311)는 그렇게 집행했고, `impl_log` 는 타 레인도 308 을 쓰고 있어 **행 고유 접두로 겨눠 내 행 1건만** 바꿨다. 대장 §7 등재.
