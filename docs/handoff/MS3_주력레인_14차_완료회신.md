## 1. ① 거부 고지 전용 슬롯 — 그리고 죽은 결선 하나

### 1.1 [중대] `limit_hold` 고지는 실기에 한 번도 뜬 적이 없다

옮기려고 호출부를 훑다가 나왔다.

```
limit_hold 의 산지  : race_engine.gd:495  (hold_respin — 엔진 전수 grep 결과 유일)
그 화면 호출부       : race_screen.gd:699  (_on_respin)
_on_respin 의 거부   : sfx("input_rejected") 만.  _notify_skill_rejected 호출 0건
```

**표에는 행이 있었고**(`SKILL_REJECT_KEYS["limit_hold"]`), **문면도 3언어로 와 있었고**(IMPL-425), **소비부는 스킬 경로뿐이었다.** 스킬은 `limit_hold` 를 내지 않는다(`_skill_respin` 은 `respin_count` 만 올린다). 즉 **그 문면에 도달하는 경로가 없었다.**

보이지 않은 이유가 더 중요하다. 28차가 세운 축이 `_notify_skill_rejected()` 를 **직접 불렀다.**

```gdscript
screen._notify_skill_rejected(LIMIT_HOLD_ERROR)      # ← 표가 문면을 가리키는지만 증명한다
```

이것은 대장에 이미 등재된 형태다 — *직접 호출은 결선의 증거가 아니다*. 27차가 `_on_respin` 의 우회를 실측해 두고 28차가 문면을 붙였는데, **둘을 잇는 한 줄이 없다는 것을 두 회차 모두 자기 축으로는 볼 수 없었다.** 옛 축은 그 한 줄이 없어도 녹색이다.

이번 축은 **키를 누른다.**

```gdscript
screen.engine.hold_used = true          # limit_hold 의 유일 조건
screen._unhandled_key_input(_key_event(KEY_R))
_ok("리스핀 키 거부 = 전용 슬롯에 고지", slot.text == expected, ...)
```

반증 M4 = 그 한 줄을 다시 빼는 것(= 28차까지의 실상)이며 **검출된다.**

### 1.2 창구를 하나로 — `_report_outcome(ok, error)`

거부의 소리와 문면을 각 지점에서 따로 울리던 것이 이 사고의 형태였다(26차에 부스트가 상한 거부에도 `boost_spend` 를 울린 것도 같은 형태다). 그래서 **귀결을 한 곳에 모았다**: 소리·문면·직전 고지 걷기가 한 함수에 있다.

- **성공이 직전 고지를 걷는다** — 방금 성립한 조작 옆에 직전의 야단이 남으면 안 된다.
- **턴 경계도 걷는다** — `limit_hold` 는 새 턴에서 **실제로 거짓이 된다**.
- **부스트·소모품도 이 창구를 탄다.** 고지 원천을 늘린 것이 **아니다** — 규칙은 한 줄뿐이다(*표에 있으면 말하고 없으면 침묵한다*). 그 결과 `charge` 는 자연히 문면을 얻고 `limit_boost` 는 침묵한다. **`limit_boost` 문면 미유입 1건을 §8 대장에 올린다.**
- 봉인 침묵 3종(`no_trouble`·`symbol`·`same`)은 그대로 침묵이다 — 문면이 곧 결과 누출이다.

### 1.3 자리와 폭 — **자수 규칙은 불요다** (총괄 요청 회신)

자리는 **액션 행 바로 아래**다. 로그 존 얹기가 치르던 두 값을 끊는다 — ⓐ거부가 경기 기록과 같은 줄에 섞여 **슬롯 4를 밀어냈다** ⓑ`E10LogFeed` 는 우측 열이라 방금 누른 액션 행에서 **눈이 가장 먼 자리**다.

**상시 표출·문면만 비운다.** `visible` 개폐면 고지가 뜰 때마다 릴·액션 행이 한 줄만큼 튄다. 예약 자리는 튜토리얼 콜아웃이 Zone A 를 예약하는 것과 같은 축이다. (실기에서 확인 — S2 고지 표출 ↔ S3 걷힘 사이 릴·액션 행 y 무이동.)

**자수 상한을 두지 않았다.** 총괄 인계는 최소 100px(ja 실측 112px)을 요구했는데 이 슬롯의 실폭은 액션 행과 같은 열이다.

| 열 실폭 | 최장 고지 문면 (ja) | 배수 |
|---|---|---|
| **371.6px** | 112px | **3.3×** |

상한이 없으면 규칙도 필요 없다. 대신 **열 폭 > 최장 문면**을 3언어로 재므로, 문면이 자라거나 열이 좁아지면 그 축이 먼저 깨진다. *숫자로 상한을 적어 두면 열이 좁아질 때 검사가 침묵한다* — 그것이 상한을 쓰지 않은 이유다.

### 1.4 E 번호를 새로 만들지 않았다

D09 별첨A RACE-01 대장은 `E01~E08 · E10 · E15 · E11~E13 · E14` 이고 **E09 는 배정돼 있지 않다**(D09 본문도 RACE-01 문맥에서 E09 를 쓰지 않는다). 비어 있다는 것은 쓰라는 뜻이 아니므로 **정본이 배정하지 않은 번호를 화면이 주조하지 않았다.** 노드명 = `RejectNotice`. 번호가 없는 노드는 *"정본 대장 밖"* 이라는 사실을 그 자체로 말한다.

## 2. ⑦ 액션 경로 전수 — 결함이 두 계열로 갈렸다

27차 ③ 이 `_on_respin` 하나에서 본 형태를 화면 층 전건에 걸쳐 훑었다. 결론부터: **우회의 성질이 하나가 아니다.**

### 2.1 계열 A — 화면만 아는 조건 (핸들러가 반드시 다시 봐야 한다)

`_timer_active`·`_revealing`·SH3 택1 대기는 엔진이 모른다. 버튼 `disabled` 에만 적으면 키·패드가 통과한다.

**실측 구멍: SH3 택1 대기 중 리스핀·차지 개입·홀드 토글이 열려 있었다.** 슬롯 행만 `_snapshot_pending()` 을 물었고 나머지 세 줄은 묻지 않았다.

피해가 조용하다 — 대기 중에 릴을 다시 굴리면 위에 뜬 '이전 후보' 줄이 **두 걸음 낡은 후보**를 가리키고, 그것을 누르면 방금 지불한 차지가 되돌려진다. 어디에도 오류가 없고 플레이어만 잃는다.

닫는 방식은 **핸들러가 버튼과 같은 술어를 부른다**로 했다. 조건을 두 곳에 적으면 언젠가 갈리고, 갈린 순간 마우스와 키보드가 다른 게임을 한다.

```gdscript
func _intervention_open() -> bool:
	return _timer_active and not _revealing and not _snapshot_pending()
```

부수로 **릴 커서 조건도 합쳤다.** 그 자리의 주석이 *"`_toggle_hold()` 의 가드와 같은 조건이다 — 조건이 갈리면 '커서는 보이는데 A 가 안 먹는' 상태가 생긴다"* 를 계약으로 적어 뒀는데 실제로는 갈려 있었다. 주석이 자기 위반을 예고하고 있었다.

### 2.2 계열 B — 엔진이 아는 규칙 (핸들러가 보면 **안 된다**)

차지 부족·턴당 1회·합산 상한·횟수 소진은 엔진이 최종 판정자다(거부 시 비용·상태 전부 무변경 — 20차 계약 §1.1). 화면이 재구현하면 판정이 두 곳에 살고, 그것이 *"버튼은 켜지는데 눌리지 않는"* 상태의 씨앗이다.

그래서 **핸들러는 계열 B 를 보지 않는다.** 버튼 `disabled` 는 마우스에게 사전 표식으로 남기고, 키·패드는 엔진에 닿아 거부를 소리와 문면으로 되받는다. **두 경로가 각자 가진 채널로 같은 사실을 배운다** — 어느 쪽도 오해하지 않는다. (이 판단이 ① 의 고지가 실제로 필요한 이유이기도 하다: 키 경로에는 회색 버튼이라는 시각 표식이 없다.)

### 2.3 전수 대장

| 액션 | 비마우스 경로 | 판정 |
|---|---|---|
| 리스핀 | R · 패드 X 뗌 | **교정** — 대기 미확인 (계열 A) · `hold_used` 는 엔진 소관 (계열 B) |
| 차지 개입 | C · 패드 Y | **교정** — 대기 미확인 |
| 홀드 토글 | 1·2·3 · 패드 X+A | **교정** — 대기 미확인 |
| 스킬 슬롯 5 | F1~F5 · 패드 RB+A | 이미 대기를 물었다 (13차) · `usable` 은 계열 B |
| 확정 / 스핀 | `ui_accept` (키·패드·클릭) | 우회 없음 — `_on_primary_action` 이 국면·잠금을 전건 본다 |
| 듀얼 부스트 | (오버레이 버튼) | **교정** — 대기 미확인 · 상한·차지는 계열 B |
| 소모품 E13 | **없음** (마우스 전용) | 우회 **불가** — `use_consumable` 이 `finished`·듀얼·T1·SECTOR_TURN·보유 수를 전건 재검. **확인했고**, 확인 없이 그렇게 적어 둔 것이 종전 주석이었다 |
| 택1 두 갈래 | `ui_accept` / 버튼 | **관문이 반전이다** — 대기 *중에만* 열린다. `_intervention_open()` 을 걸면 영원히 닫히므로 가드가 다른 것이 정상이라고 명기했다 |

## 3. ④ SH3 신 후보 전용 버튼 — 이름 없이 있던 경로에 이름이 붙었다

종전에는 한쪽만 버튼이었다. 그러면 화면이 **택1로 보이지 않는다** — 보이는 것은 버튼 하나와, *"확정을 누르면 새 것으로 간다"* 는 **어디에도 적혀 있지 않은 사실**이다. SH3 의 효과 자체가 택1이므로 두 갈래가 같은 모양으로 서야 성립한다.

```
[ 새 후보 유지 ]     ← 신설. 바로 아래 살아 있는 릴이 그 내용이다
[ 릴 0 · 1 · 2 ]
[ ◇◇◇ 이전 후보 유지 ]  ← 기존. 도상 3기를 자기 안에 담는다
```

신 후보 쪽에 도상을 다시 그리지 않았다 — 릴이 이미 그것이고, 같은 것을 두 번 그리면 어느 쪽이 실물인지 흐려진다.

**병치 구조는 유지된다.** 버튼은 `_resolve_snapshot_keep_new()` 를 부른다 — **확정과 같은 함수다.** 시그널이 반환값을 쓰지 않으므로 void 래퍼 한 줄만 뒀다(두 번째 구현이 서면 두 경로가 갈린다). 총괄 판정 *"대기 유지 — 버튼이 서면 라벨이 된다"* 의 귀결: 키를 지우지 않고 라벨을 걸 노드를 세웠다. **V6 경고 1 → 0.**

## 4. ③ 언어 전환 재문면화

즉시 반영(§6.3 *적용 버튼 없음*)이 **이 항목에서만 성립하지 않고 있었다.** 표제·탭 5종·항목 라벨·◀▶·O5 고지행·닫기·초기화가 진입 시점 언어로 굳고, 바뀌는 것은 방금 만진 값 하나였다. **언어를 바꾼 화면이 바뀐 언어로 보이지 않으면 그 조작은 확인되지 않는다.**

라벨을 하나씩 찾아 고치지 않고 **다시 세운다.** `_build_tabs()` 가 문면의 유일한 산지이므로 그것을 다시 부르는 편이 갈라지지 않는다 — 하나씩 고치면 새 라벨이 생길 때마다 한쪽을 빠뜨린다(문면 이중 관리). 대가인 활성 탭·포커스는 떠서 되돌린다(노드 이름이 결정적이라 경로가 재생성 뒤에도 같은 자리를 가리킨다).

트리거는 리터럴 `"o11"` 이 아니라 **저장소가 쓰는 `languages` 플래그**다.

**부수 교정 1건.** `_on_reset()` 이 `queue_free()` 만 하고 `remove_child()` 없이 곧바로 `_build_tabs()` 를 불렀다 — 죽기로 예약된 노드가 한 프레임 트리에 남아 **이름이 충돌**하고(`Tab0` → `Tab0@2`) 그 프레임의 `get_child(0)` 는 사라질 노드를 집는다. 초기화도 O11 을 기본값으로 되돌리므로(= 언어가 바뀐다) 같은 절차로 합쳤다.

**대조군을 함께 세웠다** — 비언어 항목은 재구축하지 **않는다**. 없으면 *"무조건 다시 세운다"* 도 통과하고, 그것은 매 조작마다 포커스를 흔드는 구현이다.

**실기 확인:** 한 번 눌러 표제·탭 5·항목 라벨·값·푸터가 전건 영문으로 전환됐고, 활성 탭(Language)과 포커스(▶ 꺾쇠)가 그대로 남았다.

## 5. ⑤ 화면 층 제원표 — 1종 결선, 15종은 판정 요청

### 5.1 결선 = 포커스 링

제원표 16종 중 포커스 링만 **다른 결정을 요구하지 않는다**: Godot 슬롯과 1:1이고, 도상이 전 링 투명 + 코너 꺾쇠(제원표 예외 ⓑ)라 기존 `normal` 박스 위에 겹쳐도 의장이 충돌하지 않으며, 엔진 기본 포커스 박스와 **같은 자리·같은 역할**을 대체한다.

**마진을 검사에 손으로 적지 않았다.** 값의 산지는 `frame_spec.json` 의 `corner` 이고 테마는 사본이므로, 검사가 **원본을 읽어 대조한다**(27차 *"원본과 기계 대조"* 의 이식). 사본이 갈리면 거기서 깨진다.

자리는 `FlowScreen._enter_tree()` 다. `bind()` 에 두면 단독 인스턴스화 경로(검사 하네스·`race_screen._ready()`)가 테마 없이 서고, 그러면 **검사가 실기와 다른 화면을 잰다.**

실기에서 확인했다 — 타이틀·옵션·레이스 전건에서 포커스 버튼에 앰버 코너 꺾쇠 4각이 뜬다.

### 5.2 15종을 열지 않은 사유 — **정본이 답하지 않는 대응이 하나 있다**

`Button` 은 상태 **5종**(normal·hover·pressed·disabled·focus)을 요구하는데 프레임 세트는 의미 **4종**(default·primary·danger·disabled)이다. **hover·pressed 에 무엇을 대응시킬지가 제원표에 없다.**

화면이 이것을 정하면 그 순간 프레임 세트의 **의미 축이 상태 축으로 조용히 바뀐다**(예: primary 를 pressed 로 쓰면 '강조 버튼' 프레임이 '눌린 버튼' 프레임이 된다). 그리고 normal 만 텍스처로 바꾸고 hover·pressed 를 두면 **마우스를 올릴 때마다 의장이 갈린다** — 그것은 안 하는 것보다 나쁘다.

부수로 **결선의 대가도 재 뒀다**: 테마에 `normal` 계열 박스가 들어오면 액션 열 최소 폭이 실제로 움직인다(반증 M16 실측 — en 초과 40.4 → 32.4). 즉 ⑤ 의 나머지와 ⑧ 은 **같은 예산을 나눠 쓴다.** 15종 결선은 ⑧ 이 정리된 뒤가 순서다.

**판정 요청 ㉛** — Button 상태 5종 대 프레임 의미 4종의 대응. 프레임 2종 추가 발주인지, 기존 4종의 상태 배정인지, 아니면 `modulate` 로 상태를 표현하고 프레임은 의미에만 쓰는지.

### 5.3 연출 배치 제약 2건 · 배경 레이어 순서 = 착수하지 않았다

`fx_*` 8종과 `stage_*` 5종은 **소비부가 0건**이다(리포지토리 전역 grep). 그 배치는 E15 씬 패널의 컷 합성 자리이고, 그 자리는 지금 이월 대장에 있다(완급 비트 미재생 · CG 컷인 노드). **배치 없이 제약만 검사로 세우면 대상 없는 축**이 되므로(28차가 정리한 "구조적으로 실패할 수 없는 검사") 세우지 않았다. 제약 2건은 배치가 서는 회차의 선행 조건으로 남는다.

## 6. ⑥ 캡슐 대장 대조 · ⑧ E08 행 폭 실측

### 6.1 ⑥ — 파트너 콘솔은 열지 않았고, 문서를 읽었다

파트너 콘솔은 로그인이 필요하고 자격 증명 입력은 제 금칙이라 열지 않았다. **대장 §6 이 이미 정본을 문서로 지정해 뒀다** — *"규격은 제출 시점의 Steamworks 문서가 정본"*. 공개 문서 2면(`store/assets/standard` · `store/assets/libraryassets`)을 읽었다.

**에셋의 미확인 기억은 맞았고 숫자가 낡았다.** 헤더 캡슐은 실재하며 현행 규격은 **920×430**(`460×215` 는 1× 시절 값).

| 헤더 캡슐 | **920×430** | ❌ **누락** |
| 소형 캡슐 | 462×174 | ✅ |
| 메인 캡슐 | **1232×706** | ⚠ 616×353 (**반쪽**) |
| **세로 캡슐** | **748×896** | ❌ **누락** |

**D15 와의 충돌은 아니다.** §2.2-5 는 *"Steam 규격 **전 사이즈** 산출"* 이라 원칙이 이미 전량이고, 짧은 것은 **대장의 열거**다. 그러므로 불변규칙 9 사안이 아니라 대장 완전성 사안이다.

**판정 요청 ㉜** — 누락 2 · 반쪽 1 · 미확인 2 의 처분. 리프레임 산출이라 추가 비용은 크롭 선언뿐이다.

### 6.2 ⑧ — 산술이 답이라고 말한 자리에서 실측은 다른 답을 냈다

내러티브 10차 §4.1 은 *"기본 테마 Button 좌우 content margin 이 측당 1.8px 보다 크면 넘친다"* 로 남겼다. **재 봤다.**

```
기본 테마 Button  normal  content margin  L=10.0  R=10.0  T=7.5  B=7.5
빈 버튼 최소 20×15  ·  "S1" 42×41
```

**측당 10.0px** 이다. 버튼 8개가 160px 을 더 먹는다 — 산술은 문면 폭만 셌다.

| 언어 | 행 최소폭 | 예산 | 판정 |
|---|---|---|---|
| ko | **369.0** | 371.6 | 여유 **2.6px** |
| en | **412.0** | 371.6 | **초과 40.4** |
| ja | **401.0** | 371.6 | **초과 29.4** |

**en·ja 둘 다 넘친다** (내러티브 산술은 ja 를 여유 82px 로 봤다). 그리고 **실기 인상은 숫자보다 나쁘다** — HBox 가 우아하게 눌리지 않고 **확정 버튼이 로그 존에 잘려 들어간다.** D09 §3.2 는 *"확정 최우측 최대"* 인데 **가장 중요한 버튼이 깎인다.**

또 하나: **ko 여유가 2.6px 이다.** 국문도 사실상 한계선이고, 잠금 3 + 배지 2 조합(내러티브 부수 산술)은 여기서 바로 넘어간다.

**검사는 0 을 단언하지 않았다.** 지렛대는 `ui.race.chargeIntervene` 영문이고 `strings.csv` 는 내러티브 배타 창구이므로 화면 층이 고칠 수 없다. 대신 **발주 대기 상한 41.0** 으로 못박았고, 그 상한이 면제로 굳지 않게 두 축을 함께 세웠다.

- **한 언어는 상한 없이 들어와야 한다** — 전 언어가 넘치면 문면 사안이 아니라 배치 결함이다.
- **상한은 실측 최악과 5px 안이어야 한다** — 여유를 남기면 새 초과가 조용히 흡수된다(반증 M13 = 상한을 100 으로 늘리는 것 · 검출).

**내러티브 발주 ㉝** — `ui.race.chargeIntervene` 영문 단축(현행 105px 포함 폭 · 필요 절감 ≥41px). 화면 층에서 임의 수정하지 않았다.

### 7.1 M16 — 축이 반증을 지지 못했다 (자기 교정)

초판 축은 *"테마가 버튼 최소 크기를 바꾸지 않는다"* 였고 테마 전후로 최소 크기를 비교했다. **구조적으로 실패할 수 없었다** — Godot 의 `Button` 최소 크기는 `normal` 계열 박스만 세고 `focus` 는 위에 겹쳐 그리기만 하므로, **포커스 전속 테마는 어떤 마진을 넣어도 레이아웃을 못 움직인다.** 28차가 정리한 *"구조적으로 실패할 수 없는 검사는 반증을 지지 않는다"* 와 같은 형태다.

못박을 것을 바꿨다 — **선언 범위**다. `focus` 밖 항목이 들어오는 순간 액션 열 예산이 조용히 재계산되므로, 그 유입 자체가 실제 계약이다. 교체 후 재주입(테마에 `Button/styles/normal` 유입) → **검출**, 그리고 그 실패가 **초과 40.4 → 32.4** 를 함께 찍어 §5.2 의 예산 공유를 실측으로 남겼다.

### 7.2 검사 수 하한 — 오염을 하나 잡았다

㉚ 이 3언어를 재는데 **세 번 모두 같은 값**이 나왔다. 값이 같은 것이 통과처럼 보였지만 **측정이 안 된 증거**였다: `_fresh_session()` → `begin_career()` → `apply_language()` 가 저장된 o11 로 되돌리고 있었다. 원인은 두 겹이었다.

1. ㉘ 이 언어를 바꾼 뒤 **런타임 언어만 되돌리고 저장된 선택지를 남겼다** → 뒤 축 전부가 다른 언어로 돌았다. **저장소도 되돌리고 그것을 축으로 세웠다.**
2. ㉚ 이 언어를 세션 **생성 전에** 바꿨다 → 순서를 뒤집고 **전제를 마운트 뒤에** 보게 했다.

부수로 13차 ⓔ 의 `<= budget` 단언도 **프로필에 남은 선택지가 판정을 바꾸는** 상태였다(그래서 붉어졌다). 언어 권한을 ㉚ 하나로 모으고 ⓔ 는 발주 대기 상한과만 대조하게 했다. 폭 산정 유도도 `_action_row_metrics()` 하나로 합쳤다 — 두 축이 각자 계산하면 갈린 뒤에 어느 예산이 참인지 알 수 없다.
