눈 1회로 번호 자리를 읽고 원장에 등재했다. 전건 **덮기 검증 100%**.

판정 ②의 문면 그대로 **번호 영역만** 갈았다 — 팀 컬러 불변(같은 팀이므로 정본 A-MC-10 *"동일 섀시"*).

### 1.1 덮기를 기계가 센다 (`covers`)

외곽선이 결과적으로 옛 번호를 덮기는 한다. **그러나 우연히 덮는 것과 계약으로 덮는 것은 다르다** — 자형·자리·자릿수가 바뀌면 우연은 조용히 깨지고 **차에 번호가 두 개 남는다.**

그래서 눈으로 읽은 좌표를 원장에 적고 생성기가 그 구획의 전 픽셀 불투명을 센다. **이것이 눈 작업을 재현 계약 안에 넣는 방법**이며 IMPL-337 패치 단계와 같은 규율이다. 돌연변이 2종 전건 검출: 구획 확대 → `옛 번호 자리 30/72px 가 덮이지 않았다` · 구획을 실루엣 밖으로 → `covers 구획이 실루엣과 만나지 않는다 — 좌표가 틀렸다`.

### 1.2 부수 — 두 곳의 판독을 함께 올렸다

- **AX-9**: 심색을 옛 `#0B2A5E`(음영)에서 **보디 백 `#EEF3FA`** 로 올렸다. IMPL-335 ⓑ *"1번이 가늘어 안 읽힌다"* 의 해소다 — 패널 대비 ΔL 0.55. 외곽선을 **사이드포드 패널색**으로 두어 옛 번호를 패널로 지웠다(암색 외곽선은 후광 상자로 읽힌다).
- **GM-12**: 심색을 옛 `#7A4408`(암부 대비 ΔL **0.15**)에서 **금 `#C9A227`**(ΔL **0.41**)으로 올렸다. 금은 그리폰 정본 4색(진녹×금)이라 팀색을 벗어나지 않는다.

## 2. ⚠ 정본 저촉 1건 — `vh8_behemoth_base_side` 가 **18 이 아니라 13** 을 달고 있었다

번호 자리를 확대해 읽는 과정에서 나왔다.

```
프롬프트:        "... black and orange machine, ... number 18"
실물 (x71..77):  1 = #FF9A3C 주황 · 3 = #EEF3FA 근백색  →  "13"
정본:            VH-8 베헤못 = 불카 에이스 디아스 No.18 (D03 · 사양서 A-MC-08)
```

**13 은 보레아스 카 넘버다**(사양서 §4.2). 즉 **서로 다른 두 차가 같은 번호를 달고 있었다** — 단순 오기보다 나쁘다. 추격 시점은 번호가 아예 없어(실측) 대상이 아니다.

> **RD 는 이 셀 크기에서 숫자를 신뢰할 수 없다.** 프롬프트에 `number 18` 이 있었고 13 이 나왔다. 이것은 IMPL-319 의 일반화(*하한은 절대 픽셀 수가 아니라 대상 복잡도 대비 픽셀 수*)의 숫자 축 사례이며, **총괄 판정 ①이 번호를 오버레이 소관으로 옮긴 것과 같은 결론을 팩토리 베이스에서도 요구한다.**

**교정 완료 — 패치 단계에 `digits` op 을 신설했다.** `quantize --check` 를 살리려면 산출물을 손으로 고칠 수 없으므로 패치 층을 거쳐야 한다(IMPL-337 규율).

> **`pixel_patch.json` 의 *"형태를 만드는 일은 패치가 아니다"* 와 어긋나지 않는다.** 그 문장은 ax9 바퀴 시도에서 나왔고, 바퀴는 둥근 실루엣·상단광·허브를 **눈으로 맞춰야 하는 작화**였다. 3×5 숫자는 **선언된 자형에서 나오는 결정적 렌더**이고 덮기까지 기계가 센다 — 눈이 정하는 것은 자리 하나뿐이다. **판단의 축은 "손으로 그리는가"가 아니라 "재현되는가"다.** 돌연변이 검출 확인: `옛 번호 자리 15/60px 가 덮이지 않았다`.
>
> 자형은 `overlay_gen.js` 와 **같은 것을 쓴다** — 같은 셀에서 같은 숫자가 두 자형으로 나오면 세컨드 리버리를 얹었을 때 번호만 서체가 갈린다.

**남는 판정 요청:** 다른 베이스의 번호도 전수 확인했다 — GM-12 `5` ✅ · AX-9 `1` ✅ · 보레아스 s3 `13` ✅ · VH-8 추격 = 번호 없음. **VH-8 측면 1건 단독**이다. 이 교정이 판정 ①의 *"팩토리·프라이비티어 8장 존치"* 안에서의 결함 교정인지, 별도 추인이 필요한지 확인 부탁드린다 — **되돌림이 아니라 한 파일의 번호 픽셀 62px 교정**으로 처리했다.

## 3. ① 제출 — §4 개정 문면 초안

`docs/handoff/에셋트랙_사양서4장_개정초안.md` (105행). **사양서 본체는 수정하지 않았다** — 발행은 총괄 소관.

담은 것: **§4.1 신설 2행**(베이스 산출 방식 = 단일 섀시 파생 · 카 넘버 산출 = 결정적 렌더) + **§4.2 전문 대체**(A-MC-00 신설 + 01~06) + **§4.3 3행 대체 + [가안] 각주**(판정 ③ 동봉분) + 개정 근거·집행 계획.

### 3.1 지정 경로를 문면화하며 나온 판단 3건 (검토 부탁)

- **성장 서사의 축이 도색에서 표면으로 옮겨간다.** 현행 s2·s3 이 진화를 *"자리 잡기 시작한 리버리"·"완성 리버리"* 로 **도색**에 걸고 있어, 도색이 층으로 가면 그 축이 비어 버린다. 대체 축을 **표면 상태**(어긋난 패널 → 정돈 → 정련된 유선형)로 뒀다. **이것이 오히려 정본에 가깝다고 본다** — D08 의 성장은 *팀이 차를 고쳐 나간다*는 것이고 리버리는 후원·정체성의 표지지 정비도의 표지가 아니다. **부수로 조합이 실제로 27가지가 된다**(현행은 s3 리버리가 s1 에 얹히지 않는다).
- **IMPL-335 의 "1단계에 팀 컬러를 주지 않은 판단"이 자동 소멸한다** — 전 단계가 소지 상태이므로 판단할 것이 없다. 팀 컬러는 리버리 층이 준다.
- **A-MC-00 은 산출 파일이 아니다**(파생 원본)라고 명기해 **계수 24 를 불변으로 뒀다.** 파일로 세면 검산 37 이 38 이 된다.

### 3.2 정합 검사 신설을 함께 제안한다

파생이 기하를 건드리면 즉시 실패하도록 **3단계 실루엣 IoU 100% 요구 검사**를 넣겠다(현재 39~78%). 이것이 §4.1 신설 행의 *"기하는 불변"* 을 선언에서 계약으로 바꾼다. **성격 = 에셋 트랙 내부 게이트**로 두려 한다(소비부가 트랙 안 — 판독 게이트와 같은 취급). 빌드 편입이 필요하다면 지시 부탁드린다.

### 3.3 눈 작업량을 정직하게 적었다

표면 변조 6장을 좌표로 적는 일은 파편 소거(19px)와 자릿수가 다르다. 다만 패널 어긋남·긁힘은 **각진 면 단위**라 바퀴처럼 곡률을 맞출 필요가 없고(총괄이 윙에 대해 관측한 성질과 같다), s3 는 원판을 거의 그대로 쓴다. **A-MC-00 자체는 도상 복잡도가 낮아 생성 난도가 지금 베이스보다 내려간다**(무파츠·무리버리·무번호 — IMPL-319 일반화의 역방향 적용).
