## 2. 원격 24차 — 승인·기록

- **ⓐⓑⓒ 전건 승인.** 엔딩 삽입 = 전환 **앞**("전환 뒤에 두면 새 시즌의 상한을 잡아먹는다")·개막의 새 자리 = 개러지 이탈 + **발생 대장(`vn_seen`) 가드**(스킵도 발생 — "발생 = 도달")·커리어 개시 경로 존치 판단(빼면 시즌 1 개막이 어디에서도 안 선다) — 전건 정합.
- **이월 규칙 해석 승인** — D08 §8.4 이월의 주어는 "한 경계에서 우선순위 경합에 밀린 마일스톤 VN"이지 시즌 상한 초과분이 아니다. 주석이 범위를 넓혀 인용했고 그것이 발주 문면까지 이어졌다 — **"정본 인용은 범위까지 정본이어야 한다"** 기록. 상한 초과 기제를 세우지 않은 것(불변규칙 9)이 맞다.
- **I1이 원 결함을 그대로 재현**(`reason: "season_cap"`) — "조용히 안 뜨는 결함은 계수 축을 먼저 세운다"의 이행. "리셋 함수는 있고 호출이 없었다" = 20차 "이름의 부재는 기능의 부재가 아니다"의 실전형.
- **[보고 ②] 마일스톤 VN 발화 경로 미결선** — 상한 계수는 있는데 페이로드 생산처가 없어 D08 우선순위 4단·이월이 실행 대상 부재. **원격 25차 벽두 확인·기안 배정** (§4).

## 4. 발주 2건

### 원격 25차

1. **[1순위·차단급] `SaveManager` 저장 루트 재지정 훅** — 테스트는 `user://test_profiles/` 격리. 전 스위트(`test_tc_p`·`test_narrative`·`test_audio_wiring`·UISCR·`capture_hub_shots`)가 훅을 타는지 전수 확인 + **실 프로필 무접촉을 축으로**(게이트 실행 전후 실 슬롯 바이트 불변).
2. 좁은 슬롯 10건 정밀 배정 (23차 §4 승계 — 화면 층 실독 재량).
3. **마일스톤 VN 발화 경로 — 벽두 확인·기안**: D08 §8.4의 "마일스톤 VN"이 기존 6건 VN(막·기원·에필로그)의 발동 분류인지 별도 콘텐츠(크루 합류·일반 성취 VN 문안)를 요구하는지 **정본 실독으로 확정 보고**. 별도 문안이 필요하면 구현 금지·기안만(내러티브 발주 사안 — 콘텐츠 완결 축 재개봉이라 총괄 판정 경유).
