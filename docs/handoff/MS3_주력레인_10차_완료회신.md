## §1. ① 튜토리얼 콜아웃 재배치 — 결함 확인·교정 완료

### 1.1 결함은 5단계 전 단계에서 발현했다

실 트리에 RACE-01 을 세워 전 단계 rect 를 측정했다.

| 단계 | 지목 요소 | 콜아웃 패널 | 스트립 겹침 | 지목 겹침 |
|---|---|---|---|---|
| 1 스핀 | `E05Reels` (5,140,371×88) | (8,8) 624×34 | **624×22 = 13,728px²** | 0 |
| 2 확정 | `E08Confirm` (269,309,107×18) | (8,8) 624×34 | **13,728px²** | 0 |
| 3 홀드 | `E05Reels` | (8,8) 624×34 | **13,728px²** | 0 |
| 4 리스핀 | `E08Respin` (5,309,51×18) | (8,8) 624×34 | **13,728px²** | 0 |
| 5 차지 개입 | `E08ChargeIntervene` (200,309,66×18) | (8,8) 624×34 | **13,728px²** | 0 |

**IMPL-138 의 규칙은 지켜지고 있었다** — 지목 요소 겹침은 전건 0이다. 깨진 것은 *반대편을 어디로
잡는가*였다: 상단 배치를 화면 최상단(y=8)에 붙여 스트립 30px 중 **22px(73%)** 을 덮었다.
그리고 현행 5단계는 앵커가 **전건 하반부**(릴 중심 y184 · Zone D 버튼 중심 y318 > 화면 중심 180)라
전 단계가 상단 분기로 귀결된다 — 그래서 결함이 표본이 아니라 **전수** 발현한다.

### 1.2 교정 = 예약 영역(`_safe_area`)

배치 구간을 화면 전체가 아니라 **상시 표시 노드를 뺀 세로 구간**으로 한정했다.

- **예약 노드는 숙주가 넘기고 좌표는 실 rect 에서 읽는다** — `setup(session, host, reserved)`.
  코드에 y 값을 적지 않는다(불변규칙 2). 넘기지 않는 화면은 종전 거동이 그대로 성립한다.
- **RACE-01 은 Zone A 만 예약한다.** 순위·랩·게이지는 튜토리얼 중에도 읽어야 하는 상태다.
  **Zone D 는 예약하지 않는다** — 5단계 중 3단계가 Zone D 를 *지목*하므로 예약하면 반대편 배치가
  성립하지 않는다(하이라이트 회피는 겹침 비교가 따로 본다).
- 씬 = `ZoneA` 에 `unique_name_in_owner`(씬 소유권 = 주력 · diff 1줄).
- 반대편이 그래도 지목 요소를 덮으면 남은 쪽으로 넘기는 **겹침 비교 가드**를 두었다 —
  좁혀진 구간에서 우선순위는 지목 요소가 먼저다.

교정 후 실측 = 전 단계 **(8,38) 624×34 · 스트립 겹침 0 · 지목 겹침 0 · 화면 내**.

### 1.3 부대 결함 1건 — 자동 줄바꿈 라벨의 최소 높이 캐시

교정 검사를 붙이자 1단계만 실패했다. 원인은 배치가 아니었다.

```
DBG panel=(8,38) 624×294   CalloutText size=(616,270) min=(616,270) lines=1
```

`PanelContainer.get_combined_minimum_size()` 가 묻는 Label 최소 높이는 **자기 현재 폭**으로
계산되는데, 첫 배치 시점의 라벨 폭은 0이다. 그 결과 1줄짜리 문안의 최소 높이가 **270px** 로
잡히고 패널이 294px 로 부풀어 **릴(88px)을 통째로 덮었다**(겹침 32,384px²). 캐시는 무효화 없이
남아 여러 프레임 뒤에야 접힌다.

교정 3단 — ⓐ라벨 줄바꿈 폭을 먼저 못박고(여백은 스타일박스에서 읽는다) ⓑ실 폭을 기입하고
ⓒ**`update_minimum_size()` 로 명시 무효화**한다(`get_combined_minimum_size()` 는 무효 표식이
있으면 그 자리에서 재계산한다). 실기 확인 = **첫 프레임부터 34px**.

> 첫 프레임에는 패널이 하단(y318)에 서고 2프레임째 상단(y38)으로 옮긴다 — 그 시점엔 릴 rect 가
> 아직 정렬 전이라 중심이 상반부로 읽히기 때문이다. 겹침은 0이고 화면 전체 레이아웃이 같은
> 프레임에 서므로 결함으로 올리지 않는다(`_process` 재배치가 규격 — 주석 명문).

### 1.4 실문안 재점검 — 폭은 문제가 아니었다

| 키 | 실측 폭 | 전각 |
|---|---|---|
| `ui.tutorial.spin` | 201px | 22.33 |
| `ui.tutorial.charge` | 187px | 20.78 |
| `ui.tutorial.hold` | 179px | 19.89 |
| `ui.tutorial.respin` | 171px | 19.00 |
| `ui.tutorial.confirm` | 164px | 18.22 |

발주 기재 **19.0~23.0** 대비 양단이 조금 낮다(**18.22~22.33** — 본문 9px 폰트 실측). 어느 쪽이든
패널 내폭 616px 대비 **3배 여유**라 **크기 조정은 불요**였고, 재점검에서 걸린 것은 세로 배치 하나다.
헤더의 "문면은 아직 없다" 주석도 유입 사실로 갱신했다.

### 1.5 실기 캡처 — 3/5 단계

실행 게임에서 온보딩 기록을 비우고 신규 커리어로 진입해 캡처했다.

- **1/5** "본 유닛 대기. 전개 후보 산출 — 개시 입력 요청." — 스트립(P16/16 · LAP 1/3 · S1/4 ·
  하버 대로 + 속성 도상 + 전방/후방 게이지) 전부 판독 가능 · 콜아웃은 그 아래
- **2/5** "잠정 결과 = 전개 후보. 확정 시 사건화." — 동일 · 확정 버튼 하이라이트 유지
- **3/5** "후보 고정 가능. 유지 항목을 지목하십시오." — 동일

부수로 **Zone A 속성 `_16` 이 섹터마다 교체되는 것**을 실기에서 확인했다(하버 대로 → 창고 지구
시케인 → 베이사이드 커브 = 3종 도상 · 9차 결선분 재확인).

**4/5·5/5 는 실기 미도달.** 두 단계는 자원 게이트 뒤에 있고(리스핀 ◆1 · 차지 개입 ◆2), 3단계를
넘기려면 **릴을 고정한 채 리스핀**을 눌러야 한다(`_tutorial_pending = "hold" if not keep.is_empty()`).
GDAI `simulate_input` 은 `InputEventAction` 만 만들므로 홀드 상자에 포커스를 둔 `ui_accept` 가
**턴 확정으로 흘러** 홀드가 성립하지 않았다(3회 시도). 한 번은 `ui_focus_prev` 가 스킵 버튼에
닿아 튜토리얼이 종료됐다. 이 축은 **패드/키보드 실기 이월분**과 같은 벽이며, 배치는 5단계가
같은 분기(하반부 → 상단)로 귀결되어 값이 동일함을 §1.1·1.2 표가 기계로 덮는다.

### 1.6 회귀 — UISCR ⑯축

**앵커가 아니라 실 rect 교집합으로 본다.** 예약 영역은 노드 rect 에서 읽어 배치하므로 앵커·오프셋
단언은 규칙이 바뀔 때마다 검사를 고쳐야 하고 정작 "겹쳤는가"는 못 본다. 겹침 면적 0이 계약이다.
정렬이 끝난 부모가 필요해 레이스 화면도 첫 프레임 선치 대상에 넣었다(0 크기 부모에서는 교집합이
늘 0이라 단언이 공회전한다 — 원격 M6 전례와 같은 축).

돌연변이 4건:

| 변이 | 결과 |
|---|---|
| M1 예약 영역 미전달(`reserved = []`) | **5 FAIL**(전 단계 겹침 13,728) |
| M3 반대편 판정 반전 | **미검출 — 거동 보존**(겹침 가드가 상단으로 되돌린다. 현행 5단계에서 등가 프로그램) |
| M3′ 반전 + 겹침 가드 제거 | **3 FAIL**(2·4·5단계 지목 겹침 963/432/594) |
| M4 캐시 무효화 제거 | **1 FAIL**(1단계 32,384) |

M3 를 "미검출"로 남긴 것은 검사의 눈이 아니라 가드의 정당성 때문이다 — 그 사실을 기록으로 둔다.

## §2. ② VN 6건 — 75라인 전량 통독 · 걸린 라인 0

실 트리에 NAR-01 을 세우고 **데이터의 `lines` 를 소비부가 넘길 형태 그대로** 페이로드로 만들어
6건을 스킵 없이 통독했다. 재트리거 게이트(0.05s)는 가상 시계(`clock_override_msec`)로 우회해
**라인당 큐음을 개별 관측**했다.

| 축 | 결과 |
|---|---|
| 폭 (24전각 = 216px) | **초과 0** — 최대 181px(20.11전각, `vn_act3` L09) |
| 줄 수 | **2줄 이상 0** — 75라인 전건 1줄 |
| 문면 | **부재 0** — 키 노출·공란 없음 |
| 지문 라벨 | **전건 공란** (`ui.vn.speakerNarration` 값이 빈 것이 규격) |
| 화자 교대 | 8~10회 / 11~16라인 — 6건 전건 라인 단위 교대 |
| 큐음 | 베인 = `SE-V01a` · 타 화자 = `SE-V02` — **오배정 0** |
| tone | calm 3건 → `BGM-09` / tense 3건 → `BGM-10` — **전건 일치** |

건별: `vn_act1` 12라인 calm · `vn_act2` 12 calm · `vn_act3` 12 tense · `vn_act4` 11 tense ·
`vn_origin` 16 tense · `vn_epilogue` 12 calm.

**대사창 실폭 620px 은 규격 이탈이 아니다.** D09 §5.3 은 24전각을 **작성 규격(D04 §5.2)** 으로
두고, 본문 504행이 *"VN 대사 줄당 전각 24자 | 대사창 전폭 ⊃ 24자 … **수용 — 무보정**"* 으로 이미
닫아 두었다. 표시 층 클램프를 넣는 것은 정본이 수용한 항목을 뒤집는 일이라 하지 않았다(불변규칙 9).
현행 문안은 전건 22전각 이하라 실질 여유도 충분하다.

**주의 1건 — `tone` 폴백은 실질이 없다.** `milestone_vn.csv`·`vn_slots.csv` 의 `tone` 열은 전 행
`calm` 이고 `milestone_vn_row("vn_act*")` 는 애초에 빈 사전을 돌려준다. 즉 6건의 정조는 **인스턴스
값 하나가 전부 지고 있다**(D12 v1.4 정본 그대로). 소비부가 페이로드에 `tone` 을 안 넘기면
**3막·4막·기원 공개가 조용히 `BGM-09`(일상)로 떨어진다** — ①의 결선 시 필수 전달 항목이다.

### 2.1 막 래치는 정합 — 다만 **표시 경로가 없다**

래치 실측: 포디움(P3) 즉시 = `milestone_first_podium` 등재(시스템 층) · **서사 층 불변**(act 1 ·
`act_vn_fired` 공집합 · `pending_act_vn` 공집합) → `close_tour()` 에서 `vn_act1`·`vn_act2` 래치 ·
act 1 → 2 → 다음 경계 재발화 없음. **D08 §8.1 이층 규칙 그대로다.**

그런데 소비부가 없다.

| 산출물 | production 소비부 |
|---|---|
| `pending_act_vn` (`run_session.gd:364`) | **0건** |
| `narrative_act` | **0건** (검사만 읽는다) |
| `entry["lines"]` | **0건** (`test_narrative.gd` 만 읽는다) |

NAR-01 진입 경로는 둘뿐이고(`save_slot_screen` 시즌 오픈 · `records_screen` 재열람) **둘 다
`line_keys` 를 넘기지 않는다** — 그래서 실행 게임의 VN 은 지금도 `ui.vn.placeholderLine01` 을
재생한다(실기 캡처 확인: 베인 화자 + 자리 문안 1줄). **6건 75라인은 현재 게임에서 도달 불가**다.

발주 ②의 "결선됐다"는 데이터·화면 계약·큐음·tone 까지는 사실이고, **경계에서 그것을 띄우는
소비부 한 겹**이 비어 있다. 이 결선은 `run_session`·라우터 소관이라 **원격 차기 회차와 겹칠 수
있어 손대지 않았다**(다중 세션 규약 4). 통독 자체는 위 방식으로 이미 성립했다.

또 하나 — 6건은 `vn_act1` 의 `milestone` 열이 공란이라 **첫 투어 경계에서 1·2막이 동시 래치**된다.
1막 문면은 개러지 도입("차고 한 칸과 머신 한 대" · 베인 기동)이라 **도입부가 4전 뒤에 2막과 붙어서
나온다.** 구조상 그 외의 발화 시점이 없다(래치는 투어 경계 전속). 판정 요청 ②로 올린다.

## §3. ③ 툴팁·모달 — ANCH 교정분 장·단 양측 유효

| 대상 | 문안 | rect | 여백 L/R | 상/하 | 화면 내 |
|---|---|---|---|---|---|
| 툴팁 | 3자 | (206,342) 228×18 | 206 / 206 | 342 / **0** | ○ |
| 툴팁 | 132자(5줄) | (206,290) 228×70 | 206 / 206 | 290 / **0** | ○ |
| 모달 | 짧은 요약 | (200,137) 240×86 | 200 / 200 | **137 / 137** | ○ |
| 모달 | 132자 | (200,111) 240×138 | 200 / 200 | **111 / 111** | ○ |

툴팁은 하단 접지·가로 중앙을 문안 길이와 무관하게 유지하고 위로만 자란다(성장 BEGIN 의도대로).
모달은 장·단 양측에서 상=하 여백이 성립한다(성장 BOTH). **좌상단 고정 서명(ⓐ형)·우하단 사분면
서명(ⓑ형) 어느 쪽도 재현되지 않는다.**

**세로 성장 상한을 실측해 둔다** — 툴팁 본문 실폭 220px 고정이라 길이는 줄 수로만 자란다:
600자(25줄·330px)까지 화면 내 · **800자(34줄)에서 상단 87px 이탈**. 실 툴팁 문안은 최장 2자
(스킬 슬롯 표기 `S1`)라 두 자릿수 차이다 — 조치 불요, 상한만 기록한다.

**실기 캡처 = 툴팁 1건 확보.** RACE-01 에서 스킬 슬롯(`잠금`)에 포커스를 두고 `detail_info`(T)를
눌러 하단 중앙 접지 표출을 캡처했다. 키보드 T 는 컨텍스트 층이 가로채지 않고 공통 층으로 내려간다는
주석대로 동작했다(가로채는 것은 패드 Y 뿐).

**모달 실기는 미확보** — `ConfirmDialog` 호출부는 HUB 4화면(정비고·오버홀·스폰서·전략)뿐이고
GP 1회 완주 뒤에야 닿는다. 이 회차 범위 밖이라 기계 실측으로 대신했다.

## §5. ⑤ 저장 표시 회전 — 실물 빌드 없이 판정 가능한 형태로 전환

발주는 "실물 빌드 조건"이었으나, **회전 대상 도상을 읽는 것만으로 결론이 선다.**

`sys_save` 는 **방향성 글리프**다 — 가로 슬래브(y8~14, 폭 15px) + **아래를 향한 화살**(y16~22).
등속 회전(주기 1.0s · D13 v1.8)을 45° 간격 8컷으로 니어리스트 표본 렌더해 판독했다:

- **0°** 슬래브 + 하향 화살 — 정상 판독
- **45·135·225·315°** 사선 슬래브 + 분리된 덩어리 — 의미 소실
- **90·270°** 세로 슬래브 + 측면 화살 — 애매
- **180°** 화살이 **위를 향한다 — 의미가 '불러오기'로 반전**

통상 스피너가 회전 대칭(고리·호·분절원)인 이유가 그것이다. 지속 2.0s × 주기 1.0s = **정확히 2회전**
이므로 반전 상태를 두 번 통과한다.

§181 이 "저장 아이콘 + 회전 애니메이션"을 명문하므로 **구현이 연출을 바꾸지 않았다**(불변규칙 9).
판정 요청 ④로 올린다. 시간 감각(2.0s 가 "저장 중"으로 읽히는 길이인가)은 여전히 실물 빌드 몫이며
이월 유지다.
