## 1. ① 익스포트 파이프라인 — 원격이 어디까지 가는가

### 실측: export template 부재 → 실 바이너리 불가

```
ERROR: Cannot export project with preset "Windows Desktop":
No export template found at the expected path:
  ~/.local/share/godot/export_templates/4.7.stable/windows_release_x86_64.exe
```

`~/.local/share/godot/export_templates/` = **빈 디렉토리**. 템플릿 조달(≈1GB 내려받기)은 발주 밖 환경 변경이라 하지 않았습니다.

### 그러나 `--export-pack` 은 템플릿 없이 성립한다

**이것이 이번 회차의 갈림이었습니다.** 실행 파일은 못 만들어도 **팩(리소스 페이로드)은 만들 수 있고**, G-6 ①·G-7 ①이 묻는 것은 대부분 팩 층의 사실입니다.

| 층 | 원격 | 주력 |
|---|---|---|
| 리소스 페이로드(무엇이 실리는가) | **전부 가능** — `--export-pack` | — |
| 팩에서 하네스 재실행 | **가능** — `--main-pack` | — |
| 실행 파일 심볼 테이블 | 불가 | **주력 몫** (템플릿 필요) |
| Steam 제출물 성립 | 불가 | **주력 몫** |

주력 인계분은 §5.

### 프리셋 2계 분리 (판정 여지 — §4 ⓑ)

**출시와 검증이 같은 빌드일 수 없다는 것**이 D14 자체에 있었습니다: §5.6 방법 ①은 "검증 코드를 빼라"고 하고 방법 ②는 "그 하네스를 출시 후보 빌드에서 재실행하라"고 합니다. 한 빌드로는 둘 다 만족할 수 없습니다.

D14 §8.1이 이미 답을 갖고 있습니다 — *"계측은 내부 테스트 빌드 전속 … 출시 빌드 컴파일 제외"*. 그 원칙을 프리셋으로 이행했습니다:

| 프리셋 | `exclude_filter` | `custom_features` | 용도 |
|---|---|---|---|
| Windows Desktop | `tests/*` | — | 출시 후보 |
| **Windows Verify** (신설) | — | `verify` | G-6 방법 ②③ 재실행 |
| Android | `tests/*` | — | (MS-3 범위 밖 — §4 ⓒ) |

**두 곳에 두면 한쪽만 낡습니다.** 그래서 검사가 그 위험을 집니다 — EXP ⓒ가 두 프리셋의 옵션 블록을 전수 대조해 **선언된 차이(name·custom_features·exclude_filter·export_path) 밖의 이탈을 잡습니다.** 반증 E3′에서 검증 프리셋의 아키텍처 한 줄을 바꿨더니 그대로 붉었습니다.

> 부수 확인: 반증 E3 초안이 *"앵커 2건 — 유일해야 한다"*로 주입 실패했는데, **그 실패가 두 블록이 실제로 동일하다는 증거**였습니다.

## 2. ② G-6 — 3방법 전건 집행

`tools/export/gate_g6.sh <출시팩> <검증팩>` 한 명령.

```
── 방법 ① 정적 검사 (출시 팩 검침)
     [ok] 출시 팩 — res://tests/ 0개
     [ok] 검증 입력 리소스 0개
     [ok] 결제·광고 SDK 심볼 0
── 대조군: 출시 팩에서 하네스 적재 시도
   [ok] 출시 팩은 하네스를 열지 못한다 (제외가 런타임에서 실재)
── 방법 ② 런타임 캡처 (검증 팩)
   [ok] SEAL-E 98검사 통과 (5경로 노출 0)
   [ok] TC-C 2241검사 — 봉인 축 전건 통과
── 방법 ③ 오디오 발화 (검증 팩)
   [ok] AUDIO 384검사 통과 (봉인 개폐·결과 암시음 0)

G6_PASS 3방법 전건 노출 0
```

### 하네스를 소스가 아니라 **팩에서** 돌렸다

`--main-pack` 은 익스포트 산출물을 그대로 주 프로젝트로 세웁니다. 여기서 도는 것은 리포지토리의 코드가 아니라 **빌드에 실린 코드**입니다. 방법 ②의 *"출시 후보 빌드로 재실행"* 이 팩 층에서 문자 그대로 성립합니다.

**대조군을 붙인 것이 요지입니다.** 목록에서 `res://tests/` 가 0개라는 것과 런타임이 그것을 못 연다는 것은 **다른 사실**입니다 — 앞은 제가 세고 뒤는 엔진이 답합니다. 출시 팩에 같은 명령을 걸면 `Can't load script` 로 거부됩니다.

### 발견 — **팩에서 원리적으로 성립하지 않는 축이 있다**

익스포트는 `.gd` 를 `.gdc`+`.remap` 으로 치환합니다. 그래서 **원본 문자열을 읽는 축**은 팩에서 파일 자체를 찾지 못합니다:

| 축 | 팩에서 | 성질 |
|---|---|---|
| TC-C11 봉인 축 · SEAL-E 5경로 · AUDIO 발화 | ✅ 통과 | **거동 축** — 어디서든 돈다 |
| TC-C "엔진 원본 적재" 1축 | ✗ | 원본 대조 축 |
| AUDIO-W 결선 대조 · UISCR 발신처 전수 | ✗ | 원본 대조 축 |

**이것은 빌드의 결함이 아니라 축의 성질입니다.** 그래서 G-6 는 거동 축만 팩에서 돌리고 원본 대조 축은 소스 트리 게이트가 집니다. 게이트 스크립트는 TC-C 의 알려진 1축을 **허용 목록으로 명시**합니다 — 그래야 TC-C11 축이 깨졌을 때 그 실패가 *"원래 하나 실패한다"* 에 묻히지 않습니다.

## 3. ③ G-7 — 데스크탑 2검사

`tools/export/gate_g7.sh <출시 산출물>`. 결과 `G7_PASS`.

- **① 결제·광고 SDK 심볼 0** — 산출물 원문 스캔(`grep -a`). 소스 층도 0건.
  **좁게 잡았습니다**: `AdMob`·`BillingClient`·`StoreKit`·`SteamAPI_` 등 벤더·API 고유 토큰 전속. 일반어를 넣으면 설계상 정당한 것을 잡습니다 — `IAdService`(D12 §2.2 어댑터 계약)와 `sfx("purchase")`(SE-U07 구매 성사음 — **게임 내 재화**)가 그 실물입니다. 오검출은 검사를 끄게 만들므로 넓은 축은 소스 층 MIX0 이 집니다.
- **② 스토어 결제 권한 선언 0** — Windows 는 권한 매니페스트가 없어 *"선언 0"이 자동으로 참*이고, **그 참은 검사의 결과가 아니라 플랫폼의 성질**입니다. 실제로 볼 것이 있는 곳은 프리셋의 권한 열이며 EXP ⓓ 가 D14 §5.7 허용 목록(네트워크·인터넷 상태·진동)으로 봅니다. 현행 안드로이드 프리셋은 **전 권한 false·커스텀 0** 입니다.
- **③ 모바일 매니페스트 = 미실시** — MS-3 = Steam EA(D15 §1.1). **통과로 적지 않았습니다.**

IMPL-334 ② 이월분입니다. 실측 결과 **전제가 틀렸습니다**: `jouyou_kanji.txt` 는 **이미 팩에 없습니다**. `export_filter="all_resources"` 는 *리소스*만 담고 `.txt` 는 임포터가 없어 리소스가 아니기 때문입니다.

> **필터를 신설하지 않았습니다.** 아무것도 막지 않는 줄을 방어처럼 남기면 *"여기서 막고 있다"* 는 거짓 근거가 됩니다(IMPL-483 등가 돌연변이 교훈의 두 번째 적용). 대신 **성질을 검침이 단언**합니다 — `probe_pack.sh` 가 검증 입력 리소스 0을 매 회 확인하므로, 누군가 `include_filter` 를 열면 그때 붉습니다.

### 함정 — 이름이 정체를 말하지 않는다

`data/structures/grid_debug.json` 은 **이름에 debug 가 있지만 출하 콘텐츠**입니다(그리드 구성 — 라이벌 8·필러 7·플레이어 시작 16). `exclude_filter="*debug*"` 같은 이름 기반 제외를 걸었다면 **게임이 그리드를 잃습니다.** 제외는 경로로만 걸었습니다.

### AUDIO-W 부하 의존 — **이번에는 로그를 남겼습니다**

- 배터리 1회차: `AUDIO_WIRING_FAIL checks=107 failures=17` — 실패 형태가 **문서화된 그 형태 그대로**입니다: `발화: (공란)` · 라운드 경계를 넘어 밀린 발화(`라운드 2 — 발화: SE-R01, SE-R02, SE-R03, SE-R04, SE-I01`) · `봉인 창이 정지 연출을 덮었다 — 창 안 발화 +0`. 실시간 예산이 굶은 자국이지 결선의 실패가 아닙니다.
- 단독 3회: **3/3 통과** (`checks=107 rounds=6`) — 문서화된 판별 절차대로.
