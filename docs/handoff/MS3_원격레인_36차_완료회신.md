## 1. ① 접미 규칙 — **되짚기로 판정한다**

붙이는 자리는 둘(개막·엔딩)이었고 **떼는 자리가 하나 더 생겼다.** 포맷을 리터럴로 흩어 두면
붙이는 쪽만 고쳐도 떼는 쪽은 *조회 실패*로만 나타나고, **조회 실패는 화면에서 "문면이 없다"와
구분되지 않는다** — 이번 결함이 정확히 그 형태였다.

```gdscript
const SEASON_VN_ID_FORMAT := "%s_s%d"
const SEASON_OPEN_VN_STEM := "vn_season_open"
const SEASON_CLOSE_VN_STEM := "vn_season_close"
const SEASON_VN_STEM_SLOTS := { SEASON_OPEN_VN_STEM: SEASON_OPEN_SLOT, ... }
```

**역방향은 `_s` 를 찾아 자르지 않는다.** 자르기만 하면 이름 안에 `_s` 를 품은 id 가 걸리고
(`vnbeat_clue_silence` 가 그 실물), 더 나쁜 것은 **자르기로는 걸러지지 않는 형태**다:
`vn_season_open_s01` 은 `_s` 뒤가 정수로 읽히므로 자르기 판정을 통과한다. 잘라 낸 조각을
**앞면 포맷으로 다시 조립해 원본과 같은지** 물으면 그때 다름이 드러난다.

> **포맷이 바뀌는 날 역방향이 스스로 실패한다** — 규칙을 한 곳에 둔 값은 상수 자체가 아니라
> 역방향이 앞면을 *인용해* 자기를 검산하게 되는 구조다. 반증 M5(포맷 변경)에서 앞면 소비가
> 실측으로 확인됐다.

## 2. ② 재열람 창구 — **조립기는 하나다**

`RunSession.archive_replay_payload(vn_id, next_route)` 신설. **여기서 새로 조립하지 않는다** —
열쇠를 되찾는 일만 하고 조립은 기존 조립기 둘(`_act_vn_payload`·`_beat_payload`)이 한다.

되찾는 갈래가 셋인 것은 아카이브에 실리는 id 계열이 셋이기 때문이다(`vn_seen` 의 실물):

| 계열 | 열쇠 | 되찾기 |
|---|---|---|
| 막 VN | `vn_act1` … | 인스턴스 id = 표 실체 id (접미 없음) |
| 브리핑·마일스톤 비트 | `vnbeat_crew_nadia` … | 비트 id 직행 |
| 시즌 경계 | `vn_season_open_s1` … | 줄기를 떼어 **슬롯으로** 비트를 되찾고 인스턴스 id 는 유지 |

**조회 실패는 빈 사전이다.** 골격 폴백으로 흘리면 이번 결함이 그대로 되돌아온다. 기록실은 그
빈 사전을 보고 **버튼을 죽이고** `replay_omissions` 에 남긴다(`vn_screen.choice_omissions` 전례 —
사람에게는 `push_error`, 기계에는 관측 지점).

### 자기 교정 — 지우는 줄이 아무것도 하지 않았다

초판은 `payload.erase("calendar")` 를 넣었다. 반증 설계 중에 **그 줄을 지워도 축이 같은 값을
낸다**는 것을 발견했다: `calendar` 플래그는 `season_open_payload` 가 **조립기 밖에서** 얹으므로
재열람 경로에는 애초에 오지 않는다. 등가 돌연변이다.

> **방어처럼 보이는 줄이 사실은 아무것도 지키지 않았다.** 코드를 지우고 **성질은 축이 단언**
> 하도록 남겼다 — 재열람이 언젠가 그 창구를 경유하게 되면 그때 축이 붉는다. 지우는 줄을
> 남겨 두면 "여기서 막고 있다"는 거짓 근거가 주석에 남는다.

## 3. ③ 발신처 전수 — 세 번째 경로

`res://ui` 전 `.gd` 원본에서 `go("NAR-01",` 를 훑었다. **발신처 6곳** — 개러지 이탈(개막·브리핑)
· 개시 경로 · 오버홀(엔딩) · 투어 결산(마일스톤) · 기록실(재열람). **직접 조립은 기록실 하나뿐이었고
세 번째 경로는 없었다.**

**눈으로 본 것을 축으로 바꿨다** (이번 결함이 22차 동형의 재발이므로 다음 재발도 사람이 아니라
기계가 받아야 한다). UISCR ㊹-ⓒ 4축:

- 인라인 사전 조립 0 — 인자가 `{` 로 시작하면 붉는다
- 전 발신처가 세션 창구를 경유
- **발신처 실재 ≥5** — 축이 스스로 비면 "위반 0"이 무의미하다(구조적으로 실패할 수 없는 검사 방지)
- **창구 대장 = 원본 실제** — `run_session.gd` 의 공개 `*_payload` 집합과 못박은 목록을 대조한다.
  새 창구가 생기면 이 축이 **먼저** 붉고, 그때 "이 창구도 전수 규칙을 지키는가"를 사람이 한 번 본다

> 검사기가 아니라 스위트에 둔 이유: 불변규칙 7의 신설 검사 절차(경고형 → 실측 상신 → 판정)는
> **검증기 층의 규약**이고, 이 축은 화면 층을 실제로 세워 재는 UISCR 의 결이다. 차단/경고 판정을
> 요청드릴 사안이 아니라고 판단했습니다 — 다르게 보시면 되돌리겠습니다.
