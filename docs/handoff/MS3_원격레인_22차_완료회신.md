## 1. 발주 밖 발견 — **통과는 검사의 증거가 아니다**

### 1.1 무엇이 나왔나

ⓔ를 집행한 뒤 반증으로 `stage_id`·`axis_id` 에 오타를 주입했다. **둘 다 통과했다.**

원인: `_run_v2_references()` 가 **두 판정기로 갈려** 있었다.

| 대상 | 판정기 | 보는 타입 |
|---|---|---|
| 구조 JSON 필드 | `_check_reference()` | `string_key` · `fk:` · `fk_optional:` · `structure_ref` |
| **표 열** | 인라인 분기 | **`string_key` · `fk:` 뿐** |

즉 표 열의 `fk_optional:`·`structure_ref`·`structure_ref_optional` 은 **아무도 보지 않았다.** 실측 5열:

| 열 | 타입 | 언제부터 |
|---|---|---|
| `garage_facilities.requires_crew` | `fk_optional:crew.csv` | 기존 |
| `milestone_vn.relation_transition` | `fk_optional:relation_axes.csv` | 기존 |
| `milestones.source_id` | `fk_optional:ai_rivals.csv` | 기존 |
| `vn_beats.axis_id` | 22차에 `fk:` → `fk_optional:` | **이번 회차에 내가 껐다** |
| `vn_beats.stage_id` | 19차부터 `structure_ref` | **19차부터** |

### 1.2 두 가지를 자인한다

**ⓐ 19차 회신의 문장이 틀렸다.** 19차 §②는 *"`stage_id` = `structure_ref` 가 실제로 걸렸다(V2 pass)"* 라고 적었다. 그때 걸린 것은 **아무것도 없었다** — 볼 분기가 없었고, `VALIDATORS_PASS` 는 "검사가 통과했다"가 아니라 "볼 것이 없었다"를 뜻하고 있었다. 20차에 스스로 적은 *"이름의 부재는 기능의 부재가 아니다"* 의 대칭형이다: **통과의 존재는 검사의 존재가 아니다.**

**ⓑ 내가 살아 있던 검사를 껐다.** `axis_id` 는 `fk:` 여서 **실제로 검사되고 있었다.** 선택화가 그 검사를 없앴고, 내러티브 5차가 근거로 든 전례(`milestone_vn.relation_transition` 이 같은 표를 `fk_optional:` 로 참조)는 **검사되지 않는 열의 전례**였다. 전례는 실재했고 검증 가치는 0이었다.

### 1.3 교정 — 판정기를 하나로 모았다

표 열도 `_check_reference()` 를 탄다. **V2 1088 → 1132검사(+44) · 위반 0** — 구멍을 닫았을 때 살아 있는 위반이 없었던 것이 가장 좋은 결과다. 오타 주입 재측정으로 양방향 확인(G3·G4).

> 검사기가 둘로 갈려 한쪽만 자라는 형태는 이 프로젝트에서 반복된다(V7 내용/논리 · AUD/AUDIO-A). 다만 그 둘은 **의도적으로** 가른 것이고 이것은 **모르고** 갈린 것이다 — 구분이 중요하다.

## 2. ⓐ~ⓒ 상용한자 — 검사가 스스로 승격했다

| 항목 | 결과 |
|---|---|
| ⓐ 표 이동 | `docs/reference/jouyou_kanji_2136.txt` → `godot/data/reference/jouyou_kanji.txt` (`git mv`) |
| 표 계수 | 문자 **2,138** · **유일 2,136** ✅ (`叱` 중복 1건 — `𠮟`→`叱` 치환이 기존 `叱` 과 겹쳤다) |
| ⓑ `JA_KANJI_EXPECTED` | 500 → **501** |
| ⓒ 상용 밖 | **0** |

`FileAccess.file_exists` 분기가 21차에 심어 둔 대로 **다음 회차 없이 실대조로 승격**했다.

**계수 501 을 두 상태에서 확인했다** — 커밋본(HEAD)과 작업 트리(내러티브 미커밋 1행 포함) 양쪽에서 501·상용 밖 0 이 동일하다. 병행 커밋 예고가 있었으므로 어느 시점에 커밋되든 대장이 흔들리지 않는 것을 먼저 봤다.

**'표를 기다리는' 분기는 만료시켰다.** 21차에는 표 부재가 정당한 상태였지만 이제 부재는 회귀다 — 경로 오타가 검사를 조용히 '대조 보류'로 내려앉히던 것을 반증이 잡았다(G1: 경로 오타 주입 시 스위트가 **녹색이었다**).

**판정 자기 검사를 달았다.** 표가 가른다는 사실(`墟`·`蜃` 불포함 · `一`·`叱` 포함)과 **비교가 실제로 돈다**는 사실은 다른 축이다 — 단일 분기 검사는 그 분기를 지우면 조용히 통과한다(G2 초판 미검출). 실사용과 자기 검사가 같은 함수(`_outside_of`)를 타고, 자기 검사는 알려진 입력에서 `墟` 1자 적출을 요구한다. V7S 와 같은 형태다.

> **정밀화 1건:** 내러티브 §6-D 의 선점검 후보 17자 중 실제 상용 밖은 **2자(`墟`·`蜃`)** 였다. `蜃 · 楼` 로 묶인 `楼` 는 상용 안이다 — 후보 목록은 "1회 사용 + 지명·풍물"이라는 선별 기준이었고 상용 여부 판정이 아니었으므로, 표가 온 지금 나머지 15자는 대체 불요다.

## 3. ⓓ 언어 스텝 — 조립 분기 제거

21차는 문면 미유입분을 계약 이름으로 조립했고(리터럴은 V2 가 차단하고 그 차단이 옳았다), 내러티브 5차가 문면을 유입해 **전 단계가 리터럴이 됐다.** `LANGUAGE_STEP_DOMAIN`·`STEM`·`NAMES` 3상수 제거.

GLYPH ⑥ 이 남는 축을 바꿔 잡는다 — **`steps.size() == languages.size()`**. 열이 늘고 문면이 안 오면 그 단계의 라벨이 빈 문자열이 되는데, **빈 라벨은 화면에서 "선택지가 없는 것"과 구분되지 않는다.** 조립 상수 잔존 0 은 저장소 **원본 텍스트**로 본다(클래스 객체에 상수 유무를 묻는 것보다 확실하고, UISCR ⑬ 이 검증기 원본을 읽는 것과 같은 형태).

## 5. ⓕ~ⓘ 개막 VN 결선 — 세 곳이 끊겨 있었다

### 5.1 표 행 (ⓕ)

```
vn_beats.csv:      vnbeat_season_open,,vnslot_season_open,,0,0,3,calm
vn_beat_lines.csv: vnbline_season_open_1~3 (지문·테오·마르타)
```

축도 무대도 없는 첫 비트. `relation_stage("")` 가 0 을 돌려주므로 단계 구간 0~0 이 그대로 성립한다(내러티브 §4.3 검증분 — 실측 확인).

### 5.2 페이로드 창구 (ⓖ·ⓗ) — **조립기는 하나다**

```
begin: save_slot_screen  ─┐
                          ├→ session.season_open_payload() → _beat_payload() → NAR-01
s2+:   overhaul_screen   ─┘
```

두 경로가 각자 조립하면 한쪽만 라인을 넘긴다 — **결선 전이 정확히 그 상태였다**(개시 경로만 있었고 그 경로가 `line_keys` 를 넘기지 않아 폴백 1줄이 떴다 = 주력 12차 관측 3).

초판은 `season_open_payload` 가 페이로드를 **직접** 조립했다. 돌연변이 G6(`_beat_payload` 의 슬롯을 상수로 되돌림)이 **미검출**로 그것을 드러냈다 — 개막 경로가 `_beat_payload` 를 타지 않으니 그 일반화가 아무 데서도 쓰이지 않았다. 조립기를 하나로 합쳐 슬롯·톤·라인이 전부 비트 행에서 오게 했고, 그러자 G6 이 검출됐다.

**시즌 2+ 진입점이 아예 없었다** — `vnslot_season_open` 의 데이터는 `trigger season_start`(매 시즌)인데 결선은 시즌 1 한 번뿐이었다. 문안을 시즌 무관 정경으로 쓴 내러티브의 근거(§4.2-2)가 여기서 결선 요구가 됐다.

`vn_id` 는 **시즌 단위 인스턴스로 유지**했다(`vn_season_open_s%d`). 비트 id 로 바꾸면 아카이브가 전 시즌을 한 줄로 접는다 — 라인은 비트에서, 신원은 시즌에서 온다.

### 5.3 아카이브 표제 (ⓘ) — 리터럴 매핑을 두지 않았다

비트 행이 이미 `slot_id` 를 선언하고 `vn_slots.name_key` 가 그 슬롯의 표제다. 매핑을 손으로 적으면 같은 사실이 두 곳에 살고 비트가 늘 때마다 한쪽이 밀린다. `name_key` 는 `string_key` 열이라 **V2·V6 이 참조를 이미 본다** — 3차가 막 VN 에 리터럴 표를 쓴 것은 막 VN 에 슬롯 행이 없기 때문이고, 성격이 다르다.

실측: 비트 2종 전건 표제 확보 · **원문 id 노출 0** (교정 전 `raw=2`).

> 부수 방어 1건: `vn_slot()` 은 미등재 슬롯에 `_load_ok = false` 를 세운다. **표시 함수가 적재 상태를 떨어뜨리면 그 다음 `param()` 부터 조용한 0 이 나오므로** 공란 검사를 먼저 둔다.

## 6. V6 고아 7 — **소멸. 다만 총괄 전망의 절반은 다른 이유였다**

`warnings=0`. 총괄은 *"ⓕ~ⓘ 결선으로 소멸 전망"* 이라 했는데, 7건 중 **2건은 ⓕ~ⓘ 와 무관**했다:

| 키 | 소멸 경로 |
|---|---|
| `ui.options.stepEnglish` · `stepJapanese` | ⓓ |
| `vn.seasonOpen.beat01~03` | ⓕ |
| **`vane.brief.skillUse01`** | **20차 §5 이월분 — `race_engine.use_skill()` 결선** |
| **`raceLog.duelLoseWaived01`** | **20차 §5 이월분 — SI1 면제 문면 결선** |

두 키는 20차가 "없는 키를 참조하는 것보다 침묵이 낫다"로 무발화로 두고 보고한 것이고, 내러티브 5차가 유입했으므로 **소비부는 엔진 층**이다. 발주에 없었지만 고아 경고의 절반이 이것이었고 침묵을 유지할 이유가 사라졌으므로 함께 결선했다.

- 스킬 발화 = `vane.brief.skillUse01`("등록 루틴 적용. 변수 갱신.") — 스킬 **이름을 인자로 넘기지 않는다**: 베인은 UI 용어를 발화하지 않는다(D05 §5.4 용어 이층).
- SI1 면제 = `raceLog.duelLoseWaived01`("충격을 받아냈다") — **패배는 말하고 페널티는 말하지 않는다.** 20차가 못 쓴다고 보고한 3키(`duelLoseDefense01` "피추월" · `defendFail01` "자리를 내줬다" · `duelLoseOvertake01` 감소량)는 그대로 미발행이며 검사가 양방향으로 못박는다(전용 문면 발행 + 대조군 미발행).

**V7 적출 1건도 소멸했다** — 내러티브가 ㉮대로 `did not hold` → `never had` 로 교체했다.

파일은 문자 2,138 · 유일 2,136 이다. GLYPH 는 유일 계수로 세므로 판정에 영향이 없다. **정리하면 파일이 정본 계수와 문자 수까지 일치**하지만, 총괄 조달물이라 손대지 않았다. 정리 여부 판정 요청.

### ② [보고] 표가 빌드에 실린다
`godot/data/reference/jouyou_kanji.txt`(7KB)는 **검증 입력**이지 게임 콘텐츠가 아닌데 `res://` 아래라 익스포트에 포함될 개연이 있다. 검사는 개발 트리에서 도는 것이므로 기능 영향은 없다. 총괄 지정 경로를 따랐고, 익스포트 제외가 옳다고 보면 프리셋 필터 사안이다.

### ③ [보고] 언어 전환 시 화면 재문면화 — 21차 이월 유지
`set_language` 는 표를 갈지만 이미 박힌 `Label.text` 는 그대로다. 화면 층 몫.
