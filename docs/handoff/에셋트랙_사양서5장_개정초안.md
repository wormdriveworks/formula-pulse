## 1. 재해석 — 컷은 "그림"이 아니라 "합성 선언"이다

```
컷 1프레임 =  배경 레이어(기존 10 · 원경/근경)
            + 머신 스프라이트(기존 37 · 공용)
            + 연출 요소 레이어(신규 생성분 — 본 개정의 대상)
            + 합성 선언(앵커·프레임 매핑 — 데이터 · 생성 0)
```

**"58프레임"의 실체가 이 재해석에서 갈린다.** 컷별 프레임 수(4·5·6·8)는 **유지**하되, 그것은 *"RD 가 낼 그림 58장"* 이 아니라 **합성 선언의 프레임 수**다. 새로 생성하는 것은 **연출 요소** 뿐이다.

> **이득이 수량으로 드러난다.** 통짜 전제에서 58프레임은 폭 상한을 넘어 **생성 불가**였다. 합성 전제에서는 **요소 8종**이고, 요소는 24~96px 이라 폭 상한 안에 넉넉히 들어간다. **컷이 넓어서 못 만들던 것이, 넓은 것을 만들지 않기로 하자 만들 수 있게 됐다.**

## 2. §5.1 규격 — 개정 문면 (2행 개정 + 1행 신설)

| 항목 | 값 |
|---|---|
| 구도 | 측면·추격 2시점만. **대치(마주보기) 구도 금지** (ToF ②) · **머신 스프라이트 공용 + 배경 레이어 스왑 + 연출 요소 레이어 합성** (D10 :243). **⟨v1.11 명문⟩ 컷은 단일 생성물이 아니라 합성 결과다** — RD 폭 상한 256 < 원도 408 이고, 배경의 `tile_x` 해법은 **머신이 반복될 수 없어** 컷에 전용되지 않는다. 컷 프레임의 실체 = 배경 2레이어(§5.3 납품분) + 머신 스프라이트(§4 납품분) + **연출 요소 레이어(§5.2.1)** + 합성 선언(§5.2.2) |
| 연출 요소 원도 | **24~96px 정사각 또는 가로형 · 투명 배경 · 순색 60 양자화**(§2 파이프라인 공통). 생성 = `rd_animation__vfx`(효과 전용 계열) 또는 `rd_advanced_animation__*`(시작 프레임 파생). **프레임 간 정합은 문면이 아니라 도구 구조가 준다** — 전자는 효과 전용 학습, 후자는 `require_input_image`. 독립 생성 N장으로 루프를 만들지 않는다(정합 실패 5회 실측 — IMPL-311·314·319·358) |
| 정지 폴백 | 각 컷 대표 1프레임 지정 (O12 — 신규 에셋 0). **⟨v1.11 부기⟩ 합성 전제에서 정지 폴백은 "연출 요소 없음 + 배경 + 머신" 으로 성립하므로 에셋이 아니라 선언이다** |

**씬 컷 공통 토큰 개정** — 현행은 국문 `와이드 레이스 장면, 트랙 측면 시점, 주행 중 머신` / 영문 `wide racing scene, trackside side view, machines at speed`.

> **전문 삭제.** 이 토큰은 **머신과 장면을 RD 에 요구하는 문면**이고, 합성 전제에서는 요구 대상이 아니다. 대체 토큰은 §5.2.1 요소 대장의 공통 토큰으로 이관한다.

## 4. 신설 §5.2.1 — 연출 요소 8종 대장 (생성 대상 전부)

연출 요소 공통 토큰: 국문 `투명 배경 위의 단일 효과, 주변 배경 없음, 사물 없음` / 영문 `single effect on transparent background, no surroundings, no objects`.

> **공통 토큰이 하는 일이 하나다 — 배경과 사물을 부른 명사를 전부 거두는 것.** 배경 회차에서 **도로 명사가 전방 소실점을 끌어왔던 것**(IMPL-376)과 같은 기제다. 요소가 배경을 데려오면 합성 시 그 배경이 무대 배경 위에 겹쳐 두 겹이 된다.

| E-01 | 스피드 라인 | 96×24 | 수평으로 늘어진 속도선 다발, 뒤로 흐르는 궤적 | horizontal speed streaks, trailing motion lines | SC-01·02 |

## 5. 신설 §5.2.2 — 합성 선언 (에셋 0 · 데이터)

| 축 | 규격 |
|---|---|
| 앵커 | 요소 배치 좌표는 **선언값**이며 코드에 대입하지 않는다 — 구현 층 `ANCH` 검사 소관(차단형 · IMPL-237) |
| 프레임 매핑 | **요소 산출 프레임 수와 컷 선언 프레임 수는 다를 수 있다.** 맞춤은 합성 선언의 **hold/skip** 으로 하고 **재생성하지 않는다** — 도구가 내는 프레임 수는 스타일이 정하고(정액 과금이라 프레임을 늘려도 값이 같다) **정본의 컷 프레임 수를 도구에 맞춰 고치는 것은 꼬리가 몸통을 흔드는 일**이다 |
| 레이어 순서 | 배경 원경 → 머신 → 배경 근경 → 연출 요소. **근경이 머신 위**인 것이 §5.1 의 2레이어 분리 목적(*"컷 합성용"*)이다 |
| 봉인 | 릴 정지 연출 완료 전 결과 상관 신호 노출 금지(불변규칙 #5) — **연출 요소는 결과와 상관하므로 합성 시점이 봉인 해제 뒤여야 한다.** 요소 자체는 무해하나 **배치가 결과를 누설할 수 있다** |

## 6. 비용 구조 실측 — 그리고 회당 상한 저촉 보고

| 계열 | 값 | 성격 |
|---|---|---|

| `rd_advanced_animation__*` | **$0.25/호출 정액** | **상한 초과** — 4프레임과 8프레임이 동가 |

**요소 8종 전량 = 8호출 × $0.07 = $0.56** (재시도 여유 포함 약 $0.7). 잔고 $6.413 안에서 여유롭다.

> **⚠ 운용지침 §0-③ 저촉 — 총괄 승인만으로는 집행할 수 없다.** 총괄이 준 파일럿 상한 $0.50 은 **총액 승인**이고, §0-③ 은 **회당 $0.05 초과 시 사용자 직접 확인**을 요구한다. 애니메이션 계열은 **최소 단가가 $0.07 이라 어떤 크기·프레임으로도 상한 아래로 내려가지 않는다.** 따라서 파일럿 1호출($0.07)도 사용자 확인 대상이며, **표정 차분 회차와 같은 경로로 상신했다.** 총괄 승인은 *경로*를 열었고 *지출*은 사용자 소관이다.

## 7. 파일럿 설계 — 1호출 $0.07 로 무엇을 확정하는가

| # | 질문 | 판정 방법 |
|---|---|---|
| ① | **프레임 간 정합이 서는가** (총괄 지정 질문) | 산출 시트의 프레임을 겹쳐 **효과 중심의 이동량**과 **필치 일관성**을 본다. 독립 생성이라면 프레임마다 다른 그림이 나온다 |
| ② | **산출 프레임 수가 몇인가** | vfx 는 `frames_duration` 을 받지 않는다 — 스타일이 정한다. §5.2.2 hold/skip 설계가 필요한지가 여기서 갈린다 |
| ③ | **투명 배경이 실제로 오는가** | 공통 토큰이 배경을 거두는지. 오지 않으면 스크럽이 아니라 **경로 재검**이다(효과에 배경이 붙으면 두 겹이 된다) |
| ④ | **순색 60 양자화를 견디는가** | 효과는 그라데이션 의존이 크다 — 60색 스냅 후 밴딩이 연출을 깨는지. **배경에서 양자화가 이음을 악화시킨 전례**가 있으므로 양자화 **후**로 판정한다 |

파일럿 대상 = **`E-04` 접촉 불꽃 48×32**. 근거: 요소 중 가장 작고 색이 단순해 **④를 가장 혹독하게 받고**(작은 면적 + 주황 단색계), 실패해도 버릴 것이 1호출이다.

> **①에 대한 사전 소견을 적어 둔다 — 이번엔 도구 구조가 우리 편이다.** 이 세션의 RD 실패 4건은 전부 *"문면으로 정합을 요구했다"* 는 한 원인이었고 성공 1건(`tile_x`)은 *"샘플러 파라미터로 요구했다"* 였다. 애니메이션 계열은 **정합이 스타일 자체의 학습 대상**이거나 **입력 이미지에서의 파생**이므로 후자에 속한다. 그러나 **추정은 유효성 검사가 아니다**(2회 실측) — 소견은 소견이고 파일럿이 판정한다.
