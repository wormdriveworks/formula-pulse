## 2. 원격 10차 — 접수·기록

- **7지점 전수 실측·결함 2건**(툴팁 = 제1 후보 적중 ⓐ형 · 모달 = 범위 밖 ⓑ형 발견) — 함정이 **두 갈래**(역산 vs 성장 방향)임을 가른 것, FULL_RECT 무해를 추정이 아니라 실측+구조 논거("오프셋 0이 곧 정답")로 세운 것, 툴팁 교정을 치수 기입이 아니라 **성장 방향 배치**(순서·크기 무의존)로 푼 것 — 기록.
- **M6 — 검사 공회전 자기 적발**(첫 프레임 0크기 항진명제 → 다프레임 전환 + 부모 실크기 전제 단언). M6′·M5에 이은 세 번째 실증 — "0 == 0 통과"는 이 프로젝트 검증 문화의 상시 감시 대상으로 자리 잡았다.
- 모달만 `grow` 한 줄이 빠져 있었다는 진단(같은 작성자가 한 곳은 알고 한 곳은 빠뜨림) — ANCH 신설 근거의 실증.

## 3. 에셋 10차 — 접수 · **총괄 문면 정정 1건**

- **파편 ⓐ 종결**(iso_open 유예 해소 — ISO 축 경고→차단 승격 부수 확인) · ⓑ `#2E6FA8` 6px 소거 집행 확인.
- **총괄 정정:** IMPL-229 §2-1의 *"`#5B646F` 그대로 지웠으면 도상 파손"* 은 **초판 대장이 색 전량 소거를 지시한 것처럼 읽히는 과장이었다.** 에셋 재분해가 맞다 — 초판 주 문면은 2px 성분을 정확히 지목했고, 틀린 것은 괄호(성분3·4를 "시안"으로 못 박아 `#2E6FA8`을 가린 대표색 오기)다. "어느 절이 왜 틀렸는지"까지 가른 재분해 — 기록.
- `attr_hazard_16` 재작화(격자→균열 1개·성분 2) — 재량 사용 적정("격자는 규칙이고 해저드는 파손" — 구성 문제로 원인 규정). 주력 재판독 즉시 가능.

## 4. 판정 2건

### ① `attr_hazard` 잔여 3파편 7px = **ⓘⓘ 전량 소거 채택 (에셋 집행)**

- 이 파일의 역할 = **재파생의 출발점**(렌더 소비부 0). FRG 경고 3건을 남기면 다음 재파생·다음 독자가 같은 판정을 반복한다 — 원도 위생 원칙(IMPL-229 ②)의 일관 적용.
- **현행 아트 방향이 이미 답했다** — 16px 재작화가 "두 조각+균열"로 갔고, ⓘⓘ가 그 결과(성분 2·FRG 0)와 결이 맞는다. ⓘ의 논거(IMPL-182 "낙하점" 도상 인정)는 렌더 소비부 0이 되면서 약해졌다.
- 성분5(2px `#5B646F`)는 초판부터의 파편 지목분 — 함께 닫는다. 시안 렌더 대조상 32px 인상 차이 미미(에셋 실측) 확인.

### ② `set_anchors_preset` 정적 검사(ANCH) = **신설 승인 · 경고형 (원격)**

두 레인이 각각 밟은 함정(저장 표시 · 툴팁/모달)이고 화면이 정상적으로 뜨므로 눈에 늦게 잡힌다 — 기계 감시 가치 성립. 대상 = 코드 생성 Control의 프리셋·성장 방향·오프셋 짝(비-FULL_RECT 프리셋에 명시적 grow 또는 명시적 오프셋 부재 시 경고). **경고형 신설 → 오검출 표본 수집 → 차단형 별도 판정** — FONT·PAL 절차 그대로. UISCR 실측 배치 축과 층 분담(정적 = 새 호출 지점 조기 경보 / 실측 = 실배치 확증).
