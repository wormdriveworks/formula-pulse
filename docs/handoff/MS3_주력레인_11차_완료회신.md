### 1.2 배치 판단 3건

- **ⓐ 대사창 위 4px 띠.** 별첨A §A-19 와이어프레임은 E05 를 대사창 *아래* 한 줄로 그리지만, 현행 대사창은 하단 접지(실측 y292~360)라 그 아래에 자리가 없다. 와이어프레임은 개략도이고 E05 의 규격 문면은 "대괄호·1줄 14자·전이 표시 전무"뿐이므로, **스킵(우상단)과 대사창 어느 쪽도 가리지 않는 유일한 띠**인 그 위를 택했다(임의 해석이 아니라 배치 구속의 유일해).
- **ⓑ 가로 배열(HBox).** 와이어프레임이 E05 를 단일 행으로 묘사하고, 선택지 10문안이 전건 ≤11.67전각이라 3개가 **313px** 로 앉는다(640 폭의 절반). 세로 목록은 스탠딩 영역(§A-19 E02)을 잠식한다.
- **ⓒ 스타일박스 재사용.** 대사창과 같은 `StyleBoxFlat_512q8` 을 공유한다 — **새 색 리터럴 0**이라 PAL 181 무증가.

- 옵션2 선택 → 오버레이 닫힘 → **반응 1라인** `테오 / 저는 그 번호 마음에 들어요.`(= `vn.act1.react2` · `reaction_speaker_key = speakerTheo`) → 합류

**2~4지점은 실플레이 미도달** — 3·4막·에필로그는 마일스톤(투어 우승·로렌츠 격파·시즌 챔피언) + 투어 경계 다수 GP 뒤에 열린다. 네 지점은 **같은 코드 경로·같은 데이터 형상**이고 §1.3 표가 전건을 기계로 덮는다.

### 1.5 발주 질의 응답 — **ⓐ축은 공회전으로 남지 않았다. FAIL 했다.**

노드를 세운 직후 UISCR 을 돌리자 **ⓐ(부재) 3검사가 즉시 FAIL** 했다:

```
[FAIL] 노드 부재 = 지점 생략 관측 — []
[FAIL] 노드 부재 = 진행 잠기지 않음 — 우리는 그중 한 순간만 가져오면 된다.
[FAIL] 선택 지점 자동 도달 — []
```

즉 **회귀가 전환을 감지했다.** 다만 그 상태로 두면 축이 죽으므로 구조를 뒤집었다:

- 종전 = *부재는 실물 / 실재는 스텁 주입*. 실물이 서면 ⓐ가 성립하지 않고, **ⓑ도 실물을 안 본다** — `find_child` 가 트리 순서상 씬 실물을 먼저 집으므로 주입한 스텁은 조회되지 않는다(계약이 이중이 된다).
- 지금 = **부재를 실물 제거로 만든다**(`_mount_vn(with_overlay=false)` 가 씬 노드를 `free()`). 두 축이 모두 **실물 계약**을 본다. 부재 축의 의미는 그대로다: 노드를 지우거나 이름을 바꾼 회차에 화면이 멈추지 않는다.
- 부수로 "선택 지점 자동 도달"의 관측점을 **생략 기록 → 오버레이 실표시**로 교체했다. 생략이 도달의 증거였던 것은 노드 부재 시절의 대용이고, 지금은 생략이 0이어야 한다.

### 1.6 ⑰-ⓓ 배치 축 신설 + 돌연변이 4건

**`visible`·`disabled` 만 보는 스킵 생존 단언은 오버레이가 스킵 위에 겹쳐도 통과한다** — 그래서 실 rect 교집합으로 본다(10차 콜아웃 축과 동형). 정렬이 끝난 프레임에 재는 것도 같은 이유다(내용이 크기를 정하는 PanelContainer 라 지점을 연 프레임에는 0 크기이고, 0 에서는 "안 가린다"가 0==0 으로 성립한다).

| 변이 | 결과 |
|---|---|
| M1 오버레이를 우상단으로 이설 | **2 FAIL**(화면 내 · 가로 중앙) — 단 스킵 겹침은 y 접선이라 0 |
| M1′ 우상단 + `offset_top 12`(실제 겹침) | **1 FAIL — 스킵 겹침 672px²** |
| M2 `ChoiceList` 노드 제거 | **4 FAIL** + 검사 수 하한 미달 |
| M3 초기 `visible = false` 제거 | **6 FAIL** |

M1 이 스킵 축을 못 짚은 것을 보고 M1′ 을 따로 돌렸다 — 겹침 단언이 실제로 무는 것을 확인한 것은 M1′ 이다.

## §2. ② `sys_save_spin` 회전체 소비부 — **회전체 단독으로 대체**

### 2.1 판단 근거

에셋 실측: `sys_save_spin` = **고리 1성분**(지름 20px · 잉크 160 · 알파 형상 **90°·180°·좌우 대칭** 실측 · 어두운 사분면 40px 이 회전 가시성을 만든다). 매니페스트가 **"회전용 변형"** 으로 규정한다.

**정지 표기를 겹쳐 두지 않고 대체한다.** 근거 3:

- **ⓐ 동심 배치가 불가능하다** — 고리 안지름 **14px** 인데 `sys_save` 슬래브 폭은 **16px** 이다(x8~x23). 같은 32×32 안에 동심으로 두면 좌우 각 1~3px 이 호와 충돌하고, 어느 쪽을 줄여 맞추는 것은 비정수 축소라 **믹셀 금지**(D10 §2.2)에 걸린다.
- **ⓑ 나란히 두지 않는다** — 32+32 로 모서리 점유가 배가된다. §181 은 저장 아이콘 **한 자리**를 지정하며, 2초 표시에 640 폭의 10%를 주는 것은 균형이 아니다.
- **ⓒ 정보는 보존된다** — §181 이 규정한 용도는 *"저장 중 종료 경고의 근거"* 이고 그 정보는 "작업이 진행 중"이다. 회전 대칭 고리는 전 각도에서 그것을 왜곡 없이 전한다. 방향성 글리프는 절반의 각도에서 그 정보를 **거짓으로** 전했다(180°에서 화살이 위 = '불러오기').

값은 무변경 — `param_fx_save_hold_sec` 2.0 · `param_fx_save_spin_sec` 1.0, `core_params` 창구 경유 유지(코드 무기입).

### 2.2 회전 감각 (이월 항목 — 필름스트립 판독)

45° 간격 8컷 니어리스트 렌더 판독: **전 각도에서 고리로 읽힌다.** 의미 반전 없음 — 10차에 올린 판정 요청의 원인이 해소됐다.

**관측 1건(비차단):** 45·135·225·315°에서 고리 테두리가 **톱니로 튄다**(3px 환형을 니어리스트로 회전시킨 결과 · 90° 배수는 깨끗하다). 선택지는 ⓐ현행 등속 유지 ⓑ회전을 90° 계단으로 양자화(주기 1.0s → 4스텝/초 · 픽셀아트 관례이고 톱니가 사라진다) ⓒ프레임 세트 사전 렌더. **ⓑ는 등속을 계단으로 바꾸는 연출 변경이라 구현이 정하지 않았다** — 판정 요청 ②.

### 2.3 회귀 3검사

**선언은 결선의 증거가 아니다** — 상수가 아니라 **물린 텍스처의 파일명**과 **알파의 90°·180° 대칭**을 본다. 돌연변이 M4(방향성 글리프 복원) 에서 3검사 전건 검출.

**부수 보고: `sys_save.png` 소비부가 0이 됐다.** 폐기/보류는 에셋 트랙·총괄 몫이다 — 판정 요청 ③.

### 3.2 실기 발견 결함 1건 — 이탈 입력의 null 뷰포트 (교정 완료)

진행 입력을 연속으로 넣어 **마지막 라인을 넘긴 프레임**에 런타임 오류가 났다:

```
Session Runtime Error: Cannot call method 'set_input_as_handled' on a null value.
  0 - res://ui/nar/vn_screen.gd:97 - at function: _unhandled_key_input
```

기제 = `_advance()` 가 마지막 라인에서 `_finish()` → `go()` 로 화면을 이탈시키고, **라우터가 노드를 트리에서 내린 뒤** 같은 함수의 다음 줄이 `get_viewport()` 를 부른다. **교정 = 소비 표시를 진행보다 먼저**(2줄 순서 교환 — 핸들러가 불린 시점의 노드는 트리 안이므로 뷰포트가 반드시 있다).

**헤드리스 단위 검사가 못 잡은 이유가 축이다** — 기존 VN 검사는 `_advance()` 를 **직접 부르므로** 입력 경로를 타지 않고 그 줄에 도달하지 않는다.

**관측점 선정 실패 1건을 기록한다.** 처음에 `root.is_input_handled()` 로 거동 단언을 세웠는데 **항진명제**였다 — 플래그 리셋 창구가 없어 앞선 검사의 `true` 를 물고 있어서, 결함을 되돌린 상태에서도 PASS 했다(실측). 라우팅 여부로도 못 본다(라우팅은 죽는 줄보다 **앞**에서 끝난다). 그래서 **주석을 걷어낸 원문에서 순서를 단언**한다(ANCH·STRF 실재 축과 같은 형태 · 돌연변이 M5 검출).

> 타 레인 파일(`vn_screen.gd`)이지만 **이 회차는 단독 회차**(발주 명문)라 병행 충돌이 없어 직접 교정했다.

### 3.3 미수행 3건

- **2~4막·기원·에필로그 실기** — 마일스톤 + 투어 경계 다수 GP 필요(액션 시뮬레이션으로 1GP 완주에 20+ 왕복).
- **아카이브 화면 실기** — 기록실이 **세이브 없으면 비활성**이다(저장 지점 = RACE-03 진입이라 GP 1회 완주가 선행). 표제 6종은 §3.1 대로 표·문면 층에서 전건 확인했다.
- **BGM-10 실청** — §4.

## §4. ④ 사운드 — 기계 축 종결 · **귀 판정은 사용자 몫**

### 4.1 먼저 명기: 이 세션에는 청각이 없다

발주 ④는 *"헤드리스에서 상태는 전건 검증됐으나 **귀는 여기서만 열린다**"* 로 축을 정확히 지목했다. 그 축은 **모델이 대신할 수 없다.** 따라서 이 회차는 ⓐ기계로 닫히는 것을 닫고 ⓑ**귀로만 닫히는 것을 사용자 청취 대장으로 분리 제출**한다. 청감표를 추정으로 채우지 않았다.

### 4.2 기계 축 — 이미 닫혀 있다 (중복 주행 없음)

원격 17차 `AUDIO_PLAYER_PASS checks=102` 가 다음을 덮는다(본 회차 재확인만): 버스 3계 실재·Master send · 풀 크기 = 가상 채널 상한 · **긴장 레이어 = 데크 불변(교체 아님)** · 덕킹 값 창구 · 볼륨 3축 독립 · **일시정지 = SFX 뮤트 / BGM 비뮤트** · 사용자 뮤트 보존. 에셋 축은 `AUDIO_ASSET_PASS 490` + `AUD 1091`.

값 확인(창구): 크로스페이드 **0.8s** · 덕킹 **-6dB / 복귀 0.3s** · 재트리거 게이트 0.05s · 가상 채널 12 · 기본 볼륨 80.

### 4.3 본 회차가 더한 것 — 징글 파형 객관 계측

기존 AUDIO-A 는 헤더·루프·길이를 본다. **온도차는 파형에 있으므로** 직접 쟀다(16bit PCM · ZCR = 영교차율 ≈ 밝기 대용):

| id | 역할 | 길이 | peak | RMS | ZCR/s |
|---|---|---|---|---|---|
| `jg_01` | GP 결산 **상위** | **0.686s** | **0.596** | **-9.2dB** | **1441** |
| `jg_02` | GP 결산 **하위** | 0.302s | 0.398 | -11.9dB | 946 |
| `jg_03` | 리타이어 | 0.484s | 0.561 | -8.8dB | 980 |
| `jg_04` | 시즌 챔피언 | 0.959s | 0.667 | -8.3dB | 1208 |
| `jg_05` | 타이틀 획득 | 0.349s | 0.562 | -8.8dB | 1789 |

**온도차가 네 축 전건에서 같은 방향으로 존재한다** — 상위가 **길고·크고·밝다**(길이 2.3배 · 피크 1.5배 · +2.7dB · 밝기 +52%). 방향은 객관적으로 확인됐고 **체감 적정성만 귀 몫**이다. 부수: jg_04 가 최장·최대(챔피언), jg_05 가 최고 밝기(타이틀).

### 4.5 일시정지 SFX 뮤트 — 원격 관측에 대한 화면 층 소견

기제는 확인했다: 일시정지 = **SFX 버스 뮤트**이므로 일시정지 메뉴 자신의 조작음도 그 버스를 타서 함께 꺼진다. D11 §4.3 문면("BGM 유지·SFX 뮤트")의 그대로의 귀결이다.

화면 층 소견 = **정보 손실은 없다.** 실기 캡처로 확인했듯 일시정지 메뉴는 포커스 링·강조로 시각 피드백을 온전히 준다(재개/옵션/업적/타이틀로 4항). 즉 "조작이 먹었는지"를 귀에 의존하지 않는다. 다만 **레트로 관례상 메뉴가 무음인 것이 고장으로 읽힐 여지**는 남고 그것은 귀 판정이다 — 청취 대장 9번. 정본 접촉 사안이므로 이상하다는 판정이 나오면 판정 요청으로 올린다.

### 4.6 품질 소견 (비차단 대장)

- **징글 5식 전건 피크 0.398~0.667** — 클리핑 여유 충분(0dBFS 미달). 최소 `jg_02` 가 0.398 로 다른 4식보다 낮아, 하위 결산이 **작게** 들릴 여지가 있다(의도된 온도차인지 레벨 미조정인지는 귀 몫).
- BGM 18스템 길이·루프는 AUD·AUDIO-A 가 이미 90~150초·루프 6식 목록으로 강제하고 있어 별도 소견 없음.

## §5. 도구 한계 · 미수행 명기

1. **청각 부재** — ④의 귀 축 전건(§4.4 9문항). 대체 불가.
2. **1GP 완주 실기 불가(비용)** — 액션 시뮬레이션이 `InputEventAction` 전속이라 홀드 조작을 못 만들고(10차 §6-1 이월분), 턴당 2~3 왕복이라 1GP 에 20+ 왕복이 든다. 그래서 RACE-03·투어 경계 뒤의 축(아카이브 화면·2~4막 실기·저장 표시 실기)이 전부 그 벽 뒤에 있다.
3. **GDAI 런타임 채널이 1회 먹통** — 진행 입력 7연타 후 스크린샷·입력이 모두 타임아웃(§3.2 의 런타임 오류와 같은 구간). 게임 재시작으로 복구. **왕복당 1입력 + 대기 300ms 이상**이 안전선이다.
4. **세이브 백업** — 실기용으로 `user://profile_*` 를 비웠다. 원본은 `user://_bak11/` 에 보존(리포 무관·로컬 전속).
