## 1. ① `sys_save_spin` — 설계 원리는 "실루엣 대칭 + 음영 비대칭"

### 왜 고리만으로는 안 되는가

주력 10차 §5 의 판독은 정확했습니다 — `sys_save` 는 **방향성 글리프**라 180° 에서 하향 화살이 상향이 되어 **'불러오기'로 뜻이 뒤집힙니다.** 지속 2.0s ÷ 주기 1.0s = **정확히 2회전**이라 반전 상태를 두 번 통과합니다.

그런데 고리로 바꾸는 것만으로는 끝나지 않습니다. **완전 회전 대칭이면 회전이 보이지 않습니다.** 판정의 요구는 *"의미 반전 없음"* 이고 연출의 요구는 *"회전이 보임"* 인데, 둘을 함께 만족시키는 것은 **실루엣을 대칭으로 두고 음영을 비대칭으로 두는 것**뿐입니다.

| 항목 | 값 |
|---|---|
| 형태 | 고리 + 어두운 1/4 호(12시~3시 사분면 — 정지 상태에서 '올라오는' 쪽) |
| 산술 | 중심 **16.0** · 외경 10.5 · 내경 7.5 · 두께 3px |
| 크기 · 잉크 | 20×20 (origin [6,6]) · **160px** — `sys_` 계열(132~352) 중앙값 근처 |
| 색 | `#3FE0F5` 120 + `#12A6C4` 40 = **3.00:1** |
| 성분 | **1개** (회전용이라 갈리면 각 성분이 따로 도는 것처럼 보인다) |
| 대칭 | **90° · 180° · 좌우 반전 전건 픽셀 단위 불변** (기계 대조) |

**초판 자기 교정 1건** — 중심을 15.5 로 잡아 **반 픽셀 어긋나 대칭이 깨졌습니다**(90° 불변 False). 32px 그리드의 기하 중심은 픽셀 중심이 `x+0.5` 이므로 **16.0** 입니다. 대칭을 눈으로 보지 않고 회전 대조로 검사해서 잡혔습니다.

### 색 비를 `sys_save` 에 맞춘 이유 — 통상 스피너와 반대로 했습니다

통상 스피너는 **어두운 고리에 밝은 표식**을 둡니다(움직임이 강하게 보입니다). 반대로 **밝은 고리 3/4 + 어두운 호 1/4** 로 했고, 색 비 **3.00:1** 은 `sys_save` 의 99:33 과 **같은 값**입니다.

근거는 저장 표시의 성격입니다 — **D11 규칙 U-a 가 이 표기를 무음으로 둘 정도로 조용한 표기**입니다(빈발 이벤트의 소음화 방지, 시각 전속). 밝은 표식을 얹어 밝기 총량을 늘리면 그 의도와 어긋납니다. 움직임은 보이되 눈을 끌지는 않는 쪽을 골랐습니다.

### 에셋 ID 를 신설하지 않았습니다

**A-UI-18 의 두 표기**입니다 — 16px 세트가 `_16` 을 붙인 것과 같은 규격입니다(*"같은 도상의 다른 치수이지 별개 에셋 ID 가 아니다"* — §4.1.1). D10 §8.1 은 정본이고 **구현이 에셋 ID 를 만들 자리가 아닙니다.**

`sys_save` 는 **무접촉**입니다(바이트·`.import` 불변). 손 작화(`icon_art.json`)이며 `icon_draw.js --check` 가 정의⇔PNG 를 대조합니다 — **RD 로는 만들 수 없습니다**(정확한 회전 대칭은 확산 모델의 산출이 아닙니다 · IMPL-215·224 실측 계열). 임포트 설정은 기존 아이콘과 **행 단위로 대조**해 동일 확인했습니다.

> **소비부 결선은 이 파일의 몫이 아닙니다.** 회전체를 `sys_save` 에서 이 파일로 갈아 끼우는 것도, 정지 표기와 회전체를 분리할지 회전체만 둘지도 화면 층(주력) 판단입니다.

## 2. ② `deadParams` 차단형 전환

`warn` → `fail`. 조건 ⓐⓑ 를 **대장 §7 함정 주석 계열에 전사**했습니다(임포트 캐시 함정과 같은 자리 — 절차를 읽는 사람이 함께 보게).

| 돌연변이 | 결과 |
|---|---|
| `se_r04` 를 초판 0.62(미발화)로 복원 | `✗ 아르페지오 미발화 (발화 2920샘플 >= 길이 2810샘플)` · **exit 1** |
| `se_u05` 에 비브라토 강도만 선언(속도 0) | `✗ 비브라토 미발화 (p_vib_speed 0)` · **exit 1** |
| 원복 후 | `SFX_GEN PASS sounds=68` · **exit 0** |

전사한 조건:

- **ⓐ 차단 대상이 빌드가 아니라 생성이다.** 다른 차단형 7종(MIX0·ARCH·FONT·PAL·ANCH·STRF·AUD)은 검증기에 있어 빌드 앞에 서지만, 이것은 **생성기**에 있어 미발화 1건으로 **전량 생성이 멈춥니다.** 성격이 갈리므로 열거를 같이 하지 않았습니다. 부분 주행 = `--only=<id>`.
- **ⓑ 발화 시점 공식은 `vendor/sfxr.js` 산술의 복제다.** 벤더 갱신 시 어긋나면 **정상 파라미터가 생성을 막습니다.** **벤더를 갱신하는 회차는 공식을 상류와 재대조하고 결과를 회신에 적는다** — 절차로 못 박았습니다.
- **확장 5축 불채택**도 근거(68식 전수 0건)와 함께 기록했습니다.

## 5. 게이트 부기 — 공유 트리가 현재 타 레인 작업 중입니다

작업 트리에 **타 레인의 미커밋 변경**이 들어 있어 공유 게이트가 본 회차와 무관하게 흔들립니다. 관측 순서대로 적습니다.

| 시점 | 공유 게이트 | 원인 (전건 타 레인분) |
|---|---|---|
| 집행 중 | `VALIDATORS_PASS **warnings=20**` | 미커밋 `strings.csv` +20키의 V6 고아 경고 — `vn.*.react` 10 + `vnChoice.*.opt` 10 = **정확히 20** (소비부 미결선) |
| 회신 작성 중 | `VALIDATORS_**FAIL** failures=2` | `godot/ui/nar/vn_screen.gd:183·188` 의 **ARCH 차단** — `push_warning(` 2건. 선택지 소비부를 지금 결선하는 중으로 보입니다 |

**그래서 격리 검증을 했습니다.** `HEAD` 로 임시 워크트리를 만들고 **본 회차 산출만 얹어** 주행했습니다:

```
VALIDATORS_PASS warnings=0        (AUD audio assets: PASS 821 checks)
ICON_CHECK PASS checks=8353 fails=0 warnings=0
ICON_DRAW PASS icons=18
SFX_GEN PASS sounds=68
```

**본 회차 산출은 경고·실패 0 입니다.** 본 트리의 마지막 전량 스위트는 `COMPILE_GATE_PASS scripts=91` · `AUDIO_ASSET_PASS checks=350` · `TESTS_PASS suites=15`(ARCH 차단 발생 전 시점)였습니다.

**타 레인 파일은 건드리지 않았고 스테이징에도 넣지 않았습니다**(`strings.csv`·`config.json`·`vn_screen.gd`·`game_data.gd`·`test_ui_screens.gd`·신규 표 2). **ARCH 차단 2건은 그쪽이 자기 게이트를 돌리면 즉시 보이는 자리**이므로 사실만 적어 두고 손대지 않았습니다 — 남의 미커밋 변경을 고치는 것은 규약이 금하는 쪽입니다.
