## 1. ① `speaker_key → char_id` — 9키 전건

대장 **§3 경로 유도 규칙** = `res://assets/characters/{char_id}_base.png` · 표정 차분 = `{char_id}_face_{expr}.png`. `char_id`는 신설 식별자가 아니라 `crew.csv`·`ai_rivals.csv`의 `id` 열입니다(같은 절 명문 — *"`char_id`·`machine_id`·`stage_id`는 전부 실존 데이터 id다"*).

| speaker_key | char_id | 실물 | 접두 근거 | VN 등장 |
|---|---|---|---|---|
| `ui.vn.speakerMarta` | `crew_marta` | base + positive/negative | `crew.csv` id | **17장면 = 전건** |
| `ui.vn.speakerTheo` | `crew_theo` | base + positive/negative | `crew.csv` id | **16장면** |
| `ui.vn.speakerSasha` | `crew_sasha` | base + **4종**(confident/shaken/anger/special) | `crew.csv` id | 2장면 |
| `ui.vn.speakerOscar` | `crew_oscar` | base + positive/negative | `crew.csv` id | 1장면 |
| `ui.vn.speakerNadia` | `crew_nadia` | base + positive/negative | `crew.csv` id | 1장면 |
| `ui.vn.speakerLorentz` | `ai_lorentz` | base + **4종** | `ai_rivals.csv` id | **0** |
| `ui.vn.speakerMaro` | `ai_maro` | base + positive/negative | `ai_rivals.csv` id | **0** |
| `ui.vn.speakerVane` | **없음** | — | — | 9장면 (§5.1) |
| `ui.vn.speakerNarration` | **없음** | — | — | 17장면 전건 |

**접두는 추측할 수 없고 표가 답을 갖고 있었습니다.** 사샤·오스카·나디아가 `crew_`인 것은 셋 다 `crew.csv`에 행이 있기 때문이고(합류 대상이므로), 로렌츠·마로가 `ai_`인 것은 `ai_rivals.csv`에 있기 때문입니다. **사샤는 두 성격을 겸합니다** — `crew.csv`의 크루이면서 표정 차분은 네임드 4종 세트를 가집니다(대장 **§4.4** 주요 4인). 그래서 `crew_sasha`가 맞고 `ai_sasha`는 존재하지 않습니다.

**로렌츠·마로는 VN 등장 0입니다.** 두 키가 쓰이는 곳은 `vn.clueAxion.*` 2행뿐이고, 그것은 총괄 판정으로 **VN이 아니라 발견 대장·로그 존 문면**이 됐습니다. 그래도 대응을 선언하는 이유는 §2.3입니다.

### 1.1 스탠딩 없음 2키 — **행을 세워 선언합니다**

`speakerNarration`(값 3언어 공란 = 지문)과 `speakerVane`은 `char_id`가 없습니다. **그 부재를 표에 행으로 세우기를 권고합니다** — `char_id` 공란 + `side = none`.

행 없이 두면 *"표에 없어서 안 선다"*와 *"없기로 정해서 안 선다"*가 소비부에서 같은 그림이 됩니다. 이 리포지토리가 반복해서 배운 형태입니다 — *"침묵은 판정이 아니라 누락이 된다"*(원격 26차) · *"표에 행이 서면 자연 소비"*(주력 15차). 조회 실패와 선언된 부재를 갈라 두면 **신규 화자가 유입될 때 행 누락이 검사로 잡힙니다.**

## 2. ② `side` 규칙 — **화자 고정 + 최근 발화자 점유**

### 2.1 데이터가 먼저 답을 좁혔다

17장면의 화자 등장 순서를 전수로 뽑았습니다. 지문·베인(스탠딩 없음)을 제외한 실 스탠딩 인물 수는 이렇습니다.

| 스탠딩 인물 | 장면 | 구성 |
|---|---|---|
| **2인** | 14장면 | **마르타 + 테오** 13 · 마르타 + 사샤 1 |
| **3인** | **3장면** | `crew_nadia`(나디아·마르타·테오) · `crew_oscar`(오스카·마르타·테오) · `clue_silence`(테오·사샤·마르타) |

**마르타는 17/17 — 전 장면에 있습니다.** 테오가 16/17(빠지는 곳은 `crew_sasha` 하나)이고, 변하는 것은 **손님 한 명**(사샤·오스카·나디아)입니다. 베인은 9/17이나 스탠딩이 없습니다.

### 2.2 세 후보와 기각 근거

| 안 | 내용 | 판정 |
|---|---|---|
| **A 화자 고정** | 인물별 `side` 열 1개 | **권고** |
| B 장면별 배정 | 장면×인물 행(~40행) | 기각 — 같은 말을 17번 반복하고, **비트가 늘 때마다 표를 손대야 하며 잊으면 스탠딩이 안 선다.** A는 인물이 늘 때만 손댄다 |
| C 등장 순서 구동 | 첫 발화자 = 좌, 둘째 = 우 | **기각 — 데이터가 직접 반증한다** |

**C를 기각한 것은 취향이 아닙니다.** 막 VN의 첫 발화자가 교대로 갈립니다 — 1막·3막·기원은 **마르타**가 먼저, 2막·4막·에필로그는 **테오**가 먼저입니다. C를 쓰면 **마르타가 막마다 좌우를 옮겨 다닙니다.** 상주 인물이 자리를 바꾸면 플레이어가 화면을 읽는 기준이 사라집니다.

### 2.3 배정

| speaker_key | `side` | 근거 |
|---|---|---|
| `ui.vn.speakerMarta` | **left** | §2.4 |
| `ui.vn.speakerTheo` | **right** | 마르타의 상시 대화 상대 |
| `ui.vn.speakerSasha` | **right** | 손님 — 마주 서는 쪽 |
| `ui.vn.speakerOscar` | **right** | 〃 |
| `ui.vn.speakerNadia` | **right** | 〃 |
| `ui.vn.speakerLorentz` | **right** | VN 등장 0 — **선언만.** 유입되면 라이벌은 팀과 마주 선다 |
| `ui.vn.speakerMaro` | **right** | 〃 |
| `ui.vn.speakerVane` | **none** | 스탠딩 없음 (§5.1) |
| `ui.vn.speakerNarration` | **none** | 지문 — 화자 표기 자체가 공란 |

### 2.4 마르타 = 좌 고정의 근거 셋

1. **전 장면에 있는 유일한 인물이다** (17/17 — 테오도 `crew_sasha`에서 빠진다). 고정석은 예외 없이 서는 인물이 가져야 기준이 된다.
2. **손님 3인의 대화 상대가 전부 마르타다.** 오스카의 *"누구냐"*에 답하는 쪽, 나디아의 협상 상대(*"우리 예산으로는 당신을 못 쓴다"*), 사샤의 복귀를 받는 쪽(*"자리는 비어 있었다. 늘."*)이 모두 마르타다. **축이 한자리에 있으면 손님이 마주 선다.**
3. **D04 §5.6-6의 어조 고정과 같은 방향이다** — 마르타 = 간결한 지시. 판단하는 쪽이 움직이지 않는 것이 그 어조의 화면 대응이다.

### 2.5 우측 경합 — **최근 발화자가 쥔다**

§2.3대로 두면 **우측 경합이 정확히 §2.1의 3장면에서만** 발생합니다(테오 vs 손님). 남은 14장면은 경합 0입니다.

**해결 = 각 자리에 배정된 인물 중 가장 최근에 말한 쪽이 그 자리를 쥔다.** 슬롯이 2개이므로 이 규칙은 §A-19의 최대 2인을 **구조적으로** 지킵니다 — 넘길 방법이 없습니다.

`clue_silence`로 검산합니다.

| 행 | 화자 | 좌 | 우 |
|---|---|---|---|
| 1 | 지문 | 마르타 | — |
| 2 | 테오 | 마르타 | **테오** |
| 3 | 사샤 | 마르타 | **사샤** |
| 4 | 지문 | 마르타 | 사샤 |
| 5 | 마르타 | 마르타 | 사샤 |

좌는 장면 내내 마르타, 우는 테오→사샤. 동시 2인을 넘지 않습니다.

> **부수: 좌측을 첫 프레임부터 세우는가.** 위 표는 마르타가 1행(지문)부터 서 있다고 가정했습니다 — 대안은 "말할 때 선다"입니다. **전자를 권고합니다**: 마르타는 전 장면 상주이므로 지문 구간에 좌측이 비면 화면이 한 박자 늦게 채워지고, 특히 `season_open`·`season_close`처럼 짧은 3라인 장면에서는 그 한 박자가 장면의 1/3입니다. 다만 이건 연출 판단이라 소견으로만 올립니다.

## 3. 표정 차분 — **base 전용으로 시작** (데이터 실태 기준 소견)

### 3.1 고를 데이터가 없다

| 원천 | 표정 열 |
|---|---|
| `vn_beat_lines.csv` | `id, beat_id, line_order, speaker_key, text_key` — **없음** |
| `act_vn.json` lines | `speaker_key, text_key` — **없음** |
| `vn_beats.csv` `tone` | 있으나 **전 비트 `calm`** |

`tone`으로 유도하면 전건 base로 떨어지므로 **열을 안 만든 것과 결과가 같습니다.** 라인별 표정을 넣으려면 ~170개 값을 새로 선언해야 하고, 그건 문면이 아니라 연출 선언이라 현 발주 범위 밖입니다.

### 3.2 반만 쓰면 위계가 거짓이 된다

실물은 **사샤만 4종**(confident/shaken/anger/special)이고 VN에 서는 나머지 4인은 positive/negative 2종입니다(대장 **§4.4** — 주요 4인 4×5 vs 그 외 9인 9×3 = 47 검산분). 일부 라인에만 표정을 넣으면 화면에 **"표정이 바뀌는 인물"과 "안 바뀌는 인물"**이 생기는데, 그 구분의 원인은 인물이 아니라 **차분 수량**입니다. 데이터 사정이 인물 성격으로 읽히면 그건 잘못된 정보입니다.

### 3.3 다만 예외 후보 1개소 — 사샤 `_face_special`

대장 **§4.4**가 그 차분의 내용을 **"해빙"**으로 못박아 두었고, A-CG-05 사양이 같은 장면을 **"풀린 표정"**으로 씁니다. **둘이 같은 순간을 가리키고, 그 순간은 정확히 `vnbeat_crew_sasha`(복귀)입니다.**

즉 **이 차분은 그 장면을 위해 그려진 것**입니다. base로 두면 대장이 스스로 쓸 자리를 적어 둔 유일한 차분이 소비 0으로 남습니다.

데이터 없이도 성립합니다 — 비트 id 1개소 대응(`vnbeat_crew_sasha` + `ui.vn.speakerSasha` → `crew_sasha_face_special`). **다만 연출 판단이라 §4에 판정 요청으로 올립니다.**

## 5. 관측 2건

### 5.1 베인 — 스탠딩이 없는 것이 정상이고, 그 자리는 파형이다 (미결선)

`godot/assets/vane/`는 **비어 있습니다**(`.gitkeep`만). 누락이 아닙니다 — **D10 §3.3이 베인을 파형 아바타로 확정**했습니다(상태 4종·파라미터 구동 런타임 렌더·단계별 신규 에셋 0). 그래서 `char_id`가 없는 것이 맞습니다.

**그런데 D10 §8.3이 NAR-01~02 소요 에셋에 '베인 파형'을 명기하고 공백을 0으로 적어 두었습니다.** 그리고 베인은 **9장면에서 말합니다**(막 VN 6 + 성취 3). 현행 `vane_waveform.gd`의 소비부는 `race_screen.tscn` 하나뿐이고 **`vn_screen`에는 파형 노드가 없습니다.**

**바탕과 같은 형태의 공백입니다** — 표는 있고 소비부가 0. 다만 이건 스탠딩 사안이 아니라 별 축이고(파형은 E02 '스탠딩'이 아닙니다), **VN에서 파형을 어디에 어떻게 세우는지는 어느 정본에도 없습니다.** 발주·판정 사안으로 올립니다.

> 부수: **중계 화자는 애초에 대상이 아닙니다** — D04 R12·D10 §3.4가 *"중계 화자 = 스탠딩 아트 대상 아님(텍스트 전용·아트 부재)"*을 구속 명문으로 둡니다. `ui.race.speakerRelay`는 레이스 로그 화자이고 VN 화자 키가 아니므로 이 표에 들어오지 않습니다. 들어오면 R12 위반입니다.

### 5.2 스탠딩 퇴장이 표현되지 않는다

`clue_silence` 4행이 *"그대로 자리를 뜬다"*입니다 — **사샤가 나갑니다.** 그런데 §2.5 규칙으로는 사샤가 5행까지 우측에 남아 있습니다.

라인별 등·퇴장을 표현하려면 라인 단위 스탠딩 데이터가 필요하고, 그건 §3.1과 같은 크기의 신설입니다. **현 규칙의 정밀도 한계로 등재하고 넘깁니다** — 17장면 중 명시적 퇴장 지문은 이 1건뿐이라 지금 값을 치를 자리는 아니라고 봅니다. 표현이 필요해지면 그때 라인 열 신설이 맞습니다.
