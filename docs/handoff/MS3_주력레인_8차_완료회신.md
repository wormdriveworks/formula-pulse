## 1. 작업 ① — PAL 0 도달 (원격 flip 트리거)

```
PAL color literal ledger: PASS (181 checks)
VALIDATORS_PASS warnings=0
```

경고형 신설(IMPL-176 ⑤) 이래 **처음 0**이다. 즉시 단독 커밋·푸시했다(`5fc201e`) — 원격이 flip 하려면 이 상태가 원격에 보여야 하므로 결선분과 묶지 않았다.

| # | 씬 | 리터럴 → 슬롯 | 대비 |
|---|---|---|---|
| ④ | `gp_result_screen.tscn:49` `RetireBadge` | `#F24D4D` → 위험 `#FF4A3D` | 4.91 → 5.20 |
| ⑤ | `run_recap_screen.tscn:61` `CreditsValue` | `#F2D973` → A2 `#D98A12` | 12.34 → 6.27 |
| ⑥ | `event_node_screen.tscn:76` `RewardValue` | `#F2D973` → **N16 `#C7D0D8`** | 12.34 → 11.09 |

**파일 단위로 치환했다.** ⑤와 ⑥은 같은 리터럴인데 슬롯이 갈린다 — 리터럴 일괄 치환은 여기서 틀린다. 7차의 속성명 분기(M2/M3·C2/C3)와 같은 함정이 **파일 축으로 한 번 더** 나온 것이고, 증보 4 ⑥의 정정이 정확히 그 지점이었다.

| 로그 피드 화자 표지 | `MARK_SLOT` 32→16 · 도상 표 2종 `_16` |

**씬 선언을 함께 올렸다(14→16).** 14 로 두면 텍스처 최소치(16)가 이겨 화면에는 16 이 뜨는데 **선언만 14 로 남는다** — 대장 §9-⑱ 이 `E02SectorAttr` 에서 지적한 "선언과 실물이 어긋난 자리"를 새로 만드는 셈이다. 17곳이 전부 재화·보상 아이콘임을 전수 확인한 뒤 바꿨다(부수 피해 0).

**실측 검산 — 등배 성립:**

```

%DataIcon    box=(16,16) tex=(16,16) scale=1.0000  currency_data_16.png
MARK         box=(16,16) tex=(16,16)               speaker_relay_16.png
```

**7차 §6-③ 밀도 저하 = 해소 확인.** SYS-04 커리어 탭이 **6.5행 + 스크롤 → 10행 무스크롤**이 됐고, 로그 피드 4슬롯이 9px 2줄 높이와 균형을 되찾았다. 축소가 아니라 **원도 교체**라 믹셀도 없다.

## 3. 작업 ③ — 활성 탭 표시 [가안] 신설

D09 는 활성 탭의 시각 표시에 침묵한다(§1.3 은 입력만, §A-3·§A-4 는 탭 구성만) → [가안].

| 축 | 결정 |
|---|---|
| 색 | 활성 = `ACCENT_ACTIVE` **C3**(정본 증보 2 의 '활성 강조' 역할) · 비활성 = `TEXT_PRIMARY` **N16**. 신규 색 0 |
| 감광 안 함 | **탭 5종이 전부 도달 가능**하므로 비활성을 흐리게 두면 잠긴 것으로 오독된다. 활성은 밝기가 아니라 **색상**으로 갈린다 |
| 3상태 고정 | `font_color`·`hover`·`focus` 를 같은 값으로 박았다 — 포커스가 옮겨 가도 활성 표시가 유지돼야 한다 |
| 적용 | SYS-03·SYS-04 공통 (`_mark_active_tab()`) |

**실기 확인:** LB/RB 로 돌리면 **포커스 링은 커리어에 남고 활성 표시만 라이벌로 이동**한다. 포커스("무엇을 조작하려는가")와 활성("무엇을 보고 있는가")이 갈려 표시된다 — 7차 §6-① 이 지적한 "LB/RB 가 먹지 않는 것처럼 보인다"가 닫혔다.

## 4. 작업 ④ — 저장 표시 UI: **구조 완료 · 값 부재로 잠들어 있다**

구조는 전부 세웠다.

| 축 | 결정 |
|---|---|
| 소유 | **라우터가 든다**(`app_root`). 화면마다 두면 저장이 화면 전환과 겹치는 회차에 표시가 함께 사라진다 — `_show()` 는 `_current` 만 갈아치우므로 이 노드는 남는다 |
| 관측 | `RunSession.progress_saved` **신설**. `SaveManager` 는 static 이라 시그널 자리가 없고, 코어에 신설하면 표시 층 사정이 코어로 올라간다(혼입 0). 저장 요청이 세션 하나뿐이라 여기가 유일 관문이다 |
| 실패 처리 | **실패 저장에는 띄우지 않는다** — §181 용도가 *"저장 중 종료 경고의 근거 표시"* 라 저장이 안 된 회차에 회전을 보이면 근거가 거짓이 된다 |
| 감쇠 | 회전은 감쇠 옵션 대상이 아니다 — 정보 채널 보존(D09 §6.3) |

### ⚠ 판정 요청 — D13 에 표시 시간·회전 주기 행이 없다

D09 §181 은 *"회전 애니메이션 (2초 내외 — **확정 기준값**)"* 이라고 쓴다. 그런데 **D13 확정 기준값 대장에 해당 행이 0 이다** — `param_fx_*_sec` 계열(`param_fx_shake_sec`·`param_fx_flash_sec`·`param_fx_gauge_pulse_sec`·`param_fx_duel_result_hold_sec`)이 서 있는데 저장 표시 행만 없다.

**호출을 넣을 수 없다.** `GameData.param()` 은 없는 키에서 `_load_ok` 를 내리고(`game_data.gd:161`), `app_root` 상단 가드가 그것을 보고 **부팅을 거부한다.** 즉 없는 param 을 부르는 순간 앱이 뜨지 않는다.

그래서 `configure()` 를 부르지 않았고, 표시는 구성 전까지 잠들어 있다(호출 시 **1회만** 보고 — 저장은 회차마다 일어나므로 매번 짖으면 로그가 묻힌다). **행 2개가 서면 `app_root.gd` 의 주석에 적어 둔 한 줄이 살아난다:**

```gdscript
_save_indicator.configure(data.param("<표시 시간>"), data.param("<회전 주기>"))
```

이름을 제가 정하지 않은 것이 의도다 — 값과 키 이름 모두 D13 창구 소관이다(불변규칙 2).

## 5. 작업 ⑤ — 재판독·눈 대조

### ① `achv_rival` 재작업 — **확인 완료**

| 항목 | 7차 | 8차 |
|---|---|---|
| bbox | 28×11 (납작) | **26×19** |
| 잉크 | 196 | **394** |
| 우측 파편 | (31,15)-(31,17) 3px | **없음** — bbox 가 x=28 에서 끝난다 |

사양(26×19·마주 보는 측면)대로다. **16px 판이 특히 좋다** — 시안·오렌지 헬멧이 서로 마주 보아 "대결"이 7차의 나란한 배치보다 훨씬 빨리 읽힌다. 7차 §3-① 의 납작 유보분·파편 건 **둘 다 종결**.

### ② 16px 10종 판독 — 8종 양호 · **추인 1건 승인 · 1건 반대**

실배치(SYS-04·로그 피드)와 ×3 등배 대조 시트 양쪽에서 봤다.

**추인 ⓐ `speaker_filler_16` 시점 변경(측면→정면) = 승인 권고.**
판별 목적이 실제로 달성된다. `achv_rival_16`(마주 보는 측면 헬멧 2개·시안+오렌지)과 **시점·수량·색 3중으로 갈린다** — 축약 규격을 어긴 대가가 값을 한다. 다만 정면 헬멧이 16px 에서 "어두운 덩어리 + 가로 슬롯"으로 단순해져 같은 피드의 마이크(매우 명확)보다 약하다. **발화원이 부재해 실배치 판정은 아직 불가**하므로 그 시점에 재확인이 필요하다.

**추인 ⓑ `achv_garage_16` 요소 삭감 = 반대 권고 (재작업 요청).**
보고문은 *"렌치+리프트 2요소 → 렌치 1요소"* 라고 적었으나 **실물은 그렇지 않다.** 32px 판이 이미 렌치 2개 교차이고, 16px 는 그 **교차 형태만 남기고 공구 머리를 잃었다** — 결과가 "공구"가 아니라 **얇은 X 표시**로 읽힌다. 같은 행의 `achv_driving_16`(스티어링 휠 = 원+십자, 명확)과 나란히 두면 차이가 확연하다.

- 제안: 보고문이 말한 대로 **렌치 1개를 크게**(대각선 1개 + 머리 형태 보존). 지금은 2개를 유지한 채 축소해 둘 다 뭉갠 상태다.

**나머지 8종 = 이상 없음.** 특히 재화 2종은 **크레딧 = 원형 금색 / 데이터 = 사각 시안**으로 D10 §5.2 의 *"실루엣이 1차 구분"* 이 16px 에서도 유지된다. `achv_career_16`·`achv_archive_16` 은 32px 판보다 오히려 정보가 늘어 읽기 쉽다.

### ③ Zone A 속성 크기 — **16px 발주 권고 · 근거 확정** (대장 §9-⑱ 요청분)

**실측했다.** 화면을 실제 트리에 세워 레이아웃을 돌린 결과:

```
ZONE_A size=(161, 30)
ATTR  box=(16,16) tex=(32,32) stretch=KEEP_ASPECT_CENTERED  →  ATTR_RENDER_SCALE=0.5000 (표시 16.0 논리px)
REEL  box=(32,32)             stretch=KEEP_CENTERED         →  등배 (표시 32 논리px)
```

**§9-⑱ 의 전제가 뒤집힌다 — 위계는 이미 갈려 있다.**

- 우려였던 *"속성만 16 으로 내리면 릴 32 와 크기 위계가 갈린다"* 는 **이미 그 상태다.** 속성은 **지금도 16 논리px 로 표시**된다(32px 원도를 정확히 1/2 축소). 16px 원도를 넣어도 **표시 크기는 바뀌지 않는다.**
- 바뀌는 것은 **그 16px 안에 든 픽셀이 작화된 것이냐 버려진 것이냐**다. 현재는 2:1 니어리스트 축소라 **원도의 절반(모든 홀수 행·열)이 버려진다.**
- 그래서 판단 축은 위계가 아니라 **정보 손실**이다. 릴 심볼은 프레임(64×62)이 32 를 받치지만 A존 속성은 받칠 프레임 없이 16 으로 눌려 있고, 그 16 이 작화되지 않았다.

> **부수 — 7차 파편 판정의 원인이 여기 있었을 수 있다.** 7차에서 `attr_hazard` (17,20)-(18,20)·`attr_sweeper` (26,10)-(27,10) 을 *"안 보인다"* 로 판정했는데, **2:1 축소는 홀수 좌표를 버린다.** 즉 그 판정은 "작아서 안 보인다"가 아니라 **"축소가 지웠다"** 였을 가능성이 있다. 16px 원도가 들어오면 같은 판정을 다시 해야 한다.

### ④ `CreditsValue` 12.34 → 6.27 — **눈 대조 미수행 (도달 불가)**

`run_recap_screen`(RUN-01)은 **투어 경계에서만** 열린다. 이번 회차의 세이브 상태로는 도달하지 못했고(무커리어에서 시작), 투어 1회 완주는 이 회차 예산 밖이었다.

산술만 올린다: **6.27:1 은 §9.2.1 이 본문 부텍스트로 확정한 `TEXT_DIM` 5.64:1 보다 높다.** 즉 이미 승인된 9px 텍스트 기준선 위에 있다. 다만 **색상이 앰버로 바뀌는 건**이라 명도만으로는 닫히지 않으므로 판정으로 대신하지 않고 **미수행으로 명기**한다 — 투어 경계 세이브가 생기는 회차에 우선 확인 항목으로 올려 둔다.

## 6. 부수 발견 1건

### 에디터가 `race_screen.tscn` 을 재정규화한다 — 이번 회차 diff 에서 걷어냈다

`race_screen.tscn` 을 에디터로 열고 실행하면 에디터가 파일을 다시 쓴다: `ext_resource` 에 `uid=` 추가 · 속성 줄 순서 변경(`font_size` ↔ `font_color`) · `layout_mode = 0` → `anchors_preset = 0`. **약 40행 규모**이며 내용 변경은 아니다.

CLAUDE.md 가 경고한 *"에디터가 열면 재정규화되어 디프가 튄다"* 의 실물이고, 8차 작업과 무관하므로 **커밋에서 제외(HEAD 복원)** 했다. 다만 **에디터로 이 씬을 열 때마다 재발**하므로 언젠가 정면으로 처리해야 한다 — 판정 요청: ⓐ 정규화 포맷을 의도적으로 1회 커밋해 고정 ⓑ 현행 유지하고 매번 걷어낸다. ⓐ가 맞다고 보지만 씬 포맷 전환은 3레인 diff 에 영향이 있어 구현이 정하지 않는다.
