## 1. 도구 선정 — **jsfxr 1.4.1 · 벤더링**

### 1.1 후보 2종 대조

| 축 | `jsfxr` (npm) | `rfxgen` (raylib) |
|---|---|---|
| 헤드리스 구동 | ✅ Node 순수 구현 — **실측 통과** | ⚠ GUI 도구(raylib) · CLI 모드는 있으나 **사전 빌드 바이너리 또는 C 빌드 필요** |
| 재생성 경로에 드는 외부 변수 | 사본 2파일 (자족) | **미버전 바이너리** — 저장소 밖 산물이 경로에 든다 |
| 런타임 의존 | **0** (devDependencies 뿐) | raylib 툴체인 |
| 라이선스 | **UNLICENSE (퍼블릭 도메인)** | zlib/libpng |
| 포맷 제어 | `sample_rate`·`sample_size` 직접 지정 → **44100/16 실측 확인** | CLI 플래그 |

⇒ **선정 = jsfxr.** 결정적 요인은 *"커밋 = 재현 계약"* 이다 — `rfxgen` 은 재생성이 **저장소에 없는 바이너리**에 걸리므로 그 계약을 만족시키지 못한다.

### 1.2 npm 의존이 아니라 **벤더링**을 택했다

`npm install` 은 재생성 경로에 **레지스트리 가용성 · 버전 해석 · `node_modules` 미커밋** 세 변수를 끼워 넣는다. `swatch_gen.js`·`icon_draw.js` 가 세운 계약(*"재현 = 같은 명령"*)을 오디오에도 그대로 적용했다.

**라이선스가 그것을 허용한다** — UNLICENSE(퍼블릭 도메인)라 사본 배포에 조건이 없다. 출처 표기는 의무가 아니라 **위생**으로 남겼다:

| 기록 | 값 |
|---|---|
| `vendor/PROVENANCE.md` | 버전 · 배포 URL · npm `dist.shasum` `b379c2d2…` · `dist.integrity` sha512 · 취득 일자 |
| 파일별 SHA-256 | `sfxr.js` `6095a635…` · `riffwave.js` `ab3cea2b…` · `UNLICENSE` `7b30c10d…` |
| 재검 | `npm pack jsfxr@1.4.1` 후 `sha256sum` 대조 |

> **벤더 사본은 한 바이트도 고치지 않았다.** 고치면 상류 해시 대조가 죽는다 — 우리 쪽 요구(§1.3)는 전부 **호출 측**에서 처리한다.

### 1.3 ⚠ 결정성 결함을 찾아 막았다 (선정 과정의 실측 산물)

**상류는 잡음 합성에 `Math.random` 을 쓴다.** 실측:

```
wave_type 0  01618461386db536  01618461386db536  결정적
wave_type 1  f5edaa2a2646f3de  f5edaa2a2646f3de  결정적
wave_type 2  800658d751c53193  800658d751c53193  결정적
wave_type 3  77be8536705e3ed5  47a9011842dbf15f  ⚠ 비결정
```

**같은 파라미터가 다른 바이트를 낸다** — 그대로 두면 "파라미터 커밋 = 재현" 계약이 성립하지 않는다.

**조치:** 생성기가 합성 구간에만 `Math.random` 을 **항목별 `seed` 의 mulberry32 로 교체하고 finally 로 되돌린다.** 벤더 사본 무접촉으로 결정성을 얻는다.

> **현행 8식은 잡음을 쓰지 않아 seed 가 출력에 영향이 없다**(실측 확인). **보험이지 장식이 아니며**, 잔여 60식에 잡음 항목(파편·노이즈 계열)이 들어오는 순간 필요해진다. 지금 넣지 않으면 그때는 이미 비결정 산출물이 커밋돼 있다.

### 3.2 D11 규격 준수 지점

- **`se_r03` = 1파일**(총괄 §2.2-ⓑ). **톤 성분을 남긴 것이 판단**이다 — 런타임 3피치 상승이 D11 의 *"사전 텐션의 청각 문법"* 이므로 순수 잡음이면 상승이 안 읽힌다.
- **`se_r05` 는 `se_r04` 와 파형·듀티를 동일하게 두고** 기음·아르페지오 폭·길이만 올렸다 — *"음색 계열 동일·상위 변형"* 이 규격이므로 음색을 바꾸지 않았다.
- **`se_u01` 이 8식 중 가장 작고 짧다**(−12.5dBFS · 36ms) — 최고 빈도이고 반복 내성이 본령(D11 §1.1)이라 의도한 배치다.
- **봉인(§1.3)은 에셋이 지킬 것이 없다** — R04/R05 의 정지 후 전속은 디스패처가 강제한다(발주서 명시).

## 4. `se_r02` 루프 실증 — **가는 길에 함정을 밟았고, 등재했다**

### 4.1 결과

```
se_r02 format=PCM16 mix_rate=44100 stereo=false loop=FORWARD begin=0 end=51881 len=1.176s
SFX_IMPORT_PROBE PASS fails=0
```

### 4.2 ⚠ WAV 임포터 `edit/loop_mode` 는 런타임 상수와 **값이 한 칸 어긋난다**

| | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| **임포터** `edit/loop_mode` | Detect From WAV | **Disabled** | **Forward** | Ping-Pong | Backward |
| **런타임** `AudioStreamWAV.LoopMode` | `LOOP_DISABLED` | **`LOOP_FORWARD`** | `LOOP_PINGPONG` | `LOOP_BACKWARD` | — |

**`LOOP_FORWARD` 라 믿고 `edit/loop_mode=1` 을 적으면 조용히 Disabled 가 된다.** `.import` 에는 `1` 이 적혀 있고 임포트도 성공하므로 **어디에도 에러가 뜨지 않는다.**

- 실제로 밟았고, **임포트 캐시 전삭제 후 전량 재임포트(127건)로도 안 고쳐졌다** — 캐시를 의심하다가 값 의미를 의심하고서야 잡혔다.
- **확인 경로는 런타임에서 `loop_mode` 를 읽는 것뿐이다.** `.import` 문면은 증거가 아니다 — `godot/tests/sfx_import_probe.gd` 가 그 형태이며, 대장 §7 에 등재했다.
- **성격은 원격이 방금 닫은 `set_anchors_preset` 순서 함정과 동형이다 — 호출은 성공하는데 결과가 다르다.** 잔여 루프 5식(`se_t03`·`se_u15`·`amb_01`·`amb_04`·`amb_05`)이 같은 자리를 지난다.

### 4.3 [가안] 압축 모드를 PCM 으로 고정했다

Godot 기본값 `compress/mode=2`(**QOA · 손실**)를 **0(무압축)** 으로 바꿨다.

- **근거:** D12 §10.1 이 *"16비트 질감은 에셋에 **베이크** — 런타임 가공 없음"* 을 명문화했는데, 손실 코덱은 그 베이크를 런타임에 흔든다. 특히 어택이 선 칩 음원에서 그렇다.
- **비용 실측:** 8식 합계 **146KB**. 68식 전량으로 외삽해도 무시할 만하다.
- **[가안]인 이유:** 전량 유입 회차에서 유지할지는 그때 판단이 맞다(아이콘 `.import` 무손실 전례와 같은 축). 총괄이 지금 못 박기를 원하면 그렇게 한다.

## 5. 귀 검수 — **하지 않았다** (측정 부기만)

발주 §7.1 명시대로 톤 판정 표본까지가 몫이다. 기계로 본 것은 규격·길이·피크·무음·클리핑뿐이다.

> **측정 부기 1건 (판정 아님):** dBFS 가 **−3.6(`se_i10`) ~ −12.5(`se_u01`)** 로 9dB 폭이다. 이는 *커서음이 가장 작아야 한다*(D11 §1.1 반복 내성)는 의도의 산물이지만, **의도한 폭인지 과한 폭인지는 귀 소관**이라 값만 올린다.
>
> **자기 교정 1건:** `se_u01` 초안이 **6ms** 로 나와 블립이 아니라 클릭으로 떨어져 **36ms** 로 늘렸다 — sfxr 포락선이 값의 **제곱**에 비례해 `p_env_sustain 0.012` 가 14샘플이었다. 되읽기 표에서 잡혔다.
