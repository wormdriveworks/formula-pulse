## 0. 한 줄 결론

**5건 중 정상 3 · 결함 1 · 미측정 1.** 결함은 **저장 표시가 설계 이후 한 번도 화면에 보인 적이 없었다**는 것이고(형제 순서 = 그리기 순서), 교정·회귀·실기 확인까지 닫았다. 미측정은 패드 — 이 머신에 패드가 **없다는 것을 실측으로** 못박았다.

발주가 이 회차를 "관찰 위주"로 규정한 판단이 맞았다. 결함 1건은 **기존 회귀 축이 통과하는 상태**로 숨어 있었고, 1GP 완주 뒤 실기 없이는 드러날 수 없었다.

## 2. 항목 ② 2~4막·기원·에필로그 VN — **1막·선택 1지점 정상 / 2막 이후 도달 불가(이월)**

### 2.1 실발동 확인분

- **1막 = 커리어 개시에서 실발동.** `vn_season_open_s1` → `vn_act1`(12줄) → `_next_route = RACE-01`. 발주 11차의 "첫 투어 경계 아님" 확인이 실플레이로 재확인됐습니다.
- **선택 4지점 중 1지점 실도달.** 앵커 `vn.act1.beat12` 뒤 `ChoiceOverlay` 실개방 · **버튼 3개** · 선택 → 반응 1줄(`vn.act1.react1`, 마르타) 삽입 → 합류. **`choice_omissions` = 빈 배열** — 11차의 씬 계약(이름 2개)이 실기에서 성립합니다.
- **1막의 앵커가 마지막 줄이라 "합류"가 곧 VN 종료입니다.** 데이터 그대로의 귀결이며 결함이 아닙니다.

### 2.2 투어 경계 래치 — 기제 실행 · 발화 0 (정상)

**10차 §7 에서 차단으로 올린 "막 VN 소비부 부재"는 해소됐습니다.** `garage_screen.gd:114`·`save_slot_screen.gd:87` 이 `take_brief_payload()` 를 소비하고 `close_tour()` 가 `latch_narrative_act()` 를 부릅니다.

리타이어로 투어 경계를 실통과했고, 개러지 출발에서 `take_brief_payload("RACE-01")` 이 빈 값을 돌려 **RACE-01 직행**했습니다. **마일스톤 미달이므로 래치가 아무것도 발화하지 않는 것이 규격입니다**(`latch_narrative_act` = 달성형 전속 · 1막만 `open_narrative_act` 개시형).

### 2.3 2~4막·기원·에필로그 = **이 회차 도달 불가** (이월)

진입 관문이 마일스톤이고, 디버그 그리드가 `player_start_position 16` 이라 실기 성적(P16·P15)으로는 하나도 서지 않습니다.

| VN | 관문 | 이번 회차 |
|---|---|---|
| 2막 | `milestone_first_podium` (gp_rank ≤ 3) | 미달 (최고 P15) |
| 3막 | `milestone_first_tour_win` (tour_rank 1) | 미달 (투어 P16·탈락) |
| 4막·기원 | `milestone_lorentz_beat` | 미달 |
| 에필로그 | `milestone_season_champion` | 미달 |
| 재회 브리핑 | `vnbeat_reunion_alta` = `stage_alta_ridge` 무대 | 무대 미도달 |

**임의로 마일스톤을 세워 띄우지 않았습니다** — 그것은 "실플레이 경로로 도달"이 아니고, 발주가 요구한 것도 아니라고 읽었습니다. 도달에는 포디움 이상의 실력 플레이 또는 시즌 완주가 필요합니다. **이월 사유를 관문과 함께 명기**하니, 필요하면 13차에서 "실력 플레이 1GP" 를 별건으로 발주해 주십시오.

## 3. 항목 ③ 저장 표시 — **결함 발견 · 교정 완료 (IMPL-312)**

### 3.1 결함: 표시가 **한 번도 보인 적이 없다**

`app_root.gd` 는 `_ready()` 에서 표시를 한 번 붙이고, `_show()` 는 전이마다 화면을 **그 뒤에** 붙입니다. **형제 순서가 곧 그리기 순서**이므로 화면이 표시를 덮습니다. 그리고 저장 지점 3곳(D09 §2.4)의 화면은 **전부 전면 불투명 `Background`(alpha 1.0)** 를 깝니다.

주석이 *"라우터가 화면 위에 얹어 둔다"* 로 쓴 계약이 구현에서 뒤집혀 있었습니다.

**실측 근거**

- 전이 후 형제 인덱스 = 표시 **18** < 현 화면 **19**
- 저장 지점 3화면(`gp_result`·`tour_report`·`garage`) 전건 `Background` 불투명 full-rect
- 값·결선은 **정상**이었습니다: `_hold_sec 2.0` · `_spin_sec 1.0` · 텍스처 적재 · `_reported false` · `save_progress()` 가 `progress_saved` 실발신

즉 **"안 도는" 결함이 아니라 "못 보이는" 결함**입니다. 그래서 값 축·결선 축 검사가 전부 통과하고 있었습니다.

### 3.2 교정

`_show()` 에서 `bind()` **앞**에 `move_child(_save_indicator, -1)`.

- `bind()` **앞**인 것이 규칙입니다 — RACE-03 은 `_on_bound` 에서 저장하므로 순서를 뒤집으면 2.0초 중 앞부분이 화면 밑에서 소모됩니다.
- `z_index` 가 아니라 형제 순서를 쓴 것은 **검사가 볼 수 있는 사실**이기 때문입니다.

### 3.3 교정 후 실기 확인

- **개러지 화면 위에 `sys_save_spin` 고리가 실렌더** (GDAI 런타임 스크린샷)
- 실 저장 직후 `rotation` = **4.712389 = 3π/2 정확** — 등속 회전에서는 나올 수 없는 값
- `_elapsed 19.988` 에 대해 `floor(19.988 / 0.25) % 4 = 3` 과 일치 → **90° 계단과 주기 소비가 엔진 값으로 교차 검증**

관측 목적으로 `param_fx_save_hold_sec` 를 일시 20.0 으로 올려 촬영했고 **즉시 원복**했습니다(`git diff` 공란 확인). D13 값은 무변경입니다.

### 3.4 회귀 — UISCR ⓓ-2 신설 (317 → 319)

**기존 ⓓ 는 이 결함 상태에서도 통과했습니다.** `visible and is_inside_tree()` 만 보았기 때문입니다 — **가시 플래그는 "보인다"의 증거가 아닙니다.** 축을 **"덮이지 않는 자리"**(라우터의 마지막 형제 · 인덱스 > 현 화면)로 옮겼습니다.

돌연변이 **M1**(`move_child` 제거 = 교정 되돌리기) → **2검사 FAIL 로 검출**, 진단이 `last=SaveSlotScreen` · `indicator=18 current=19` 로 결함 상태를 그대로 출력합니다.

### 3.5 판정 요청 — 저장 시간 감각 (2.0s)

**지금까지 아무도 이 표시를 본 적이 없으므로 "체감"의 이력이 0입니다.** 교정 후 실기 소견만 올립니다.

- **RACE-03·투어 결산 = 2.0s 로 충분합니다.** 두 화면은 입력까지 정지해 있어 표시가 뜬 채로 읽힙니다.
- **개러지 출발 = 2.0s 가 전이를 가로지릅니다.** 출발 즉시 화면이 RACE-01 로 바뀌는데 표시는 남습니다 — §181 이 "저장 중 종료 경고의 근거"라고 규정한 용도에는 **오히려 이 쪽이 맞습니다**(전이와 함께 사라지면 근거가 끊긴다).
- 소견: **2.0s 유지 · 값 변경 불요.** 다만 이 판단은 표시가 이제 막 보이게 된 직후의 것이라, 실사용 감각은 사용자 눈이 한 번 받아 주는 편이 낫습니다.

## 5. 항목 ⑤ 마우스 클릭 전수 재확인 — **정상 (IMPL-301 교정분 실기 확인)**

실 OS 마우스 이벤트(Win32 주입)로 다음이 도달했습니다.

| 경로 | 결과 |
|---|---|
| **스핀** (`E08Confirm`) | **정상** — 2세션에서 각 1회. 릴 적재 · `스핀`→`확정` · 타이머 개시 |
| **리스핀** (`E08Respin`) | **정상** — "후보 고정. 잔여 재연산." · 차지 −1(`param_charge_hold_cost`) |
| **차지 개입** (`E08ChargeIntervene`) | **정상 (거부 포함)** — 트러블 부재 턴에서 `negate_trouble` 이 `no_trouble` 로 정상 거부 |
| 기록실 · 아카이브 탭 · 계속하기 · 일시정지 재개 | 전건 정상 |

**이중 발화 관측 0** — 클릭 1회 = 스핀 1회 · 릴 1벌이며, 키보드 경로와 상태 변화가 동일합니다.

### 5.1 미확정 관측 2건 (결함으로 올리지 않습니다)

`SET-01 개러지로` · `기록실 통산 기록 탭` 에서 클릭 무반응을 각 2회 관측했습니다. 그러나 **결함으로 단정할 수 없습니다.**

- 같은 크기(18px)의 버튼이 다른 화면(`E08*` 3종 · 일시정지 `재개`)에서는 **정상 동작**했습니다.
- 두 관측 구간에 **임베드 게임 패널 원점이 세션 중 이동**(768,432 → 786,467)한 것이 확인됐습니다. 이 이동량은 컨트롤 공간 y 로 약 15 이고, **높이 18px 버튼을 정확히 벗어나게 하는 크기**입니다.
- 두 버튼의 `pressed` 결선은 코드·UISCR ⑳ 양쪽에서 실재합니다.

**하네스 기하 오차로 판단하되 단정하지 않습니다.** 두 버튼 클릭만 눈으로 한 번 확인해 주시면 닫힙니다.

### 5.2 하네스 자수 — 화면 캡처 채널은 무효였습니다

GDI `CopyFromScreen` 이 게임의 **GL 표면을 잡지 못해** 덮인 남의 창을 찍었습니다(같은 순간 GDAI 스크린샷은 고리를 보여 줬습니다).

**한때 "버스트 70프레임 점등 0"을 저장 표시 결함의 근거로 삼았으나 그 근거는 무효입니다.** IMPL-312 의 실제 근거는 **형제 인덱스 실측 · 불투명 배경 · 돌연변이 M1** 이며, 코드 주석에서도 무효 근거를 제거하고 유효 근거로 교체했습니다. 이후 관측은 전부 GDAI(엔진 되읽기·스크린샷)로 전환했습니다.

부수: `/root.position`(960,540)·`size`(1920×1080)는 **논리 단위**입니다 — 물리 화면 좌표가 아니며 DPI 계수 0.8 이 곱해집니다. 좌표는 매 입력 직전 재해석해야 합니다.

## 6. 부수 교정 — UISCR ⑫ⓔ 전제 자립화 (IMPL-312 ⑥)

실기 회차 직후 `[FAIL] 전제: 온보딩 팁 표출` 이 났습니다. **원인은 코드가 아니라 검사의 전제**입니다: 온보딩 팁은 1회성이고 기록이 `user://options.json` 이라 **테스트 밖의 실플레이가 전제를 소모합니다**(마운트 자체가 `mark_onboarding()` 을 타 디스크까지 씁니다).

검사가 머신 상태에 의존하면 **회귀가 아니라 날씨**가 되므로, 기록을 비우고 들어가 **디스크까지 되돌리도록** 고쳤습니다. 씬 로드 실패 시에도 검사 수가 줄지 않게 양 갈래 모두 `_ok` 를 냅니다.
