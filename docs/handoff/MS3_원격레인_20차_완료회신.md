## 1. 엔진 API·계약 (주력 13차가 집을 이름)

### 1.1 `RaceEngine` — 투입

| 시그니처 | 반환 | 비고 |
|---|---|---|
| `use_skill(skill_id: String, args: Dictionary = {}) -> Dictionary` | `{"ok": true, "events": Array, "family": String, "effect": String}` / `{"ok": false, "error": String}` | 기본 개입 3종(`hold_respin`·`negate_trouble`·`add_duel_boost`)과 **동형 반환**. 거부 시 비용·횟수·상태 전부 무변경 |
| `use_skill_check(skill_id: String) -> Dictionary` | 동일 | **인자 없이** 판정 가능한 관문만. 버튼 활성 판정용 |
| `choose_snapshot(keep_new: bool) -> Dictionary` | 동일 | SH3 전속 2단계 |
| `skill_slots() -> Array[Dictionary]` | 렌더링 창구 | 아래 §1.2 |
| `snapshot_previous: Array` | SH3 구 후보 | 비어 있지 않으면 **택1 대기 중** |

**`args` 규약** — 타입별로만 읽는다:

| 계열 | args | 예 |
|---|---|---|
| 홀드 (SH1·SH2·SH3) | `{"keep": [릴 인덱스]}` | SH1 = 정확히 2개 강제 · SH2 = 불요 · SH3 = 자유 |
| 변환 (SC1·SC2·SC4) | `{"target": 릴 인덱스}` | — |
| 변환 (SC3) | `{"target": 릴, "donor": 인접 릴}` | `abs(target-donor) == 1` 강제 |
| 증폭·보험 (8종) | 없음 | 턴 스코프 변조 |

**`error` 값 전량** (UI 문면 분기용): `phase` · `deck` · `unknown` · `uses` · `charge` · `duel_turn` · `sector_turn` · `already` · `respin_cap` · `no_provisional` · `keep` · `target` · `symbol` · `adjacent` · `same` · `effect`

### 1.2 `skill_slots()` 행 형식

```
{id, name_key, family, effect, charge_cost, uses_per_tour, uses_left, usable, reason}
```

- `uses_left`: **−1 = 투어 무제한** (0 은 '소진'이므로 무제한과 같은 값을 쓸 수 없다)
- `usable`/`reason`: `use_skill_check()` 를 **그대로 호출해** 채운다. 조회와 투입이 각자 판정하면 "버튼은 켜지는데 눌리지 않는" 상태가 생긴다 — 판정은 한 곳뿐이다(돌연변이 E17 로 확인).
- 화면은 `data.skills` 도 `outgame.deck` 도 읽지 않는다. **`engine.skill_slots()` 하나면 슬롯이 그려진다.**

### 1.3 봉인 준수 (불변규칙 5)

- 투입 자체가 `T4_INTERVENTION` 게이트 뒤다 (돌연변이 E3).
- `use_skill` 은 **심볼을 반환하지 않는다** — 기본 홀드 전례 그대로 UI 가 `get_provisional()` 로 가져간다.
- **인자 의존 조건을 `use_skill_check` 에서 일부러 보지 않는다.** "SC1 을 누를 수 있는가"가 트러블 유무로 갈리면 **버튼 상태가 곧 결과 상관 신호**가 되어 릴 정지 연출 전에 결과를 흘린다. 관문 조건은 전부 잠정 결과의 내용과 무관하다(창·덱·차지·횟수·턴 종류·자릿수).

### 1.4 세션 창구 (`ui/flow/run_session.gd` — 범위 판단 보고)

```
begin_gp():  outgame.deck                → engine.deck_carry_in
             outgame.skill_uses_this_tour → engine.skill_uses_carry_in
start_gp():  반입 필드 → engine.deck / engine.skill_uses (GP 스냅숏)
close_gp():  engine.skill_uses          → outgame.skill_uses_this_tour
```

**발주는 "`godot/ui` 무접촉"이고 `run_session.gd` 는 그 아래 있다.** 그런데 발주 §5 가 요구한 "세션 창구"의 실체가 이 파일이며, 여기를 건드리지 않으면 아웃게임 덱이 엔진에 도달하지 않아 **API 가 서도 발동이 성립하지 않는다.** 무접촉의 취지는 주력 소유물(화면 스크립트·`.tscn`)이라고 읽고 **이 1파일만, 가산 7줄로** 손댔다. 화면·씬은 전건 무접촉이다. 다르게 읽어야 하면 원복 후 주력 13차에 이관한다.

### 1.5 SFX — 표는 이미 서 있다

`sound_map.csv` 에 `skill_hold`·`skill_convert`·`skill_amplify`·`skill_insure`(SE-I05~I08)가 실재한다. 화면에서 **`sfx("skill_%s" % family)` 한 줄**이면 결선이다 (`use_skill` 반환의 `family` 를 그대로 쓴다). AUDIO-W 미결선 대장의 4행은 남겼고 **사유를 갈았다** — "덱 슬롯 전량 잠금"은 이미 해소된 이유이고, 남은 것은 화면 슬롯 미렌더 하나다. 사유를 고치지 않으면 다음 사람이 해소된 이유를 보고 판단한다.

## 2. 소비 규칙 실측

### 2.1 값의 창구 — **신설 6항 · 철회 1항**

D13 별첨A §4.2 가 16종 효과 수치를 전량 확정해 두었다. `core_params` 전사분:

| 키 | 값 | 정본 |
|---|---|---|
| `param_skill_advance_mult` | 1.5 | SA1 "전진 효과 ×1.5" |
| `param_skill_pulse_mult` | 2 | SA2 "펄스 차지 생산 ×2" |
| `param_skill_defense_mult` | 1.5 | SA3 "방어 효과 ×1.5" |
| `param_skill_defense_duel_add` | 12 | SA3 "방어 듀얼 판정 +12" |
| `param_skill_boost_per_judgment` | 16 | SA4 "부스트 차지당 보정 10 → **16**" |
| `param_skill_chassis_floor` | 1 | SI4 "섀시 최저 1" |

**철회 1항 — 재회전 총량 상한은 이미 전사돼 있었다.** 초판은 `param_skill_respin_cap,2` 를 새로 만들었는데, `param_hold_total_cap_per_turn,2` 가 **오래 전부터 표에 있고 소비부가 0이었다.** 새 키를 두면 같은 정본 값이 두 곳에 살고 한쪽만 고쳐지는 날이 온다 — 철회하고 기전사 키를 소비했다. 발견 경로는 우연이 아니다: 픽스처 표(`tests/fixtures/tables/core_params.csv`)에 내 신설 키가 없어 DATA 스위트가 붉어졌고, 그 표에 `param_hold_total_cap_per_turn` 이 이미 있었다.

**코드 무기입 확인:** 효과 수치 중 코드 리터럴 0. 심볼 치환·복제는 `symbol_match_effects` 를 그대로 타므로 별첨A 의 "게이지 부가 +11 G"(SC1)·"게이지 차 +13 G"(SC4)·"차지 +1"(SC2)은 **치환의 귀결**이고 별도 가산이 아니다 — 검사가 표에서 읽은 값으로 차분을 대조한다.

### 2.2 비용·횟수

| 항목 | 실측 |
|---|---|
| `charge_cost` 차감 | 표 값 그대로 · 거부 시 무변경 (E1) |
| `uses_per_tour` | 0 = 무제한 · SH4 = 2 · SI4 = 1. 투어 5턴 시도 → **정확히 2회만 성립** (E2) |
| 투어 경계 리셋 | `OutgameState.begin_tour()` (E21) |
| 정본의 소재 | **아웃게임**이다 — 엔진에 두면 GP 를 새로 시작하는 것만으로 상한이 되살아난다 |
| 세이브 직렬화 | 엔진 = `deck`·`skill_uses`·`respin_count`·`skill_mods`·`snapshot_previous` / 아웃게임 = `skill_uses_this_tour`. 구세이브 관용 전건 |
| 재로드 리롤 무효 | 재회전 직전 스냅샷 → 3회 재로드 → 동일 결과 (D12 §6.3) |

**변조를 세이브에 싣는 이유:** 턴 스코프라 빼고 싶지만, 재로드로 보험이 풀리면 이미 지불한 차지가 사라지고 반대로 남으면 재로드가 이득이 된다. 어느 쪽도 스커밍 무효 규칙과 양립하지 않는다.

### 2.3 무효과 투입 거부 — 새 규칙이 아니라 기존 취지의 연장

D05 §6.1 은 "무비용 통제는 존재하지 않는다"고 쓴다. 그 반대편, **비용만 태우고 아무 일도 없는 투입**도 막았다. 판정은 "효과가 이번 턴에 도달할 수 없으면 거부":

- 듀얼 턴은 정산 ①~⑤ 를 돌지 않는다(`_settle_duel`) → SA1·SA2·SI2·SI3 거부(`duel_turn`)
- 섹터 턴에는 부스트·듀얼 판정이 없다 → SA4·SI1 거부(`sector_turn`)
- **SA3 만 양쪽에서 성립한다** — 별첨A 문면이 "방어 효과 ×1.5 **+** 방어 듀얼 판정 +12"라 절반씩 다른 턴에서 쓰인다. 섹터 턴에서는 듀얼 가산을 세우지 않는다(세우면 배수가 두 번 붙는다).
- 같은 변조 재투입 · 대상 심볼 아님 · 이미 동일한 복제 · 재회전 대상 0 → 전건 거부

### 2.4 홀드 계열 총량 가드

D07 §4.2·별첨A §4.2 의 "기본 홀드 + 스킬 홀드 합산 턴당 2회". 카운터를 **둘** 둔다: `hold_used`(기본 액션의 턴당 1회 — D05 §5.4 무개정) + `respin_count`(합산 상한). 스킬이 상한을 먼저 소진하면 **기본 홀드도 거부된다**(E6) — `hold_used` 만으로는 그것이 표현되지 않는다.

### 2.5 정산 8단계 무변경 (C-2)

효과는 전부 기존 단계 **안에서** 해소된다. 단계 신설 0 · 순서 변경 0:

| 스킬 | 소비 지점 |
|---|---|
| SI2·SI3 | 단계 ① 위험 (섀시 소모 / 후방 가산) |
| SA2 | 단계 ② 자원 (펄스 심볼 생산만 — 안정 완주·듀얼 승리는 심볼 생산이 아니다) |
| SA3 | 단계 ③ 방어 |
| SA1 | 단계 ④ 전진·공략 |
| SA4·SA3(듀얼분)·SI1 | 단계 ⑥ 듀얼 (판정치 / 패배 페널티) |
| SI4 | 리타이어 판정 **직전** — §3 참조 |
| 홀드·변환 계열 | 정산 전(T4) 잠정 결과 조작 |

**SI4 의 배치가 규격이다.** 섀시를 깎는 경로는 단계 ①(트러블)과 단계 ⑥(듀얼 패배) **둘**이다. 어느 한 단계 안에 최저값을 넣으면 다른 경로가 바닥을 뚫는다 — 돌연변이 E13 이 실제로 듀얼 패배로 리타이어시켰다(`chassis 0.0 · finished true`).

## 3. RNG (발주 ③)

**신설 스트림 0 · 기존 관례 승계.** 스킬 재회전은 기본 홀드와 같은 `reel` 스트림을 쓴다(D12 §6 — 릴 결과를 만드는 난수는 reel 하나). 계열별 실측:

| 계열 | 난수 소비 |
|---|---|
| 홀드 (SH1·SH2·SH3) | `reel` **만** |
| 변환·증폭·보험 | **0** (전부 결정적) |

전 스트림 상태를 투입 전후로 되읽어 대조했다 — "reel 을 썼다"가 아니라 "**다른 5스트림이 움직이지 않았다**"까지 본다. SH1 의 트러블 제외는 확률 표를 따로 두지 않고 **가중 0 대입**으로 한다: `pick_weighted` 가 합으로 나누므로 0 대입 자체가 별첨A 의 "재정규화"다.

## 6. 판정 요청·보고 3건

### ① [가안 — 판정 요청] SA1 "전진 효과 ×1.5" 의 적용 범위에 **모멘텀 보너스가 포함되는가**

**현행 구현 = 심볼 유래 전진분 전속** (슬립스트림·라인·찬스), 모멘텀 보너스 제외.

근거 두 갈래:
- 별첨A 문면의 '전진 효과'는 정산 ④ 심볼 항이고, 모멘텀은 D05 §7.3 **타이머** 보너스로 소관이 다르다.
- **D14 §8.3 ③ 매트릭스의 판정 기준이 "개입 후에도 모멘텀 델타 불변"이다.** 모멘텀을 곱하면 그 기준 자체가 깨진다 — 정본이 스킬 층에서 그 기준을 해제한다고 쓰지 않았다.

정본이 침묵하는 지점이라 **[가안]** 이며, 판정이 뒤집히면 곱 대상 1줄 + 매트릭스 기대값 1줄이다. **어느 쪽이든 검사가 갈린다**(E8 = 모멘텀까지 곱하면 델타 7.5 로 검출).

### ② [보고] R-D07-1 순생산 — 별첨A 산식과 구현이 **±2 갈린다**

| 펄스 매치 | 기본 생산 | SA2 순생산(구현) | 차 |
|---|---|---|---|
| 1매치 | 1 | 1 | ±0 |
| 2매치 | 2 | 3 | **+1** |
| 3매치 | 4 | **7** | **+3** |

별첨A §4.2 R-D07-1 대조는 "최대 조합(SA2+펄스 3매치)도 `6 − 1 = 5`"로 적었다. 3매치 차지는 표기가 **"+3 (+보너스 1 = 4)"** 이고 CSV 는 단일 값 4이므로, 별첨A 산식은 **보너스 1을 배수 밖에 둔 것**(3×2=6)이고 구현은 행 전체를 곱한다(4×2=8). CSV 가 3매치를 한 값으로 모델링하는 한 코드가 그 둘을 쪼갤 근거가 없다 — 쪼개려면 표에 열이 필요하고, 그것은 데이터 개정이다.

**판정 불변 전망:** 2매치 이상 발생률 **3.97%** · 보유 상한 10 · SC2 순생산 −1. R-D07-1 이 방어하는 것은 "차지 무한 양산 엔진 빌드"이고 5든 7이든 상한과 빈도가 그것을 막는다. **값을 바꾸지 않았고 제안하지도 않는다** — 표기의 어느 쪽을 정본으로 볼지가 총괄 판정 사안이다.

### ③ [보고] 검사 수 하한은 **이미 쪼그라든 상태에서 세우면 아무것도 못 잡는다**

초판 돌연변이에서 4종(E9·E10·E11·E15)이 미검출이었고 **원인은 하나**였다. 검사 보조 함수 `_match_row` 가 `data.match_effects`(2단 딕셔너리 `symbol_id → {match_count → 행}`)를 **행 배열로 다뤄** `row["symbol_id"]` 에서 죽었고, GDScript 는 그 자리에서 **호출 프레임을 통째로 중단**한다 — 뒤따르는 검사 수십 개가 실행되지 않은 채 스위트가 `PASS` 를 냈다.

**하한 게이트가 이것을 못 잡은 이유:** 하한을 그 붉은 상태의 검사 수로 세웠다. 하한은 *나중의* 축소를 잡지만 *처음부터의* 축소는 정상으로 못박는다. 4종이 미검출로 나온 것이 유일한 발견 경로였다 — **돌연변이가 검사를 검사한 사례**다. 교정 후 TC-C 2197 → 2229(실행되지 않던 32검사 부활) · 4종 전건 검출.

부수로 잡은 측정 함정 3종(전부 "값이 아니라 측정이 사라진" 형태):
- **차지 상한 절단** — 프로브 차지를 99 로 채우면 생산분이 전부 상한(10)에 먹혀 차분이 −잔액이 된다. 비용만큼만 주어 0에서 출발시킨다.
- **게이지 하한 절단** — 0 에서 출발하면 앞차 저항이 음수로 밀어 절단되고, 절단된 두 값의 차분은 효과가 아니라 절단폭이다. 기저값 50 에서 잰다.
- **정산 ⑧ 이 측정을 지운다** — 인접 상대를 `""` 로 지우면 백그라운드 AI 스왑 후 `_retarget_if_changed` 가 "상대가 바뀌었다"로 판정해 게이지를 0 으로 되돌린다. **시드마다 갈리므로 "어떤 시드에서는 통과하는 검사"가 된다.** 플레이어를 선두(전방 측정) 또는 최하위(후방 측정)에 두어 그 면의 상대를 구조적으로 없앤다.

## 7. TL-5 §8.3 ③ Convert 행 — **종결**

IMPL-133 이 남긴 미측정 1행을 닫았다. 다만 **이전 판의 판정문 자체가 다시 세워졌어야 했다**:

```
# 이전 (IMPL-133)
_ok("변환 개입 = 엔진 API 부재 (매트릭스 미측정 행)", not probe.has_method("convert_symbol"))
```

`convert_symbol` 은 **당시의 추측 이름**이고 실제 진입로는 `use_skill` 이다 — 소비부가 서도 이 검사는 그대로 통과했을 것이다. **이름의 부재는 기능의 부재가 아니다.** 실측으로 갈아치웠다:

| 매트릭스 행 | 판정 |
|---|---|
| 홀드 | 모멘텀 델타 불변 (기존) |
| 보험 | 모멘텀 델타 불변 (기존) |
| 홀드+보험 | 중첩 0 (기존) |
| 증폭(부스트) | 구조적 배타 — 양방향 확인 (기존) |
| **변환** | **API 실재 + 모멘텀 델타 불변 = 정의 외 상호작용 0** |
| **증폭(SA1)** | **신설 행** — 부스트와 달리 섹터 턴에서 성립해 모멘텀과 **같은 턴에 공존한다.** §6 ① 의 판정 지점 |

증폭 행이 둘로 갈린 것이 실질이다: 이전 판의 "증폭 = 구조적 배타"는 **부스트에 대해서만** 참이었고, 스킬 인스턴스가 서면서 배타가 아닌 증폭이 생겼다.
