## 1. ① PAL 차단형 flip — **경고 5곳 전부를 넘겼다**

`_warn`→`_fail` 을 위반 본체 1곳이 아니라 PAL 의 경고 **5곳 전부**에 적용했습니다.

| # | 경고 지점 | 성격 |
|---|---|---|
| 1 | 대장 밖 색 (`%s:%d`) | 위반 본체 |
| 2 | 조달 대장 적재 실패 | **검사 무결성** |
| 3 | 조달 소스가 한 색도 기여 못 함 | **검사 무결성** |
| 4 | 기능색 출처가 한 색도 기여 못 함 | **검사 무결성** |
| 5 | 허용 목록 항목에 근거(reason) 부재 | **검사 무결성** |

### 왜 2~5까지 넘겼는가

**검사 자신이 서지 못한 상태를 경고로 남기면, 조달 경로를 망가뜨리는 것이 곧 검사를 끄는 우회로가 됩니다.**

이건 가정이 아니라 이 프로젝트에서 실제로 일어난 일입니다 — `master_56.gpl` → `master_60.gpl` 개명이 **대장 절반을 죽인 채 통과**했고(IMPL-198 발견), IMPL-201 이 그 구멍을 신호로 바꿔 놨습니다. 그런데 **그 신호가 경고면 차단형 게이트에서 여전히 통과**합니다. 불변규칙 7의 "검증기를 우회·완화·비활성화하지 않는다"를 검사 무결성 축에도 대칭으로 적용한 것입니다.

**V7 무접촉**이며(작법 판단 = D04 소관), `CLAUDE.md` 불변규칙 7과 `run_validators.gd` 머리 주석의 차단형 목록에 PAL 을 편입했습니다. — **`CLAUDE.md` 는 총괄 소관 파일이라 한 절만 손댔습니다. 문면이 총괄 의도와 다르면 그대로 고쳐 주십시오.**

## 2. ② 저장 표시 결선

### 가. D13 v1.8 전사 2행

| 키 | 값 | D13 별첨A §8.1 |
|---|---|---|
| `param_fx_save_hold_sec` | **2.0** | 저장 표시 시간 (D09 §181 "2초 내외"의 값 충전) |
| `param_fx_save_spin_sec` | **1.0** | 저장 표시 회전 주기 (원천 확정) |

키 이름은 `param_fx_duel_result_hold_sec`(표기 유지 = `hold`)의 조어를 그대로 승계했습니다 — 같은 축(표시 지속)이라 새 어휘를 만들 이유가 없습니다.

### 나. `configure()` 결선

8차가 값 부재를 이유로 보류해 둔 호출을 살렸습니다. `_mount_save_indicator(data)` 가 `data` 를 받아 `param()` 창구를 거칩니다 — **리터럴 0**.

### 다. ⚠ 부수 교정 — 8차 주석의 사실 하나가 틀렸습니다

주석은 *"없는 키를 부르면 `GameData` 가 `_load_ok` 를 내려 상단 가드가 부팅을 거부한다"* 고 적었고, 저도 처음엔 그 문장을 그대로 승계해 다시 적었습니다. **돌연변이 M5(행 2개 삭제)가 그것을 뒤집었습니다:**

> `is_ok()` 가드는 `load_all()` **직후**에 서 있고 이 조회는 그 **뒤**입니다. 행이 사라져도 **부팅은 거부되지 않고**, `param()` 이 0.0 을 돌려주어 표시가 **"구성됐는데 안 도는"** 상태가 됩니다.

**보류 판단 자체는 옳았습니다**(불변규칙 2 — 없는 값을 임의 기입하지 않는다). 틀린 것은 근거 문면뿐입니다. 주석을 실측대로 고치고, **보증을 주석에서 회귀 축으로 옮겼습니다**(표 행 실재 = 별도 축).

## 3. 반증 — 돌연변이 7건 전건 검출

| # | 돌연변이 | 검출 |
|---|---|---|
| M1 | 대장 밖 색 1건 주입(도색 문맥) | `VALIDATORS_FAIL failures=1` · exit 1 |
| M2 | 조달 소스 경로 오타(죽은 소스) | `[FAIL] PAL: 조달 소스가 아무 색도 기여하지 못했다` · exit 1 |
| M3 | `configure()` 결선 제거 | 5축 FAIL — `actual=-1.000`(센티넬) · 성공 저장 미표시 |
| M4 | 실패 저장에도 표시 | `[FAIL] 실패 저장 = 미표시` |
| M5 | D13 행 2개 삭제 | **재시행 후 3축** — 아래 |
| M6 | 회전 주기를 표시 시간으로 오배선 | `[FAIL] 회전 주기 = D13 창구 경유 — actual=2.000` |
| M7 | 표시가 화면 전환에 딸려 나감 | `[FAIL] 화면 전환 후에도 표시 생존` |

### M1 — 첫 주입이 무효였다 (프로토콜 함정 #1)

`self_modulate` 자리에 색을 넣었더니 **PAL 의 modulate 문맥 제외**(IMPL-184)에 정확히 걸려 미검출로 나왔습니다. 검사가 옳게 동작한 것이지 구멍이 아닙니다 — 도색 문맥(`add_theme_color_override`)으로 옮겨 재주입해 검출을 확인했습니다.

### M5 — **내 단언이 항진명제였다** (설계 함정 ③)

"값이 D13 창구에서 왔는가"를 `indicator._hold_sec == data.param(...)` 로만 봤습니다. 그런데 **행이 사라지면 양쪽이 똑같이 0.0 을 돌려줍니다** — `0.0 == 0.0` 으로 조용히 통과합니다. 첫 시행에서는 회전 축이 우연히 걸려(`spin_sec = 0.0`) 겨우 1축만 울렸고, 정작 창구 축 2개는 **초록이었습니다.**

비교와 **독립된 사실**인 표 행의 실재(`data.params.has(...)`)를 먼저 세우는 축을 추가해 닫았습니다. 재시행 결과:

```
[FAIL] D13 표 행 실재 — 표시 시간
[FAIL] D13 표 행 실재 — 회전 주기
[FAIL] 표시 중 회전 진행 — rotation=0.000
```

> 같은 창구에서 온 두 값을 서로 비교하면, **창구가 무너진 순간 둘이 함께 무너져 비교는 성립**합니다. 값 검사는 값끼리 맞추는 것으로 닫히지 않습니다.

### 관측 지점

**라우터를 세워 봅니다.** 저장 표시는 화면이 아니라 `app_root` 가 들고 있고 저장 지점 3곳(D09 §2.4)의 화면이 무엇인지는 정해져 있지 않으므로, 실화면 하나로는 계약이 재현되지 않습니다. 표시 여부·회전 진행·전환 생존을 **거동으로** 읽습니다 — 상수 표나 `configure()` 직호출은 결선의 증거로 치지 않았습니다.
