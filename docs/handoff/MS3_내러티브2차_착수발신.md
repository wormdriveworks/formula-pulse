## 1. 범위 — 선택지 문안 + 배치 설계

T7 본편(4막·에필로그·VN 6건 75라인)은 편입 완결됐다(IMPL-253). 남은 서사 발주 = **선택지**. `vn_screen.gd`의 선택지 오버레이는 골격 미사용 상태로 실문안을 기다리고 있다.

**집필 산출물 3축:**

1. **배치 설계** — 기존 VN 6건(`act_vn.json`) 중 **어느 VN의 어느 라인 뒤에 선택 지점을 둘지**. 지점 수·위치는 집필 판단이다(정본이 수를 발주하지 않았다 — 과밀은 D01 G2 비강제성과 긴장하므로 절제 권고).
2. **선택지 문안** — 지점당 2~3개.
3. **반응 변주 라인** — 선택별 직후 상대 반응(아래 §2-③).

## 2. 구속 (D04 §5.3 — 전건 기계 이전 확인 완료)

| # | 구속 | 내용 |
|---|---|---|

| ② | 표기 | **1줄 · 전각 14자 이내**(조건부 확정 — D09 보정 가능) · **대괄호 표기 통일** |

## 3. 실물 참조 (기결선 — 맞춰서 쓴다)

- **사운드 기결선**: 선택지 표시 = `SE-V03` · 선택 결정 = `SE-U02` 재사용(D11 §2.10 V-c 계열 — 신규 에셋 0). 집필이 손댈 것 없음, 참고만.
- **스킵 무게이트**(D11 V-c·D01 G2 조건 2): 선택지가 떠 있어도 스킵이 막히면 안 된다 — 배치 설계 시 "스킵 시 이 지점은 어떻게 되는가"를 명기할 것(권고: 스킵 = 기본 선택지 1번 자동 처리 또는 지점 자체 생략 — **집필이 정하되 명기**).
- 1차 납품 관례 승계: 값 콤마 0 · 1줄 · 예시는 기존 데이터 인용.

## 4. 신설안으로 올릴 것 (구현하지 않는다)

1. **선택지 데이터 스키마** — `act_vn.json` `lines` 배열에 선택 지점을 어떻게 담을지(예: 라인 항목에 `choices: [{text_key, reaction_line_keys}]`). **스키마 초안 = 신설안으로 제안**하고 총괄 판정을 경유한다(1차 신설안 B·C 절차).
2. **선택지 자수 기계 규칙** — `string_write_rules`에 선택지 규칙이 **없다**(총괄 실독: `raceLog./relay./vane.` 22자·`vn.` 24자뿐). 14자 규격이 기계 미강제이므로 선택지 키 도메인(예: `vnChoice.`)과 규칙 행을 신설안으로 함께 제안 — 기계 검증 없는 규격은 언젠가 새는 것을 1차가 실증했다(`resonance03`).
