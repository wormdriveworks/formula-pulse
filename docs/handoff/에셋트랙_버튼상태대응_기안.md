# [에셋 → 총괄] 판정 ㉛ 기안 — Button 상태 5종 대 프레임 의미 4종

> 발주: 총괄 재가동 발신 ② (커밋 `d33bff9` · IMPL-433) · 원 판정 요청 = 주력 14차 §5.2
> 소관: 프레임 원도 저자(에셋 트랙). **결선은 화면 층 소관이고 본 문서는 원도 쪽 기안이다.**

## 0. 한 줄

총괄이 유력하다고 본 **ⓒ(`modulate` 로 상태 · 프레임은 의미 전속)의 방향은 맞고 기구가 틀렸다.**
**틴트 창구는 이미 색각 축이 쓰기로 돼 있었는데, 그 축이 틴트로는 성립하지 않는다는 것을 리포지토리가 이미 판명해 뒀다.** 상태를 거기에 얹으면 두 축이 겹치는 게 아니라 **없는 자리에 얹는 것**이 된다.
권고는 **ⓓ — 프레임 텍스처는 의미 전속, 상태는 라벨 색과 마진으로.** 신규 원도 0 · 폭 예산 0.

---

## 1. 먼저 계수를 고쳤다 — **5 대 4 가 아니다**

| Button 슬롯 | 현황 | 남는 문제인가 |
|---|---|---|
| `focus` | **이미 닫혔다** — 포커스 링(주력 14차 §5.1 결선 · 제원표 예외 ⓑ: 전 링 투명 + 코너 꺾쇠) | 아니다 |
| `disabled` | **1:1** — `button_disabled_9p` | 아니다 |
| `normal` | 의미 **3종**(default·primary·danger) 중 하나를 받는다 | 아니다 |
| `hover` · `pressed` | 대응 없음 | **여기뿐이다** |

그런데 남은 둘을 프레임으로 낸다면 **2장이 아니다.** `normal` 이 의미 3종을 받으므로 실제 행렬은

```
의미 3 (default·primary·danger) × 상호작용 3 (normal·hover·pressed)  +  disabled  +  focus  =  11 슬롯
```

즉 **ⓐ(프레임 추가 제작)는 +2 가 아니라 +6** 이다(버튼 프레임 4 → 10). 의미를 무시한 hover 1장으로 때우면 **마우스를 올리는 순간 default·primary·danger 가 같은 그림이 되어 의미가 사라진다** — 주력이 경고한 것이 정확히 그 현상이고, 프레임 수를 줄이면 그 경고가 되살아난다.

**ⓑ(기존 4종의 상태 배정)는 의미 축을 그 자리에서 잃는다.** 주력의 반대 논거를 그대로 지지한다.

---

## 2. 원도가 이미 답을 반쯤 갖고 있었다 — **의미는 테두리, 상태는 면**

`frame_spec.json` 을 다시 읽었다. 세 의미 프레임의 **면(`center`)이 전부 `N05` 로 같다.**

| 프레임 | profile (테두리) | center (면) |
|---|---|---|
| `button_default_9p` | N01 · N09 · N06 | **N05** |
| `button_primary_9p` | N01 · **C2 · C1** | **N05** |
| `button_danger_9p` | N01 · **DANGER** · N06 | **N05** |
| `button_disabled_9p` | **N02** · N05 · N04 | **N04** ← 유일하게 면을 내렸다 |

`button_primary_9p` 의 주석이 왜 그런지도 적어 놨다 — *"면까지 시안으로 채우면 라벨(9px 본문)의 대비가 무너진다."*
그래서 **의미는 테두리에만, 면은 상수**다. 그리고 **면을 건드린 것은 `disabled` 하나뿐이고 그것은 의미가 아니라 상태다.**

세트는 이미 축을 갈라 놨다: **테두리 = 의미 / 면 = 상태.** hover·pressed 를 프레임으로 내려면 면을 건드려야 하고, 면은 의미마다 있으니 3×2 = 6장이 된다. §1 의 산수는 여기서 나온다.

---

## 3. ⓒ 를 권고하지 않는 이유 — **틴트로는 애초에 안 되는 축이 그 자리를 쓰기로 돼 있었다**

`button_danger_9p` 의 `DANGER #FF4A3D` 는 색각 모드에서 **`#7A5CFF`(팔레트 정본 §6)** 로 가야 한다. 종전 제 주석은 그 교체를 *"표시 층 틴트가 한다"* 고 적었다. **그 주석이 틀렸고, 근거는 리포지토리가 이미 갖고 있었다.**

```
godot/ui/race/race_screen.gd:1139
  # 런타임 틴트로는 정본 색을 재현할 수 없다 — 같은 도상의 대체색 파일(`<id>_alt.png`)을 …
```

심볼 2종(`symbol_line` · `symbol_trouble`)은 그래서 **별도 파일**로 갔다(`*_alt.png` 실재 확인). 산술로도 같은 답이 나온다 — 틴트는 채널별 **곱**이고

```
#FF4A3D (255, 74, 61)  →  #7A5CFF (122, 92, 255)
필요 배율            R ×0.48   G ×1.24   B ×4.18
```

**1 초과 배율이 둘**이고 Compatibility 비HDR 프레임버퍼에서 잘린다. **색상 회전은 곱으로 표현되지 않는다.**

그러므로 ⓒ의 문제는 "두 축이 틴트를 나눠 쓴다"가 아니다 — **색각 축은 틴트로 성립하지 않으므로 텍스처 교체로 가야 하고, 그 뒤에 상태가 틴트를 쓰면 danger 버튼은 `_alt` 텍스처 × 상태 틴트의 곱**이 된다. 교체색을 정본 §6 값으로 맞춰 놓고 그 위에 다시 곱하는 구조다.

부수로 ⓒ 자체 문제도 있다: `self_modulate` 는 **라벨까지 물든다.** 9px 본문의 대비 여유는 이미 얇아서 정본 §9.2.1 에서 두 색을 올려 잡은 전례가 있다.

## 4. 권고 = **ⓓ (ⓒ의 정련)** — 프레임은 의미 전속, 상태는 다른 창구

| Button 슬롯 | 배정 | 신규 원도 | 폭 예산 |
|---|---|---|---|
| `normal` | 의미 프레임 3종 중 1 | 0 | (§6 참조) |
| `hover` | **normal 과 같은 텍스처** + `font_hover_color` 명도 상승 | 0 | 0 (색은 폭에 무관) |
| `pressed` | **normal 과 같은 텍스처** + `content_margin` 종방향 1px 이동 (상하 **합 불변**) | 0 | 0 (합이 불변이므로 최소 크기 불변) |
| `disabled` | `button_disabled_9p` | 0 | — |
| `focus` | 포커스 링 (기결선) | 0 | — |

**왜 의미 축이 지켜지나** — hover·pressed 에서 **텍스처가 바뀌지 않는다.** 주력이 경고한 *"마우스를 올릴 때마다 의장이 갈린다"* 는 텍스처 교체에서 나오는 현상이고, 교체가 없으면 프레임은 상태를 **한 번도 말하지 않는다.** 의미 축이 상태 축으로 바뀔 경로 자체가 닫힌다.

**왜 폭을 안 쓰나** — `pressed` 의 마진 이동은 상하 합이 불변이라 `Button` 최소 크기를 움직이지 않고, 라벨 색은 폭과 무관하다.

**정직하게 남는 대가 하나** — hover 가 **프레임으로는 안 보인다.** 라벨 명도만 오른다. 9px 픽셀 UI 에서 그것이 충분한 어포던스인지는 **눈으로만 알 수 있는 것**이라 실기 회차 관측 항목으로 남긴다. 부족하다고 판정되면 그때 `button_{default,primary,danger}_hover_9p` **3장을 추가**한다(면만 한 단 올린 파생 — 지출 0). **0장에서 시작해 필요분만 늘리는 순서라 선택지를 닫지 않는다** — 반대 순서(6장 먼저)는 되돌릴 수 없다.

## 5. ㉛ 과 별개로 떨어진 결함 1건 — **A-FR-09 색각 대체 원도 부재**

§3 의 근거로 `frame_spec.json` 의 A-FR-09 주석을 **교정했다**(이번 회차 반영). 그리고 그 교정은 **없던 산출물 1건을 드러낸다**:

- **`button_danger_alt_9p`** — `CB_DANGER: #7A5CFF`(정본 §6) 팔레트 키 1개 추가 + profile 1행. 명명은 심볼 선례(`<id>_alt`)를 그대로 쓴다.

**아직 만들지 않았다.** ㉛ 이 프레임을 쓰지 않는 방향으로 결정되면 불요해지므로, **답이 나오기 전에 만들면 제가 던진 질문에 미리 답해 버리는 셈**이다. 판정 직후 산출한다(지출 0 · 파생 1장).

> 이것은 **색각 모드에서 위험 버튼이 적색으로 남는다**는 뜻이므로, 프레임을 쓰기로 하면 결선 전에 닫혀야 하는 항목이다. 도상 무접촉 원칙(정본 원칙 3)은 지켜진다 — 색만 갈린다.

## 6. 착수 순서에 관한 관측 — **41.0 상한은 결선 전에만 유효하다**

총괄 지시대로 **결선(15종)은 ㉝ 뒤**로 두고, 본 문서는 문서라 폭 예산을 쓰지 않는다. 다만 주력 14차의 숫자를 읽으면 순서가 한 방향으로만 서지 않는다.

주력 실측(M16): 테마에 `normal` 계열 박스가 들어오면 **en 초과 40.4 → 32.4** — 즉 **결선이 8.0px 을 돌려준다**(프레임 9패치 마진 8 이 기본 테마 10.0 보다 얇다). 그렇다면

- **결선은 ㉝ 의 부담을 늘리지 않고 줄인다.** 두 사안이 예산을 다투는 관계가 아니라, 한쪽이 다른 쪽에 여유를 준다.
- 그리고 주력이 못박은 **발주 대기 상한 41.0 은 결선 전 값이다.** 결선이 먼저 서면 실측 최악이 32.4 가 되고, 주력이 함께 세운 두 번째 축 — *"상한은 실측 최악과 5px 안이어야 한다"* — 을 41.0 이 **8.6px 로 어긴다.** 상한이 면제로 굳지 않게 세운 축이 순서 때문에 스스로 깨지는 모양이다.

> **부기 (본 문서 작성 중 유입 · 내러티브 11차 `f7c5782`):** 같은 상수를 **내러티브 레인이 반대쪽에서 짚었다** — 채택 문면이 들어가면 세 언어가 다 예산 안에 들어와 `worst = 0.0` 이 되고 `41.0 − 0.0 > 5.0` 으로 축이 붉어진다(§2.6 · `test_ui_screens.gd:3361`). **두 관측은 겹치지 않고 더해진다:** 문면 채택은 초과를 0 으로 내리고, 결선은 그와 별개로 **8.0px 을 더 돌려준다.** 즉 `ROW_OVERFLOW_CEILING := 41.0` 은 **문면·결선 두 방향에서 독립적으로 낡는다** — 어느 쪽이 먼저 서든 낡는다.

**처분은 제 소관이 아니라 총괄·주력 소관**이라 판단하지 않고 올린다. 다만 셋 중 하나여야 할 것으로 보인다: ⓐ 결선을 ㉝ 앞으로 옮긴다 · ⓑ 상한을 실측 최악 기준으로 다시 못박는다(결선 뒤 32.4 · 문면 채택 뒤 0.0) · ⓒ 상한 문면에 *"어느 시점의 값인가"* 를 명기한다. **에셋 트랙은 어느 쪽이든 대기 중이다** — ⓓ 안은 폭을 쓰지 않으므로 순서에 종속되지 않는다.

**그리고 ㉝ 은 아직 결선이 아니다** — 내러티브 11차는 **후보 제시·채택 판정 대기**다(`Step In` 절감 48 권고 · 차선 `Negate` 47). 그러므로 총괄이 지정한 착수 순서(㉝ **결선** 후)는 아직 충족되지 않았고, **본 문서는 문서라 폭 예산을 쓰지 않으므로 순서에 걸리지 않는다.** 결선 15종은 통보를 기다린다.
