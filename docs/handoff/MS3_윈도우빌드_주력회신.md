## 3. ⚠ 적발 — 주력 트리에서 뽑으면 **MCP 런타임이 제품 팩에 실린다**

### 3.1 빌드를 워크트리에서 뽑은 이유가 그대로 결함을 꺼냈습니다

주력 트리에는 `godot/addons/`(GDAI MCP)가 실재하고 그것은 **리포지토리에 없는 파일**입니다. 출시 후보 빌드가 개발 트리의 미추적 파일을 담으면 *리포지토리가 아닌 것*이 제품이 되므로, detached 워크트리(= HEAD 그대로)에서 임포트·게이트·익스포트를 전건 수행했습니다.

그리고 **대조로 주력 트리에서 그대로 뽑아 봤습니다.**

```
워크트리 팩 : 889 files
주력 트리 팩 : 895 files      ← 차이 6건 전부 res://addons/gdai-mcp-plugin-godot/**
   gdai_mcp_runtime.gd / .gdc · gdai_mcp_plugin.gd(c) · .gdextension
   + 네이티브 라이브러리 6종 선언(win/linux/macos)
```

**실 사고도 이미 있었습니다** — 사용자의 선행 시도(11:46)가 `godot/` 에 네이티브 dll 을 복사해 뒀고, **애드온 원본과 해시 동일**(`cab3b731…`)로 확인했습니다. 즉 이번이 처음이 아니라 **한 번 일어난 뒤였습니다.**

`.gitignore` 19~21행이 이미 이렇게 적어 두었습니다 — *"커밋하면 … ③MCP 런타임이 제품 빌드에 실린다."* **그 장치는 리포지토리를 지켰고 팩은 지키지 못했습니다.** 커밋을 막는 것과 팩에 담기는 것을 막는 것은 다른 일입니다.

### 3.2 원격 검침은 이것을 통과시킵니다

`probe_pack.sh` 의 축은 `res://tests/` · 검증 입력 리소스 · 결제/광고 토큰 **3종**이고, **에디터 플러그인은 어느 축에도 없습니다.** 실측에서 오염된 팩이 `PACK_PROBE_PASS` 로 통과했습니다. 축의 결함이 아니라 **대상이 미계상**이었던 자리입니다.

### 3.3 교정

`exclude_filter` 에 `addons/*` 합류 — 출시·Android 2프리셋. **검증 프리셋은 무접촉**입니다(그쪽은 전량 적재가 존재 이유이고, `tests/*` 를 담아야 G-6 방법 ②가 성립합니다).

재익스포트 실측(주력 트리에서) — **팩 내 addons 0 · 산출물 옆 네이티브 라이브러리 0.** 선행 시도의 dll 복사까지 함께 멎습니다. `EXP 181검사` 통과.

> **소견:** 검침 축에 *"에디터 애드온 0"* 을 1줄 추가하실지 판단 요청드립니다. 필터는 방어이고 축은 **그 방어가 살아 있는지**를 보는 자리라, 지금은 필터가 죽어도 아무도 붉지 않습니다.

## 4. 부수 실측 3건

**ⓐ `probe_pack.sh` 에 exe 를 넣을 수 없습니다.** 인계 §5-3 은 *"두 스크립트 모두 pck·exe 양쪽을 받습니다"* 인데, 프리셋이 `embed_pck=false` 라 **exe 에 팩이 없어** `--main-pack` 이 실패합니다(`PROBE_FAIL 팩 적재 실패` → `G7_FAIL`). 실 산출물 검침은 **pck 로** 돌렸고, exe 는 `probe_pack.sh` 와 **같은 토큰 어휘**로 별도 스캔했습니다 — 검출 **0**. 문면이 `embed_pck=true` 를 전제한 것인지, 아니면 exe 경로에 안내를 더할지 원격 판단 사안으로 올립니다.

**ⓑ `codesign/enable=true` 가 매 익스포트 경고를 냅니다.** signtool 부재로 `ERROR: Could not create child process: signtool sign …` + `completed with warnings` 가 나옵니다(빌드 자체는 성립). 어느 쪽이든 **바이너리는 미서명**이고, 그것은 EA 진입 시 **SmartScreen 경고**로 나타납니다. 인증서 조달은 비용·사업 판단이라 **서명 정책 판정 요청**으로 올리고 프리셋 값은 원격이 커밋한 `true` 그대로 두었습니다(끄면 *"서명하지 않기로 했다"* 가 리포지토리 기록이 되므로 제 판단으로 넘길 자리가 아닙니다).

**ⓒ exe 메타데이터 전건 공란** — `ProductName`·`CompanyName`·`LegalCopyright`·**`LegalTrademarks`** 가 비어 있습니다(`FileVersion` 만 `0.2.0.0` 로 `config/version` 승계). Windows 파일 속성은 사용자 가시 면이고 **`LegalTrademarks` 는 상표 규율의 면**이라 임의 기입하지 않았습니다.

## 6. 관측 — 릴리스 빌드 종료 시 경고

산출 exe 를 `--quit` 로 세우면 종료 시 `4 ObjectDB instances were leaked` · `2 resources still in use` 가 나옵니다. **같은 프로젝트를 디버그 가능 바이너리로 `--quit` 하면 경고 0**입니다. 릴리스 템플릿은 누수 상세를 열거하지 않아 **특정하지 못했습니다.** `--quit` 는 프레임 도중 내려가므로 정상 종료에서도 같은지는 **확인하지 않았습니다** — 단정하지 않고 관측만 올립니다.

## 7. 환경 — **해소 완료** (사용자 조치 2026-08-30)

익스포트 도중 **엔진 바이너리가 실행 불가**가 됐습니다. `C:\SDKs\godot\Godot_v4.7.1-stable_win64.exe` 에 Windows 호환성 계층 **`~ RUNASADMIN`** 이 붙어(HKCU AppCompatFlags\Layers) 콘솔 래퍼(198KB — 본체를 `CreateProcess` 하는 구조)가 `error 740`(승격 필요) 로 죽었습니다. 선행 익스포트가 exe 를 쓰는 것을 프로그램 호환성 도우미가 설치 동작으로 보고 붙인 것으로 추정합니다.

**우회가 산출물에 영향을 주지 않았음은 §2 재현성 실측이 증명합니다**(원본 경로 재익스포트 = md5 동일). 즉 이 항목은 회차 기록으로만 남고 산출물 신뢰도에는 걸리지 않습니다.

**재발 조건이 남아 있습니다** — 같은 도우미가 다음 익스포트에서 다시 붙일 수 있습니다. 증상(`CreateProcess failed, error 740`)과 확인처(위 레지스트리 키)를 여기 적어 둡니다.

## 8. 재확인 (2026-08-30 · IMPL-500) — **출하 경로 산출물이 검증·디버그 빌드로 바뀌어 있었다**

사용자 요청으로 두 게이트를 재확인한 결과, `build/windows/` 의 산출물이 **§1 인증분이 아니었습니다.**

부수로 `codesign/enable=false`·`application/modify_resources=false` 도 함께 쓰였습니다. **개정 의도가 아니라 에디터 부산물**로 판단해 프리셋을 커밋 상태로 원복했습니다.

### 8.2 처리

커밋 상태 원복 → HEAD(`16fb6c6`) detached 워크트리 재산출 → **`G6_PASS 3방법 전건 노출 0`·`G7_PASS 데스크탑 2검사`** → 산출물 교체 → 현장 재검침 **`PACK_PROBE_PASS files=889`**.

**재현성 3회차 성립** — `exe 1d6776e1…` · `pck 0424664b…` 가 ①복사 바이너리 ②원본 바이너리 ③`.godot` 재생성 후 새 HEAD 까지 **md5 동일**입니다.

### 8.3 소견 — EXP 에 1줄 (원격·총괄 판단 요청)

**검증 프리셋은 출시 경로를 물 수 없어야 합니다** — `Windows Verify` 의 `export_path` 가 공란이거나 파일명에 `verify` 를 포함할 것.

필터도 검침도 **팩 내용**을 봅니다. 그런데 이번에 깨진 것은 내용이 아니라 **어느 프리셋이 어디로 나가는가**이고, 그것은 아무도 보지 않습니다. 드롭다운 한 칸이 출시물을 검증물로 바꿉니다.

부수 판별점 하나 — **출하 디렉토리에 `*.console.exe` 가 있으면 그 자체가 디버그 빌드의 표지**입니다(값싸고 눈으로 즉시 걸립니다).

### 9.1 "두 곳"은 취향이 아니라 기계 요구였습니다

`EXP_ALLOWED_DIFF = [name, custom_features, exclude_filter, export_path]` 이므로 **그 넷 밖의 옵션은 출시·검증 프리셋이 전값 일치해야 합니다.** 아이콘을 한쪽만 적으면 EXP 가 붉습니다 — 총괄의 *"두 곳"* 지시에 기계적 근거가 있었습니다. 메타 4항도 같은 이유로 양쪽에 넣었습니다.

### 9.2 `use_filter=false` 가 이 회차의 규격 판단입니다

`project.godot` 은 **손 편집**했습니다(에디터 저장은 `[input]` 주석 21줄을 지웁니다 — IMPL-186 계보).

**부트 스플래시는 씬 트리 이전에 그려지므로 전역 `default_texture_filter=0`(니어리스트)의 적용을 받지 않습니다.** 켜 둔 채로 두면 640×360 도트가 보간되어 **D10 §2.2 믹셀 금지에 저촉**합니다 — 전역 설정과 별개의 축이라 프로젝트 설정에 명시했습니다.

`bg_color` 는 팔레트 `BG_DEEP`(마스터 N01 `#080B11`) 전사이며, 16:9 창에서는 보이지 않는 여백색입니다.

**시각 확인** — 표시 시간을 임시로 연장해 실기 촬영했습니다(연장 설정은 산출물에 넣지 않았습니다). 니어리스트 확대·자형 경계의 각짐을 육안 확인했습니다: `docs/handoff/build_evidence/boot_splash_live.png`.

### 9.3 메타 4항

`ProductName`·`CompanyName`·`LegalCopyright` 확정값 기입, `LegalTrademarks` **공란 유지**(운용 규율 5 정합). `©` 인코딩 보존을 되읽기로 확인했고, `modify_resources=true` 가 전제라 값이 실제로 PE 리소스에 실립니다(exe +1,536 B).

> `application/file_description` 은 확정 4항에 없어 **공란 그대로 두었습니다.** Windows 작업 관리자가 보여주는 항목이라 5번째 항으로 볼지 판정 요청드립니다.

### 9.4 템플릿 크기 지문은 기계화하지 않았습니다

콘솔 래퍼 축은 세웠지만, 크기 지문은 **등식으로 적으면 우연을 계약으로 굳힙니다** — 출시 exe 는 아이콘·메타 기입으로 템플릿과 크기가 갈리고(109,072,896 ≠ 109,212,160), 디버그 쪽이 우연히 템플릿과 같았을 뿐입니다. 사람이 읽는 지문으로 머리말에 남겨 둡니다.

### 9.5 ⚠ 발견 — ICO 가 익스포터 요구 6종 중 4종만 갖습니다

익스포트가 경고를 냅니다:

```
WARNING: Resources Modification: Icon size "64" is missing.
WARNING: Resources Modification: Icon size "128" is missing.
```

배치 대장 §6.1 선언은 **16/32/48/256** 인데 Godot Windows 익스포터가 쓰는 것은 **16/32/48/64/128/256** 입니다. 아이콘 자체는 성립합니다(Windows 가 인접 크기를 축소) — 다만 **출시 빌드가 경고를 안고 나갑니다.** 대장 개정 + 2엔트리 추가 = 에셋 사안으로 상신합니다.
