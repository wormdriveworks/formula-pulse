## 2. 파이프라인을 새로 쓴 이유

jsfxr 은 **단발 효과음 합성기**입니다 — 포락선 1벌·단성·길이 상한 6.8초. 지속 다성 음악을 낼 수 없어 오실레이터(구형·톱니·삼각·정현·잡음)·ADSR·1극 LPF/HPF·디튠·믹서를 `bgm_gen.js` 에 직접 뒀습니다.

**SFX 경로는 무접촉입니다**(`sfx_gen.js`·`vendor/` 불변) — 두 파이프라인은 코드를 공유하지 않고, 파라미터 원장도 갈립니다(`sfx_params.json` / `bgm_params.json`). 검사도 그에 맞춰 채널별 원장을 읽습니다.

## 3. 심리스의 실체는 둘입니다

**① 그리드 정수배.** BPM 은 **박당 샘플 수가 정수가 되는 값에서만** 고릅니다 — 44100×60 = 2,646,000 이므로 `2646000/BPM` 이 정수여야 합니다. 98BPM → **27,000샘플** 정확. 아니면 마디마다 소수점 오차가 쌓여 루프 길이가 정수 샘플이 아니게 되고 **그 자리에서 깨집니다.** 생성기가 이 조건을 검사합니다.

**② 꼬리 감김.** 루프 끝을 넘는 잔향을 버리지 않고 **버퍼 앞쪽에 되감아 더합니다.** 꼬리를 자르면 이음매에서 소리가 끊기고, 그냥 두면 마지막 마디가 비어 들립니다. 실측 이음매 **0.89%**.

**산술이 이음매를 없애고, 안 들리게 하는 것은 편성입니다.** 48마디를 넷으로 갈라 조용히 열고(탭·햇·베이스 · 8마디) 패드를 얹고(16) 리드를 얹고(16) **다시 조용히 닫습니다**(8). 마지막 8마디가 첫 8마디와 같은 밀도이므로 **되감기 지점이 사건으로 들리지 않습니다.**

**Vorbis 블록 코덱의 길이 위험도 확인했습니다** — `oggdec` 로 디코드해 샘플 수를 대조합니다. 어긋나면 되감기 지점이 밀려 심리스가 성립하지 않습니다. 실측 일치.

## 4. OGG 재현 계약 — `oggenc` 는 기본적으로 비결정적입니다

**같은 입력·같은 설정이 매번 다른 바이트를 냅니다.** 원인은 **Ogg 스트림 시리얼**과 그것에 딸린 페이지 CRC — 두 회차 산출물의 차이가 정확히 **32바이트**였습니다.

**`--serial` 을 고정하면 3/3 동일**입니다. 그래서 시리얼을 트랙별로 `bgm_params.json` 에 커밋했습니다. **고정하지 않으면 `--check` 자체가 성립하지 않습니다** — 재생성이 매번 다른 파일을 내는데 바이트 대조를 걸 수는 없습니다.

**q 매핑:** D12 §10.1 의 "~q0.7" 은 libvorbis **정규화 품질**(−0.1~1.0)이고 `oggenc -q` 는 그 **10배 스케일**(0~10)이므로 **q0.7 = `-q 7`** 입니다. 실측 산출 122kbps.

**인코더를 PROVENANCE §4 에 갈라 적었습니다** — 벤더 사본은 리포 안에 있어 바이트가 고정되지만 **시스템 도구는 머신마다 다를 수 있습니다.** 버전이 바뀌면 `--check` 가 먼저 깨지므로 조용히 지나가지 않고, 깨졌을 때 판단할 근거로 표를 둡니다.

## 5. 자기 결함 2건 자수 — **둘 다 측정이 잡았습니다**

### ⓐ 룸톤 공존 규격을 스스로 어겼습니다

D11 §4.1 이 BGM-02 를 *"룸톤(AMB-04)과 공존 설계"* 로 두었고, `amb_04` 는 기음 72Hz·LPF 최저로 **저역만 남긴 지속음**입니다. 그 위에 서브 베이스·클럽 킥을 얹으면 같은 대역에서 싸워 룸톤이 진흙이 됩니다.

그래서 ①베이스를 룸톤 위로 올리고 ②타격을 킥이 아니라 **탭(180Hz 짧은 정현파)** 으로 뒀습니다 — **개러지의 맥동은 클럽의 4박이 아니라 공구가 규칙적으로 두드리는 소리**입니다.

**그런데 초판은 C 화음만 보고 "C3(131Hz) 한 옥타브 위"라고 적었고, F·G 의 베이스가 87.3Hz·98.0Hz 로 룸톤 대역 안에 있었습니다.** 대역 에너지를 재보니 ≤90Hz 가 **8.21%** 였습니다. 두 화음의 베이스를 한 옥타브 올려 **3.86%** 로 내렸습니다(베이스 4음 = C3 131 · A2 110 · F3 175 · G3 196). 베이스 윤곽이 후반에 들리는 형태로 바뀌는데, 개러지의 "온기"에는 그 쪽이 맞습니다.

**문면이 아니라 측정이 잡았습니다.** `intent` 에 규격을 적어 두고 데이터가 그것을 어기고 있었습니다.

### ⓑ 근사 측정이 답을 뒤집었습니다

첫 대역 분석은 계산을 줄이려 **4배 데시메이션 DFT** 를 썼는데, 그것이 5.5kHz 위를 앨리어싱해 **햇 대역을 68%로 오측**했습니다("햇이 믹스를 잡아먹는다"는 잘못된 결론이 나왔습니다). 순수 radix-2 FFT(4096점·해닝·창 12개)로 다시 재니 햇은 **0.08%** 였습니다. **근사가 답의 부호를 바꾸는 자리였고, 그 근사로 믹스를 고쳤으면 엉뚱한 데를 고쳤을 겁니다.**

> **부기:** 햇의 0.08% 는 **에너지 비율**이고 청감과 다릅니다 — 등청감 곡선상 4kHz 는 100Hz 대비 크게 부각되므로 에너지 비율은 햇의 가청도를 과소평가합니다. 그래서 수치만 보고 햇을 키우지 않았습니다. **판정은 귀 소관입니다.**

## 6. 기안 가정 1건 정정 — OGG 에는 그 함정이 없습니다

기안 §3 이 *"루프 임포트 설정 런타임 되읽기 확증(WAV `loop_mode` 함정 전례 — **OGG 임포터에도 동형 함정 가정하고 실증**)"* 을 요구했습니다. **가정은 성립하지 않습니다.**

OGG 임포터의 루프는 **열거가 아니라 불리언 `loop`** 이고, `loop=true` 를 적으면 런타임 `AudioStreamOggVorbis.loop` 이 `true` 로 읽힙니다(되읽기 실측). WAV 의 한 칸 어긋남은 열거 매핑 때문이었고 불리언에는 그 여지가 없습니다.

**대신 조용한 실패가 다른 자리에 있습니다** — OGG 임포터는 **박 정보 3항**(`bpm`·`beat_count`·`bar_beats`)을 따로 두고 기본값이 `0` 입니다. 적지 않으면 **박을 모른 채 임포트되고 아무 에러도 없습니다.** AUDIO-A 가 `beat_count/bpm×60 = 길이` 산술 정합까지 되읽어 그 자리를 막습니다.

**함정이 없다는 것도 실측 결과이며 잔여 트랙들은 이 판정을 승계합니다**(대장 §9-㉕ 종결).

## 7. 함정 2건 등재 — 둘 다 이번 회차에 당했습니다

### ⓐ 검사가 조용히 죽었습니다 — 그리고 게이트는 PASS 를 냈습니다

OGG 헤더 파서에 `bits` 키를 두지 않았는데 공통 축이 `header["bits"]` 로 읽었습니다. GDScript 가 **그 자리에서 스캔 함수를 중도 이탈**시켰고, **실패 0 · 보고 0 이 되어 `VALIDATORS_PASS` 가 찍혔습니다.**

**돌연변이(`loop=true`→`false`·꼬리 절단)를 넣었는데 통과하는 것이 이상해서** 파고들다 잡혔습니다 — 검사가 죽은 것을 검사가 알려주지 않았습니다.

**대처 2겹:** ①딕셔너리 접근을 전부 `get(기본값)` 으로 ②**완주 관문** — 스캔 말미에 `_aud_completed` 를 세우고 `_init` 이 확인해 없으면 실패시킵니다. `run_tests.sh` 의 *"성공 토큰의 부재 자체를 실패로 본다"* 와 같은 축입니다.

> **이번 실측의 요지: 차단형 검사에도 이 사고가 납니다.** 대장은 *"경고형 검사는 스스로 죽어도 빌드를 멈추지 못한다"* 로 적어 뒀는데, **차단형도 죽으면 멈추지 못합니다.** 차단/경고의 문제가 아니라 **완주 확인의 유무**입니다.

### ⓑ 돌연변이 원복에 `git checkout` 을 쓰면 미커밋 작업이 사라집니다

돌연변이를 원복하려고 `git checkout tools/validators/run_validators.gd` 를 실행했고, **그 파일에 담겨 있던 이 회차의 AUD 확장 전체(치환 10건)가 HEAD 로 되돌아가 사라졌습니다.** 재작성했습니다.

**원복은 시험 전에 떠둔 백업 사본으로 합니다.** 대장 §7 의 *"돌연변이 시험은 원복까지가 한 벌"* 에 **원복 수단**까지 포함시켰습니다.

## 9. 귀 판정 — 무엇이 기계 밖인가

기안 §2.2 가 경로 A 의 위험을 *"32비트 문법의 품질이 도구 한계에 걸릴 수 있음 — 그래서 파일럿"* 으로 두었습니다. **기계로 닿는 것은 전부 통과**했고, 남은 것은 다음 넷입니다.

| 판정 항목 | 왜 기계 밖인가 |
|---|---|
| 무드가 **"일상·정비의 온기"** 로 들리는가 | D11 §4.2 의 무드 방향은 문장이고 기계는 대역·길이만 봅니다 |
| **117초가 개러지 체류에 지루하지 않은가** | HUB 체류는 사람이 메뉴를 만지는 시간이고 실측 불가입니다 |
| 편성 아치가 **루프를 실제로 감추는가** | 이음매 0.89% 는 진폭 수치일 뿐 "되감긴 것이 들리는가"는 다릅니다 |
| **32비트 문법의 품질이 외주 대비 수용 가능한가** | 확대/전환의 분기점 자체입니다 |

**판정 결과에 따라:** 통과 → 잔여 12트랙(17스템 — A/B 포함) 확대 · 미달 → 외주 전환(**명세·무드 번역·검수 체계는 그대로 재활용**되며 A/B 박 동기 요건을 계약 문면에 넣는 것이 그때의 몫입니다).
