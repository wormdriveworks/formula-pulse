## 1. 산출물 — 값을 손으로 옮기지 않았다

| 파일 | 내용 | 커밋 형태 |
|---|---|---|
| `master_56.gpl` | 56 엔트리 | 평문 (LFS 아님·`.import` 없음) |
| `master_56.png` | 288×874 스와치 | **LFS + `.import` 커밋** |
| `colorblind_alt.gpl` | 56 + 교체 4 = 60 엔트리 | 평문 |
| `colorblind_alt.png` | 288×930 스와치 | **LFS + `.import` 커밋** |

**전사 검산 — 불일치 시 산출이 중단되도록 걸었다.** 정본 §1~§4의 hex를 기계 전사한 뒤 **인계 §2 본문의 RGB 56행과 전건 대조**했고, 함께 구성(16+12+16+12)·마스터 중복 0·기능 13·교체 4·hex 형식을 검사했다. 전건 통과.

**지시대로 지킨 3가지**
- `.gpl` 구분자 = **탭**.
- **기능 컬러 13색은 `.gpl`에 넣지 않았다** — 파일명 계약(`master_56`)이 56을 뜻하게 두고, 값의 정본은 `ui_palette.gd`에 남긴다.
- **심볼 6색은 스와치 PNG에 별도 구획으로 병기**했다. 아이콘 원도에 실제로 칠해지는 색이라 아티스트가 `.gpl` 밖에서 집을 수 있어야 한다.

**스와치 구성:** 마스터 4블록 + 기능 부속 13. 각 칩에 **ID와 hex 병기**. 색각 대체본은 마스터 4블록을 그대로 두고 `기능 13(CB 적용)` + `교체 4(기본▸대체 분할 칩)` 두 구획을 더했다 — 마스터 본체 무접촉이 눈으로 확인되게 했다.

## 3. 규칙 ⑦ 인용 교정 — 지적이 정확했다

원문 대조 결과 **D12 §10.1은 오디오 전속**이고 `.gpl`은 그 조항에 없다. 지시대로 **값은 그대로, 근거만** 고쳤다 — `.gpl`(팔레트) → **대장 §9-② 구현 재량**. `.wav`·`.ogg`의 D12 §10.1 인용은 정확하므로 유지했다.

덧붙이면, **§9-②가 옳았고 규칙 ⑦이 틀린 구조**였다. 대장은 §9-②에서 팔레트 형식을 [가안]으로 정확히 등재해 두고, 요약표인 규칙 ⑦에서만 네 확장자를 한 근거로 묶었다. 그래서 §9-②를 종결 처리할 때 "규칙 ⑦이 틀렸다"를 함께 적어 뒀다 — 다음 독자가 반대로 읽지 않도록.

**지적하신 유형 반복(이번 주 3건)에 동의한다.** D08 §8.11(35 vs 39) · D11 §2.9(18 vs 19) · 본 건 — 셋 다 **열거·집계는 맞고 요약·인용만 어긋난** 형태다. 대장 쪽에는 이 유형 표기를 §2에 남겨 뒀다.

## 4. 신규 보고 1건 — 색각 대체에서 `VANE-ALERT`만 미교체 (비차단)

정본 §6이 교체를 4색으로 확정했는데, **`VANE-ALERT`도 같은 적색 `#FF4A3D`인데 교체 대상에 없다.**

**대장 판단으로는 의도된 것으로 보인다.** 교체된 4색은 전부 **적록 축에서 충돌하는 쌍**의 구성원이다 — 심볼 라인(라임)↔트러블(적), 게이지 주의(앰버)↔위험(적). 반면 베인 4상태의 이웃은 평상 시안 `#12A6C4`·고양 `#FFD86B`·손상 무채 `#6B7686`이라 적록 충돌쌍이 아니다. 즉 최소 교체 원칙(§6 "이중 부호화가 1차 방어")과 정합한다.

**다만 경고(적)와 고양(밝은 앰버)의 2색각 근접은 계산으로 배제되지 않는다.** 파형 A·F·S가 1차 부호화이고 명도 차가 크므로 **비차단**으로 두고, 대장 §9-⑫에 등재해 **G-2 계열 실측(MS-5)** 트리거로 걸었다. 조치 요청 아님 — 판단 근거만 남긴다.

## 5. 질의 1건 — 스와치 생성기를 커밋할지 (비차단)

스와치 PNG는 손으로 그리지 않고 **생성기로 산출**했다(Node·zlib 내장 PNG 인코더 + 3×5 비트맵 폰트 — 시트 자체가 도트 규격이 되도록). 이 생성기를 **커밋하지 않았다.**

- **안 한 이유:** `tools/`는 에셋 트랙 소유 경로가 아니고(다중 세션 규약 — 새 디렉토리라 충돌은 없지만 방금 확정한 경계를 스스로 넓히는 모양이 된다), 산출의 진짜 원천은 `.gpl`이다.
- **대신:** 재현 규격 4항(탭 구분자·수록 범위·구획 구성·칩 표기)을 **대장 §4.9에 남겼다.** 팔레트 개정 시 이 4항이면 같은 시트가 다시 나온다.
- **질의:** 팔레트가 개정되면 스와치 2장을 다시 그려야 하는데, **`tools/palette/`에 생성기를 두는 편이 나은지** 판단 바란다. **권고 = 현행 유지(비커밋).** 팔레트 개정 빈도가 낮고, 손으로 그려도 되는 산출물이며, 경계를 넓히는 값이 그만큼은 아니다.

## 6. 실측 함정 1건 — **전 레인 공유** (대장 §7 등재)

`--headless --import`가 **에디터 동시 실행 시 죽는다.**

```
ERR [MCPServer] MCP server failed to start: Port 3571 is already in use.
EXIT = 0xC0000005 (접근 위반)
```

헤드리스 임포트도 GDAI 애드온을 적재하는데, 에디터가 이미 MCP 포트 3571을 점유 중이면 충돌 후 **접근 위반으로 종료**되고 `.import`가 생기지 않는다. 이번에 실제로 걸렸다 — 타 세션이 `race_screen.tscn`을 편집 중이었다.

> **대처: 에디터를 끄지 말고 에디터에게 시킨다.** GDAI `execute_editor_script`로 `EditorInterface.get_resource_filesystem().scan()`을 한 번 부르면 신규 파일이 임포트되고 `.import`가 생성된다. 이 경로로 팔레트 2종을 임포트했다. **3레인 병렬 상황에서 "에디터를 끄고 임포트"는 타 세션 작업을 끊는 조치라 쓸 수 없다.**

부수 확인 2건: **`.gpl`은 `.import`가 안 생기는 것이 정상**(Godot 임포터 없음 — 누락으로 오인 말 것) · 니어리스트는 `project.godot:35 default_texture_filter=0` 전역이라 파일별 오버라이드 불요.
