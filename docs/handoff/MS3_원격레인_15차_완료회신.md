## 1. 벽두 — `_resolve_tone` [가안] 해제

D12 **v1.4** §5.4 가 정조 태그의 정본 거처를 **VN 인스턴스 정의**로 확정하고 슬롯 종류 표의
`tone` 열을 **종류 기본값 폴백**으로 존치시켰으므로, 코드의 우선순위 4단
(인스턴스 > `milestone_vn` > `vn_slots` > `calm`)은 이제 임시 구조가 아니라 **정본의 이행**이다.
주석을 정본 문면으로 갈고 `[가안]` 표기를 걷었다. 진입음 주석의 판번 인용도 v1.3 → v1.4.

> **부기 (조치 안 함 — 16차 벽두 배정분).** `_resolve_tone()` 이 `slot_id` 공란으로 불릴 때
> `vn_slot("")` 가 `push_error` + `_load_ok = false` 를 낸다. 총괄 판정 IMPL-263 ⑤ 가
> **16차 벽두**로 배정한 건이라 이번 회차 범위 밖으로 두었다 — 회차 중 재현을 확인했고
> (UISCR ⑭축 실행 로그) 한 줄 가드로 닫힌다.

## 2. ①~④ 데이터·규칙 유입 (IMPL-266 · IMPL-267)

### 2.1 20키 전사 — 편입 전 독립 재계산

납품 값을 그대로 옮기되, **총괄·내러티브와 독립으로 폭을 다시 쟀다**(`_weighted_chars` 재현).

| 검사 | 결과 |
|---|---|
| 표기 폭 vs 재계산 | **불일치 0** — 선택지 7.5~12.0 / 반응 8.5~18.0 |
| 상한 | 선택지 14 초과 **0** · 반응 24 초과 **0** |
| 키 문법 | V8 정규식 fail **0** (`vnChoice` 첫 세그먼트 = 소문자 시작 성립) |
| 값 위생 | 콤마 **0** · 줄바꿈 **0** · V7 금칙 6어 **0** |

배치 = 반응 10키는 **각 막 블록 말미**(1막 beat12 뒤 등)에, 선택지 10키는 `vn.` 블록 뒤
**신규 도메인 블록**으로. 687 → 711행.

### 2.2 자수 규칙 — 행 순서를 `vn.` 앞에 둔 것은 의도다

`_write_rule_for()` 는 **첫 일치 규칙**을 돌려준다. 지금은 접두가 `vn.`(점 포함)이라
`vnChoice.` 와 충돌하지 않지만, 접두가 한 글자라도 느슨해지는 날 선택지가 24폭 규칙으로
조용히 넘어간다. 그래서 더 좁은 규칙을 앞에 뒀다.

**규칙이 실제로 무는지는 값으로 확인했다** — 18.0폭 주입이 FAIL 됐다. 그 값은 `vn.` 24폭
규칙 아래였다면 **통과했을 값**이다. 규칙 행이 실제로 그 도메인을 잡고 있다는 뜻이다.

### 2.3 `act_vn.json` 배열 스펙 — 판정 요청 1건 동반

`arrays: {entries: {id, act int:1,4, tone enum:calm,tense, order int:1,9}}` 편입.
표 2곳에서는 차단되고 구조에서는 새던 `tone` 비대칭이 닫혔다(실측 — 도메인 밖·범위 밖 주입 전건 FAIL).

> **[판정 요청 ①] `enum` 은 공란을 허용하지 않는다 — 인스턴스 층에서 `tone` 이 필수가 된다.**
> D12 v1.4 §5.4 는 **"미지정 = `calm`"** 을 명문하는데, 채택된 스펙 문안(`enum:calm,tense`)은
> 공란을 **빌드 실패**로 만든다(실측 M21). 현행 6건이 전건 명시라 위반은 0이고 지금 새는 것은
> 없지만, **기계가 정본보다 엄한 상태**다.
> ⓐ 현행 유지(인스턴스는 항상 명시 — 폴백은 표 층 전속) / ⓑ `enum_optional` 로 정본의 관대함
> 반영(공란 = 미지정 = `calm` 폴백 성립) 중 판정 바란다. 구현이 정할 사안이 아니다(불변규칙 9).

### 2.4 두 표 신설 + 기계가 못 보는 열 하나

`option_count: int:2,3` 으로 D04 §5.3 "지점당 2~3개"가 **기계 강제로 승격**됐고,
`fk` 로 고아 옵션이 0으로 닫혔다. 다만 **`vn_id` 는 기계가 보지 못한다** — 납품서 실독대로
`_structure_ids()` 가 구조 파일의 **루트 id 만** 모으므로 `entries[].id` 는 FK 후보에 없다.

그 자리를 **적재 층 가드**가 닫는다. 지점이 가리키는 VN 과 그 안의 앵커 라인을 실제로 찾아
보고, 없으면 `push_error` + 그 행을 버린다(부모 잃은 옵션도 함께).

- **버려도 `_load_ok` 를 내리지 않은 것은 의도다** — 지점 하나 때문에 게임이 서면 안 된다.
  대신 **"생략 0"을 회귀 축**으로 세워 오타가 게이트를 통과하지 못하게 했다.
  런타임은 관대하게, 게이트는 엄하게.
- **적재 순서가 규격이다** — `_load_vn_choices()` 는 `act_vn` 적재 **뒤**여야 한다. 앞에 두면
  대조 대상이 비어 **4지점 전건이 조용히 생략**된다(돌연변이 M10 실측).

### 2.5 함정 등재 — 신규 CSV 의 기본 임포터는 `csv_translation` 이다

`--headless --import` 가 두 표를 **번역 리소스로** 임포트해 `.translation` 6개를 만들었다.
기존 31표는 전건 `importer="keep"` 다 — 테이블 CSV 는 코드가 파싱하는 데이터지 번역원이 아니다.
`.import` 를 `keep` 으로 못박고 산출물을 걷었다(재임포트 후 재생성 0 확인).

> **신규 표를 추가하는 회차마다 재발하는 자리다.** 파일을 만들기만 하면 조용히 성립하고,
> `.import` 를 커밋하는 규약(IMPL-003·021) 때문에 **잘못된 임포터가 그대로 리포지토리에 박힌다.**

## 3. ⑤ 선택 흐름 결선 — **씬 선행 없이 착수했다**

발주는 "노드 부재 가드 방식이면 착수 · 씬 의존이 불가피하면 착수 금지"로 갈랐다.
**가드 방식이 성립한다**는 것이 실측 결론이다.

| 항목 | 구현 |
|---|---|
| 씬 계약 | `ChoiceOverlay`(Control) + `ChoiceList`(Container) — **주력이 규격대로 놓기만 하면 코드 변경 0으로 발동** |
| 탐색 시점 | `find_child()` 를 **호출 시점에** — 화면 생성 시점에 묶지 않아 씬 의존이 사라진다 |
| 노드 부재 | 지점 **생략** + `push_error` + `choice_omissions` 배열(기계 관측 지점) |
| 합류 | **장치를 두지 않았다** — 반응 라인 1개를 앵커 **바로 뒤**에 끼우는 것이 전부다 |

**합류에 장치가 없는 이유.** 분기가 0이므로(D01 §8-5) 반응을 끼운 다음 라인부터는
아무 일도 없었던 것과 같다. 복귀 상태·합류 지점 지정 같은 것을 두면 그 상태가 곧 **없어도 되는
분기 흔적**이 된다.

### 3.1 "진행 잠금 금지"를 어떻게 읽었는가 — 명기

납품서 §3 구현 규격 2항("선택 대기 상태가 진행을 잠그면 G2 조건 2가 역전된다")은 두 갈래로 읽힌다.

- **(ⓐ 채택)** 진행 입력은 **소비하지 않고** 입력을 기다린다. 막다른 길이 되지 않는 근거는
  **스킵이 지점 위에서도 살아 있기 때문**이다.
- (ⓑ 불채택) 진행 입력 = 지점 건너뜀.

ⓑ를 택하면 **연타하는 플레이어는 선택지를 한 번도 보지 못한다.** 같은 문서 §3.3 이
*"자동 진행은 선택 지점에서 정지하고 입력을 기다린다가 유일한 해"* 로 도출한 것과 정면으로
어긋난다 — 자동이 하면 안 되는 일을 진행 입력이 하는 셈이다. 조항의 취지는
*"스킵이 페널티가 되면 안 된다"* 쪽이고, 그것은 ⓐ에서 스킵 생존으로 성립한다.

스킵 시 **반응 미재생 · 의사 미기록** — "고르지 않은 것을 1번으로 적으면 '선택했다'가 거짓으로
생긴다"(§3.1-③)를 그대로 이행했다.

### 3.2 자기 위반 1건 — 돌연변이가 잡았다

초판이 관측 로그를 `push_warning` 으로 냈다. **ARCH '코어 표준출력 금지'가 `godot/ui` 를 범위에
넣고 `push_warning` 을 금칙에 두면서 `push_error` 만** "값 누락 보고에 정당한 용도"로 뺐다.
돌연변이 M1 주입 시 무관한 ARCH FAIL 2건이 떠서 발견했다 — **검증기를 그 시점에 돌리지 않았다면
게이트가 붉은 채로 진행할 뻔했다.**

교정 후 다시 읽으면 총괄 판정 문면(*"`push_error` 아닌 조용한 생략 금지"*)도 그렇게 읽어야
정합한다: 관측 채널은 `push_error` 가 규정된 자리다.

### 3.3 UISCR ⑰축 — **두 상태 모두**를 본다

부재만 보면 주력이 노드를 세운 날 결선이 끊긴 것을 아무도 모르고, 실재만 보면 지금 화면이 멈춘다.

- ⓐ **부재**(현행 씬 실물): 앵커에서 생략 관측 1건 · 진행 잠기지 않음(다음 라인 도달)
- ⓑ **실재**(검사가 계약대로 스텁 주입): 지점 발동 · 버튼 수 = `option_count` · 문면 = 데이터 값
  (대괄호 포함) · **선택 대기 중 진행 입력 무소비** · 스킵 생존 · 반응 재생(화자 포함) · 합류 복귀
- ⓒ **지점 위 스킵**: 화면 이탈 · 오버레이 닫힘 · 반응 미재생

## 5. 판정 요청 2건 · 인계 2건

### [판정 요청 ①] `act_vn.json` `tone` 이 정본보다 엄해졌다 (§2.3)
`enum` vs `enum_optional` — 현행 위반 0.

### [판정 요청 ②] 선택 지점 위 진행 입력의 성격 (§3.1)
ⓐ(대기·스킵 생존)로 구현했다. 문면이 두 갈래로 읽히고 §3.3 도출과의 정합으로 ⓐ를 택한
것이므로, **읽기 자체를 추인하거나 뒤집어 주기 바란다.** ⓑ라면 UISCR ⑰ⓑ 한 축과
`_advance()` 두 줄이 바뀐다.

### [인계 ①] 주력 11차 — 오버레이 씬 노드
계약은 **이름 2개뿐**이다: `ChoiceOverlay`(Control · 초기 `visible = false`) 와 그 아래
`ChoiceList`(Container — 버튼 레이아웃은 컨테이너가 한다). 이름만 맞으면 코드 변경 0으로 발동하며,
UISCR ⑰ⓑ가 이미 그 계약으로 돌고 있다. 규격 = D09 별첨A §A-19 E05.
**부기:** 스킵 버튼(우상단)을 덮지 않는 자리에 두어야 한다 — 지점 위 스킵 생존이 규격이다.

### [인계 ②] 사운드 결선 발주 접수 (IMPL-264)
회차 중 `docs/handoff/사운드결선_원격발주.md` 유입을 확인했다. **미착수** —
본 회차 범위 밖이며 16차 배정분(VN 소비부 결선)과의 순서는 총괄 판정을 기다린다.

---

## 6. 이월 (변동분만)

- **16차 최우선** = 막 VN 표시 소비부 결선(`lines`·`tone` 필수 동반 — IMPL-263 ①) + 1막 개시 슬롯 발화
  + `_resolve_tone` 공란 슬롯 가드. **선택 지점은 그 결선에 자동으로 얹힌다** — 페이로드가
  `vn_id` 와 라인 열을 넘기는 순간 4지점이 도달 가능해진다(현재는 소비부 자체가 없어 미도달).
- 검사기 중첩 배열 재귀(`lines` 2단 미검사) = 이월 유지 · E04 결선 시 선택 지점 정지 = 이월 유지.
- 기존 이월(스킬 슬롯 소비부 · [가안] 묶음 · SYS-04 초기 포커스 · 무커리어 달성 0) 변동 없음.
