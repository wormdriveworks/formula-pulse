## 2. 판정 요청 A — SYS-04 항목 행의 3요소, 소재가 없다

D09 §A-4 는 항목 행을 **아이콘 · 명칭 · 조건 · 달성 일시**로 규정하고 §5.5 도 '달성/미달성 · **달성 일시**'를 명문화한다. 이 중 **명칭만 소재가 있다.** 자리를 비워 둔 것이 아니라 채울 것이 없다.

| # | 요소 | 부재 내용 | 성격 |
|---|---|---|---|
| A-1 | **달성 일시** | `outgame.achievements` 는 `id → true` 뿐이고, 리포 전체에 벽시계 개념이 `SaveManager.saved_at` 외에 없다. 더 근본적으로 **재로드 시 `evaluate_achievements()` 가 현 상태로 재판정해 소급 달성이 성립**하므로(코어 주석 명문) 해제 시각을 찍어도 실제 달성 시점과 어긋난다 | **설계 판단** |
| A-2 | **아이콘** | D10 §8.2 리소스 목록에 업적 아이콘 항목 자체가 없다(미계상) | 에셋 계상 |
| A-3 | **Steam 도전과제 동기 상태** | `IAchievement`·`DesktopAchievement` 는 있으나 `desktop_services.gd` 에만 있고 **세션에 배선되지 않았다.** 어댑터를 화면 층에 어떻게 넣을지는 D12 §2.2 구조 결정 | 구조 결정 |

**A-1 에 대한 관측 (판정 재료):** §5.5 의 칭호 이력 문면 규격이 `[칭호명] — 달성 (시즌 N)` 으로 **인게임 시즌**을 시각 축으로 쓴다. 소급 재판정 구조와도 충돌하지 않는다(시즌은 세이브에 있고 되돌아가지 않는다). 벽시계 일시를 새 필드로 두면 직렬화·마이그레이션이 따라붙고, 소급 달성분의 값이 무엇인지부터 정해야 한다.

- **판정 ①:** 시각 축 = 인게임(시즌 N) → 표시 층에서 즉시 처리 가능, 정본 개정 0, 코어 필드 1개(달성 시즌) 신설
- **판정 ②:** 시각 축 = 벽시계 → 코어 필드 + 직렬화 + 구세이브 관용 규칙 + 소급분 처리 규칙이 필요
- **판정 ③:** 달성 일시 열 자체를 두지 않음 → D09 §5.5·§A-4 문면 개정 사안으로 승격

A-2·A-3 은 판정이라기보다 **계상·배선 트랙 배정** 요청이다 (아이콘 = D10 차기 개정 / 어댑터 배선 = 원격 구조 몫으로 볼 여지).

## 3. 판정 요청 B — CG-03 '첫 순위 역전 인접 듀얼'의 판정 규격

인계 ⑤는 "L3 컷인 재생(T6)에서 **1줄 연결**"을 전제했으나, **전제가 성립하지 않았다.**

- `trigger_signature_event` 는 **테스트에만 존재**했고 production 발화 주체가 0건이었다.
- 즉 L3 발동 판정 자체가 없어 `record_discovery` 를 걸 지점이 없었다.

D10 §7 결정 #6 이 3종의 조건을 확정해 두었으므로 **조건이 온전히 서는 CG-01 만 결선**했다. 나머지 2종:

| CG | 조건 (D10 §7) | 상태 |
|---|---|---|
| CG-02 재회·카이 | '대면' 도달 듀얼 | **데이터 차단** — 재회 축이 `relation_axes.csv` 에 부재(현행 3축). T7 서사 유입 의존 (IMPL-113 §5와 같은 축) |
| CG-03 동기·주드 | **첫 순위 역전 인접 듀얼** | **규격 부재 — 판정 요청** |

**CG-03 질문 2개:**
1. **'인접'의 기준은 무엇인가?** — 챔피언십 순위 차 1인가, 그 GP 내 주행 순위 인접인가. (엔진에는 IMPL-114 가 신설한 `jude_rank_delta` = 챔피언십 순위 차 컨텍스트가 있다)
2. **'첫 순위 역전'의 래치 지점은 어디인가?** — 챔피언십 순위가 처음 주드를 앞선 시점인가, 그 상태에서의 첫 듀얼인가.

임의 해석 금지(불변규칙 9)로 미착수 상태다. 판정이 오면 CG-01 과 같은 구조로 즉시 붙는다.

**부기 — 연출은 여전히 미결선:** 도트 CG(CG-01~03) 미유입이라 컷인 **재생**은 T6 몫이다. 이번에 닫은 것은 기록·정보 축뿐이다(조우 자체는 성립했으므로 기록을 미루지 않았다).

## 4. 보고 — HUB-08 표시-상태 괴리 가능성 (잠복·비차단)

요약행의 '후보 N' 은 `overhaul_slots(_rank)` 가 돌려주는 **규칙값**인데, 목록은 `outgame.overhaul_candidates` 라는 **추첨 결과**다. 두 축의 rank 가 어긋나면 헤더가 목록과 다른 수를 말한다 — 검증 하네스가 진입 payload 키를 틀렸을 때 **'후보 4 · 목록 5행'** 으로 실제 재현됐다.

정상 경로에서는 `close_season()` 의 추첨 rank 와 진입 payload 가 같아 드러나지 않는다. 다만 **HUB-08 의 유일 진입인 SET-02 가 아직 없어** 그 계약이 굳지 않았다. 헤더 수치를 추첨 결과 크기에서 끌어오면 구조적으로 갈릴 수 없다 — **SET-02 결선 시 동반 판단 대상**으로 올린다.

**인계문 오기 1건:** §1-③ 이 '**HUB-05** 스킬 티어 개방'이라 적었으나 D09 §8.1 대장상 HUB-05 = 기록실(3탭·§A-15)이고 스킬·덱은 **HUB-04 전략실(§A-14)** 이다. 인계문이 병기한 §A-14 쪽이 맞다.

## 5. 부수 소득 — 선재 결함 1건 적발·교정 (IMPL-125)

**코드로 만든 Control 이 본문 폰트 9 가 아니라 엔진 기본 16 으로 서 있었다.**

`gui/theme/default_font_size=9` 는 **씬에 놓인 노드에만** 먹는다. `Label.new()`·`Button.new()` 로 런타임 생성한 Control 은 엔진 기본 테마의 16 으로 해석된다(실측: `get_theme_font_size("font_size")` = 씬 노드 9 · 코드 생성 **16**).

**SYS-03 옵션 화면이 이 상태였다** — 탭 5개와 전 옵션 행(라벨·값·◀▶·O5 고지행)이 16px, 씬에 박아 둔 초기화·닫기 버튼만 9px. D10 §5.7 본문 계열 9 위반이고 한 화면 안에 두 크기가 섞여 있었다.

- **교정:** `param_font_size_body` 를 데이터 창구에서 읽어(불변규칙 2 — 코드에 9를 적지 않는다) 코드 생성 컨트롤 전량에 `add_theme_font_size_override`. 전례 = `log_feed.gd`.
- **적발 경위:** SYS-04 첫 캡처에서 행 텍스트가 씬 노드인 요약 라벨보다 커 보였고, 눈대중으로 단정하지 않고 폰트 크기를 찍어 16을 확인한 뒤 SYS-03 을 같은 방법으로 대조해 선재 결함임을 확정했다.
- **범위 판단:** 인계 배정 밖이나 (a)같은 계열·같은 층이고 (b)교정이 3행이며 (c)총괄이 방금 공통 바 폰트로 D10 을 개정한(IMPL-117) 직후라 남겨 둘 이유가 없어 동반 처리했다. **되돌리려면 커밋에서 `options_screen.gd` 만 떼면 된다.**
- **미점검 잔여:** 코드로 컨트롤을 만드는 다른 화면(HUB 계열 카드 등)에 같은 축이 남아 있을 수 있다 — 전수 점검은 별건으로 둔다.
