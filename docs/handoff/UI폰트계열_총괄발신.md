# UI 폰트 계열 배정 판정 요청 — HUB 공통 바 재화 수치 (2026-08-16)

> 작성: 주력 GUI 레인 · 대상: 총괄 (마스터플랜 §0.8 절차)
> 성격: **문면 해석 판정 요청 1건.** 신규 수치 제정 요청도, 정본 개정 요청도 아니다 —
> D10 §5.7 적용 대상 문면의 '헤더'에 HUB 공통 바가 포함되는지만 판정하면 된다.
> 판정이 ①이면 구현 레인이 정본 무개정으로 즉시 처리하고, ②면 개정 여부를 총괄이 판단한다.
> **차단성:** 없음 (MS-3 착수 무관 — 표현 층 국소 사안).

---

## A. 판정 요청 (단일)

**질문: D10 §5.7 대형·VN 계열의 적용 대상 "VN 대사창·선택지·헤더·결산" 중 '헤더'에, HUB 8화면 상단의 공통 바(재화 2종 아이콘+수치·시즌/투어 표기)가 해당하는가?**

| 판정 | 귀결 | 처리 주체 |
|---|---|---|
| ① 해당한다 | 공통 바 수치에 대형 계열(현행 실물 14px) 적용 — **정본 개정 0** | 구현 레인 즉시 처리 |
| ② 해당하지 않는다 | 현행(본문 계열 9px) 유지가 정본 정합. 시각 균형을 조정하려면 D10 §5.7 적용 대상 표 개정이 필요 | 총괄 판단 |

사용자 요청은 "아이콘은 그대로 두고 텍스트를 키운다"이며, 아이콘 축소안은 **사용자가 배제**했다.

---

## B. 배경 — 실측 (2026-08-16, 1920×1080 캡처 픽셀 측정)

HUB 공통 바에서 재화 아이콘과 수치의 크기 차가 크다는 사용자 지적이 있었다. 실측값:

| 대상 | 잉크 높이 (device) | 캔버스 환산 |
|---|---|---|
| 크레딧 아이콘 (`currency_credit.png`) | 81px | **27px** |
| 재화 수치 `2000` (본문 9px) | 24px | **8px** |
| 화면 제목 (대형 14px) | 39px | **13px** |

→ 현재 아이콘 : 수치 = **3.4 : 1**. 대형 계열 적용 시 **2.1 : 1**로 완화된다.

**부기 (판정 무관·전제 공유):** 아이콘 측 결함은 없다. 32×32 원도가 캔버스 32px에 1:1 무배율로 그려지고 캔버스만 ×3 정수 확대되는 정합 상태다 — 직전 세션이 비정수 축소로 보고했던 건은 **오진이었고 철회했다**(IMPL-106).

## C. 왜 레인 단독 판단으로 처리하지 않는가

1. **폰트 크기는 확정 기준값이다.** D10 §5.7이 2계열 3단(본문 8/9/10 · 대형 12/14/16)을 확정했고 D13 별첨A §10이 "채택"으로 전사했다. 값의 유일 창구 = D13 (불변규칙 2).
2. **어느 요소가 어느 계열인지도 D10 §5.7이 지정한다** — 본문 계열 적용 대상 = "레이스 로그·메뉴·**라벨**·툴팁". 공통 바 수치를 라벨로 보면 본문 계열이고, 헤더로 보면 대형 계열이다. **문면 해석이 갈리는 지점이므로 임의 해석 금지**(불변규칙 9)에 걸린다.
3. **대안(본문 계열 base 상향)은 구조를 건드린다** — 아래 §D 참조.

## D. 선택지 영향 분석 (총괄 판단 재료)

### 안 1 — 공통 바를 대형 계열로 (판정 ①일 때)
- 영향 범위 = HUB 8화면 공통 바 + RUN-02 보상 행. **로그 존·VN·툴팁 무영향.**
- 정본 개정 0 (판정 ①이면 기존 문면 안). 데이터 무변경(`param_font_size_head` 14 그대로 사용).
- **권고안.** 영향이 국소적이고 되돌리기 쉽다.

### 안 2 — 본문 계열 base 9 → 10 (전역)
- **로그 존 자수 규격과 직결.** IMPL-080·082 실측: 로그 슬롯 본문 가용 폭 **226px**, 전각 22자 = 8px:176 · 9px:198 · **10px:220** · 11px:242(초과).
  → 10px는 여유 6px로 통과하나 **그 위 단이 없다.**
- **O7(텍스트 크기 100/115/130%) 매핑을 소진한다.** D10 §5.7의 3단 = O7 3단이다. 현재 base가 9(중간단)라 위로 10 하나가 남아 있는데, base를 10으로 올리면 **O7 상향 여지가 0**이 된다. O7은 아직 소비부 미결선(IMPL-087)이라 지금은 드러나지 않지만, 결선 시점에 막힌다.
- 자수 22자(D04)·시각 줄 2(D09)는 **불변**이므로 조정 창구는 로그 존 폭(D13)뿐이다.
- → **비권고.** 국소 문제를 전역 구조 소진으로 해결하게 된다.

### 안 3 — 아이콘 표시 축소
- **사용자 배제.** 참고로 기술적 귀결만 적으면, 상자를 줄이려면 `expand_mode` 변경이 동반되고 그 순간 32×32가 ÷2 다운샘플되어 디테일이 절반 소실된다. 손실 없이 줄이려면 재화 전용 16×16 원도 별도 제작이 필요하다(에셋 배치 대장 §4.1).

## E. 판정 후 처리 (레인 분담)

- **판정 ①:** 구현 레인이 공통 바 라벨의 `font_size`를 `param_font_size_head`(14) 참조로 전환한다. 코드에 수치를 기입하지 않고 데이터 참조로 잇는다(불변규칙 2). 대상 = HUB 8화면 `.tscn` + `event_node_screen.tscn` + 코드 생성 2개소. 캡처 눈 검증 + 검증기·테스트 전건 동반.
- **판정 ②:** 현행 유지. 시각 균형 조정을 계속 원할 경우 D10 §5.7 적용 대상 표 개정 안건으로 승격 요청.
- 어느 쪽이든 **D13 수치 신설·변경은 발생하지 않는다** (14는 기확정·기전사값).

---

## F. 참고 — 현행 구현의 base단 (전제 공유, 판정 무관)

D10 §5.7의 100% 단은 본문 8 · 대형 12이나, 구현은 **본문 9 · 대형 14**를 base로 쓴다(`core_params.csv`). 사용자 제공 Galmuri 실물이 9/11/14뿐이어서 계열 내 최근접 단을 택한 결과이며(IMPL-082 확정), D13 별첨A §10이 계열 전체를 "채택"으로 전사했으므로 계열 내 값이다. 본 발신은 이 기확정 사항의 재론이 아니다.
