## 2. 작업 ② — 결선 2군

### ①-1 업적 6종 → 항목 행 **완료**

§A-4 "항목 행 = 아이콘·명칭·조건·달성 일시" 대로 아이콘 열을 신설했다. 대장이 A-UI-22~26 을 **카테고리 이름**으로 배정했으므로 매핑은 카테고리 1:1 이다 — 아이콘은 업적의 정체가 아니라 소속 축의 표지이고, 39행이 5종을 나눠 쓰는 것이 규격대로다. 달성 조회는 `_achieved()`/`_progress_for()` 창구 경유 그대로 유지했다(IMPL-177 구조 무접촉).

**히든 미달성 행 = 공용 도상 `achv_hidden` — [가안] · 판정 요청.**

§5.5 문면은 *"명칭·조건·아이콘 전부 비노출"* 이라 **아이콘을 비우는 독법도 성립한다.** 공용 도상을 택한 근거 3:

1. 대장 A-UI-27 이 이 도상에 **"업적 히든 (미달성 공용)"** 용도를 명시했다 — 비운다면 이 에셋의 소비처가 영구히 0이 된다.
2. **카테고리 도상을 그대로 쓰는 것이 오히려 누출이다** — 탭 위치와 합치면 후보가 좁혀진다. 공용 도상은 카테고리조차 가린다.
3. 발신 §2 가 "**업적 6종** 결선"과 "히든 아이콘 은닉"을 함께 지시했다 — 둘이 동시에 성립하는 독법이 이것뿐이다.

뒤집으려면 `_build_row()` 의 히든 분기 1줄이다.

**등배 고정:** 원도 32×32 를 축소하지 않는다(비정수 배율 = 믹셀 — D10 §2.2·D12 §9.1). 그 대가가 §6-③ 의 행 높이 문제다.

**감광 없음:** 달성/미달성으로 아이콘을 감광하지 않았다 — 상태는 표기 열과 명칭 색이 이미 지고 있고 아이콘은 카테고리 축이다. 감광이 필요하다는 판단이 서면 그것은 배율 신설이므로 총괄 경유다(IMPL-195 전례).

## 3. 작업 ③ — 결선 후 실배치 재판독

### ① 업적 6종 + `achv_rival`

- **아이콘 열 성립.** 커리어 탭 전 행에 월계관(`achv_career`)이, 라이벌 탭 전 행에 헬멧 2개(`achv_rival`)가 뜬다. 카테고리 표지로 읽힌다.
- **`achv_rival` 세로 11px 납작 = 실배치에서 확실히 드러난다.** 같은 목록에서 `achv_career`(세로 22px)가 슬롯을 채우는 데 비해 헬멧 2개는 **가로 띠**로 앉는다. 32px 슬롯 안에서 위아래 여백이 10px씩 남아 홀로 작아 보인다. **판정 요청** — 재작업(세로 확장) 대상인지.

## 6. 부수 발견 3건

### ① [실사용] 활성 탭 표시가 없다 — LB/RB 가 "먹지 않는 것처럼" 보인다

`_select_tab()` 은 **패널 visible 만 토글**한다(`achievement_screen.gd:337` · `options_screen.gd:220` 동형). 탭 버튼에 활성 상태 표시가 없다.

- 마우스·키보드로는 눌린 탭에 포커스 링이 남아 우연히 활성 표시처럼 보인다.
- **LB/RB 로 돌리면 내용만 바뀌고 탭 줄에서는 아무것도 움직이지 않는다.** 실측 — 커리어 탭에 링이 남은 채 내용이 라이벌로 갔다.
- 발신 §5 가 "LB/RB 탭(감김 [가안] 감각 포함)"을 실기 항목으로 지목했는데, **표시가 없으면 그 감각을 판정할 대상 자체가 없다.**

D09 는 활성 탭의 시각 표시에 침묵한다. 2화면 공통이고 [가안] 신설이므로 판정 요청으로 올린다.

### ② [표시] 필러 대상 로그 3종에서 `{number}` 가 치환되지 않는다

실기 관측 문면: **`No.{number} 머신 리타이어.`**

`race_engine.gd:570-571` 이 규약을 주석으로 적어 두었다 — *"number 는 필러 name_key(`No.{number} 머신`)의 표기 매개다 — 표기 층이 name_key 를 번역할 때 함께 치환한다"*. 그런데 **그 매개를 넘기는 곳이 듀얼 개시 1곳뿐**이다.

| 발행 지점 | `number` 전달 |
|---|---|
| `:573` `duelStartOvertake01`/`duelStartDefense01` | ✅ 있음 |
| `:680` `overtakeSuccess01` | ❌ 없음 (`target`+`rank`) |
| `:682` `defendSuccess01` | ❌ 없음 (`target`) |
| `:829` `aiRetire01` | ❌ 없음 (`target`) |

**네임드 라이벌은 문면에 자리가 없어 무해하므로 필러가 대상일 때만 드러난다** — 그래서 여태 안 잡혔다. `core/state/race_engine.gd` 는 원격·코어 소관이라 보고만 한다. 고칠 자리는 3줄이다.

### ③ [밀도] 32px 등배 아이콘이 행 높이를 3배로 만든다

믹셀 금지를 지키면(등배) 9px 텍스트 행이 32px 행이 된다.

| 화면 | 영향 |
|---|---|
| SYS-04 항목 행 | 360 캔버스에 **6.5행**만 든다(종전 ~10행). 39행 스크롤 길이가 3배 |
| RACE-01 로그 피드 | 슬롯 4개가 기존 ~96px → **128px+**. 존 여유는 있으나 행간이 크게 벌어져 피드가 헐렁하다 |

**규격을 지킨 결과이므로 구현이 되돌리지 않았다.** 선택지는 셋이고 전부 판정 사안이다: ⓐ 그대로 수용 ⓑ 16px 원도 별도 발주(정수 2:1 축소는 절반 정보 손실이라 원도 신설이 정직하다) ⓒ 행 레이아웃을 아이콘 크기에 맞춰 재설계(§A-4 재개정).
