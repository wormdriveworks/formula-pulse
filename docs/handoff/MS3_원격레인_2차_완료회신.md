## 1. 이번 작업의 실질 소득 — 선재 결함 37건 (인계 ⑥)

FONT 검사를 신설하자마자 **12개 화면 37지점**이 걸렸다. 전부 이미 커밋돼 있던 것이다.

| 축 | 건수 | 성질 |
|---|---|---|
| FONT-A 오버라이드 부재 | **34** | 코드 생성 Control 이 프로젝트 기본 폰트를 상속하지 않고 **엔진 기본 테마 16** 으로 해석된다. 640×360 캔버스에서 16 은 레이아웃을 깨뜨린다 |
| FONT-B 크기 리터럴 기입 | **3** | 값 창구 우회 (불변규칙 2) — `run_recap_screen.gd` |

**왜 눈으로는 안 잡혔나.** `.tscn` 노드는 프로젝트 테마를 정상 상속한다. 같은 화면 안에서 씬 노드는 멀쩡하고 **코드로 만든 행만** 크게 나오므로, 화면을 훑으면 "행 간격이 좀 넓네" 정도로 보인다. v2.35 ⑧의 "눈으로 훑으면 또 샌다"가 정확했다.

**결선 방식 — 값 조달을 베이스로 올렸다.** 화면마다 `_body_font_size` 를 선언·조달하던 형태(2건 실재)를 `FlowScreen` 이 `bind()` 에서 **`_on_bound()` 보다 먼저** 한 번만 채우는 구조로 바꿨다. 화면 초기화가 이 값으로 Control 을 만들기 때문에 순서가 규격이다. `ConfirmDialog` 만 화면이 아니라 컴포넌트라 인자로 받는다(호출 4지점 동반 수정).

## 2. 오디오 디스패처 (인계 ② — 최대 병목)

### 무엇을 만들었나

| 층 | 내용 |
|---|---|
| 데이터 | `sound_map.csv` **86행** = SFX 채널 68(D11 §2.11 총계) + BGM 13(§4.1 — 예비 1은 미배정이라 행 없음) + 징글 5 |
| 정책 | `AudioDispatcher` — 봉인 / 재트리거 게이트 / 가상 채널 상한·P3 컬링 / P1 보호 |
| 출력 | `AudioOutput` — **기본 구현이 곧 무음 폴백** |
| 검사 | `test_audio.gd` 354검사 (표 전수·이벤트 결속·정책 4종·값 출처) |

### 설계 판단 3건

**① 사운드는 표 경유로만 발화한다.** 호출부는 이벤트 id 만 던지고 무엇이 울릴지는 `sound_map` 이 정한다. 코드가 SFX id 를 직접 들고 재생하는 경로를 두지 않았다 — 그래야 '씬 컷 전용 SFX'가 **구조적으로 생겨날 수 없다**(D11 §1.4 → C-A2). 검사도 이 축으로 짰다: 무대 5종 BGM 결속은 무대 목록을 손으로 적지 않고 `content_manifest` 에서 끌어와, 무대가 늘면 검사가 같이 걸린다.

**② 봉인을 디스패처가 강제한다.** 호출부가 지키는 규약이 아니라 **호출부가 어겨도 통과 못 하는 층**이다. 릴 정지 연출 완료 전에는 `seal_gated` 행(매치음 2 · 결과음 6 · 스팅 3 · 함성 1)이 어떤 경로로도 나가지 않는다. 주력이 SFX 호출을 화면에 붙일 때 잘못 걸어도 여기서 막힌다.

> **봉인 기록의 함정 하나를 닫았다.** 차단된 사운드의 id 를 로그에 남기면 그 로그 자체가 결과 상관 신호의 디버그 노출 경로가 된다(불변규칙 5는 디버그 오버레이를 명시 포함). **차단은 건수만 센다.**

**③ 무음 폴백이 기본 구현이다.** 사운드 실물이 하나도 없는 지금도 디스패처·호출부·검사가 전부 성립한다. 실물이 유입되면 `AudioOutput` 계약을 구현한 재생기를 주입하면 되고, 디스패처와 호출부는 손대지 않는다.

### SEAL 계열 편입 (인계 지시분)

SEAL-E 가 **화면 표면**을 보고, AUDIO 봉인 축이 **발화 경로**를 본다. 두 축이 짝을 이룬다.
반증에서 봉인 판정을 무력화하면 AUDIO 가 즉시 실패하고, "게이트에 걸려 안 울린 것"이 봉인 준수로 오인되지 않도록 **봉인 판정을 다른 어떤 판정보다 먼저** 두었다(시간을 아무리 전진시켜도 봉인은 뚫리지 않음을 별도 검사로 고정).

## 3. 총괄 판정 대기 (3건 — 전부 비차단)

| # | 사안 | 성격 |
|---|---|---|
| **A** | **D13 §8.3 오디오 값 2건 미전사** — 가상 채널 상한 **12** · 동일 SFX 재트리거 최소 간격 **0.05초** | **전사 누락 (구조 판단 아님)** |

### A — D13 §8.3 미전사 2건 (이번 작업의 유일한 정본 접촉면)

두 값은 **정본에 확정치로 실재한다**:
- D11 §6.3 표 — *"동시 발음 … 가상 채널 상한 **12** (확정 기준값 … 실구현 D12)"* / *"재트리거 … 동일 SFX 최소 간격 **0.05초** (확정 기준값 — D12/D13)"*
- D12 §10.2 — *"**가상 채널 상한 12** … **재트리거 최소 간격 0.05초** = 디스패처 게이트(값 D13)"*

그런데 **D13 별첨A §8.3 오디오 9항에 두 값이 없다**(§10 대장 D11 행도 10항 — 볼륨·햅틱 감쇠·햅틱 지속·덕킹·크로스페이드·광고 감쇠·스팅·트랙 길이·함성 간격). **결정 #14 ④(햅틱 지속 시간)와 정확히 동형** — D11 §8.2 이관 목록 누락으로 미전사였던 것이 뒤늦게 드러난 형태다.

**처리:** 값을 **발명하지 않았다.** D11 §6.3 원문 그대로 `core_params.csv` 에 넣고(`param_audio_virtual_channels,12` · `param_audio_retrigger_gate_sec,0.05`), 코드는 전량 데이터 경유로 읽는다 — 픽스처로 갈아 끼우면 거동이 따라오는지를 별도 검사로 고정했다(리터럴 회피).

> **판정 요청:** 두 값의 **D13 §8.3 전사**(대장 93 → 95항). 값·구조 무변경이며 결정 #14 ④ 전례 그대로다.
> 작업 중단 대신 진행을 택한 근거를 밝힌다 — 불변규칙 2의 중단 조건은 "**필요한 값이 D13에 없으면**"이고, 이 둘은 D11·D12가 '확정 기준값'으로 명시한 값이 D13 전사만 빠진 상태다. 임의 기입이 아니라 **창구 정리 사안**으로 판단했다. 이 판단 자체가 부적절하다면 되돌린다.

### B — FONT 검사의 성격 (V7 전례대로 스스로 정하지 않음)

**현재 경고형으로 두었다.** 차단형으로 먼저 켜면 판정 전에 게이트를 점유하게 되고, 그것은 "검증기 성격을 구현이 정했다"는 사실을 되돌리기 어렵게 만든다. 판정에 필요한 사실:

| 축 | 사실 |
|---|---|
| 오검출 위험 | 현 리포에서 0 — 결선 후 잔여 경고 0건 |
| 판정 근거의 성질 | 기계적(문법 수준). "폰트를 지정했는가"이며 **미적 판단이 아니다** — V7(작법 판단이 D04 소관이라 경고형)과 성격이 다르다 |
| 놓쳤을 때의 비용 | 레이아웃 파손. 눈 검증으로 잡히지 않음이 실측됨(37건) |
| 이름 | **`FONT` 로 지었다** — D12 §4.2가 확정한 것은 V1~V8이라 'V9'는 정본 확장을 함의한다. `MIX0`·`ARCH` 전례를 따랐다. 명칭도 판정 대상 |

> 위 4축은 차단형을 시사하나, **판정은 총괄 몫**이므로 지시가 올 때까지 경고형으로 둔다.

### C — `sound_map` 우선순위 3층 배정 [가안]

D11 §6.3은 **P1~P3의 성격만** 정하고 86행 개별 배정을 하지 않는다. 배정 원칙:
- **P1 정보성 = 명문 예시 6종 전속** (타이머 3 · 듀얼 예고 · 섀시 경고 · 레조넌스 공표) — 임의 확대 안 함
- **P2 결과성 28** = 결과음·스팅·징글·듀얼 결판·매치·GP 개시/종료·순위 스탬프·업적·펄스 소비
- **P3 장식성 52** = UI·큐음·앰비언스·릴 조작음

배정이 틀려도 게임 규칙에는 영향이 없다(컬링 순서와 P1 보호에만 관여). **확인만 요청**한다.
