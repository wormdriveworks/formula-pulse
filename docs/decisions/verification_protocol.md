# 검증 프로토콜 — 돌연변이 주입 반증 운용 노트

> 작성: 2026-08-11 (MS-2 원격 레인 종료 시점) · 근거: MS-1~MS-2에 걸친 독립 검증 5라운드의 실측
> 목적: **같은 함정을 다시 밟지 않기 위한 절차서.** 여기 적힌 항목은 전부 실제로 한 번씩 걸렸던 것이다.

---

## 0. 판정 원칙

**"통과했는가"가 아니라 "틀리게 만들면 실패하는가"로 판정한다.**
검사가 통과했다는 사실은 그 검사가 쓸모 있다는 증거가 아니다. 사본에 의도적 결함(돌연변이)을 주입해
검출되는지 확인해야 비로소 그 검사에 이빨이 있다고 말할 수 있다.

원본은 절대 수정하지 않는다. 실험은 사본에서만 하고, 결함은 고치지 말고 보고한다
(고치는 사람과 반증하는 사람을 분리하는 것이 요점이다 — 자기가 쓴 코드를 자기가 승인하면 순환이다).

---

## 1. 돌연변이 하네스의 함정 5종 (전부 실제로 걸렸다)

| # | 함정 | 증상 | 방어 |
|---|---|---|---|
| 1 | **주입이 조용히 no-op** | 패턴 불일치로 아무것도 안 바뀐 채 "미검출"로 보고됨 | 주입 성공을 `assert`로 확인. 확인 없는 "미검출"은 증거가 아니다 |
| 2 | **주입 결과가 컴파일 안 됨** | 파스 에러 → 클래스 로드 실패 → 검사가 실행되지 않았는데 통과로 보임 | 주입 후 컴파일 성립을 확인. 검사 수가 붕괴했는지 대조 |
| 3 | **게이트 일부만 실행** | 테스트만 돌리고 검증기를 빼면 미검출 수가 과대 집계됨 (실측: 240 → 실제 230) | 게이트 판정은 `run_tests.sh` + `validate.sh` **둘 다** |
| 4 | **관측 불가 돌연변이** | 효과가 가환이거나 이중 가드라 결과가 안 바뀜 | 미검출 보고 전에 **그 돌연변이가 관측 가능한 효과를 갖는지** 먼저 확인 |
| 5 | **단발 시행** | 희귀 분기(3매치 등)에 숨은 결함은 한 번의 시행으로 안 드러남 | 확률 경로는 수백 회 반복. 표본 확보 자체를 별도 단언으로 |

## 2. 검사 설계의 함정 4종

**① 자기 일관성.** 기대값을 검사 대상과 같은 데이터에서 읽으면 값이 바뀔 때 기대값도 함께 바뀌어
표류를 못 잡는다. → D13 확정값을 **문면 그대로 전사하는 블록**을 한 곳에 격리한다
(`test_tc_c.gd`의 `_d13_anchor_values()`).

**② 죽은 쪽 단언.** 같은 값이 두 곳에 정의돼 있으면 단언이 코드가 읽지 않는 쪽에 붙을 수 있다.
→ 단언 전에 `grep`으로 **실제 소비 경로**를 확인한다. 이중 정의는 지운다.

**③ 항진명제.** 참조를 비교하면 무슨 일이 있어도 참이다 (`info.get("events") == 같은 배열`).
→ 비교는 사본(`duplicate(true)`)으로. 검사식이 실제로 갈라지는지 주입으로 확인한다.

**④ 마법수 허용 오차.** 문면 불일치를 tolerance로 흡수하면 문제가 검사 뒤에 숨는다.
→ 성분을 정확히 단언하고, 불일치는 impl_log 보고 항목으로 올린다(불변규칙 9).

## 3. 게이트가 거짓말을 하는 방식 3종

| 방식 | 실측 | 방어 |
|---|---|---|
| 파스 에러가 통과 | 클래스 로드 실패로 검사 수가 108 → 2로 붕괴했는데 `TESTS_PASS` · exit=0 | 컴파일 게이트 + **검사 수 하한** |
| 컴파일 게이트 자체가 무동작 | `load()`는 파스 에러 스크립트에도 non-null을 반환 (정상 `reload()=0` / 파손 `43`) | `reload() != OK`로 판정 |
| 게이트가 자기 파스 에러로 죽음 | 종료코드는 잡히나 진단이 사라짐 | 호출부에서 **성공 토큰 부재 자체**를 실패로 |

> 게이트는 구조적으로 자기 자신을 검사할 수 없다. 자기가 안 돌면 아무 말도 못 한다.

## 4. 반복된 한 가지 형태 — **"만든 것"과 "작동함을 보인 것"의 간격**

이 세션에서 같은 형태가 세 번 나왔다:

1. **고치고 회귀 가드를 안 붙임** — 백업 회전·프로필 범위 교정을 되돌리는 돌연변이가 통과했다.
2. **게이트를 만들고 그것이 잡는지 안 봄** — 컴파일 게이트가 무동작인 채 "작동한다"고 커밋됐다.
3. **픽스처를 넣고 소비부를 안 부름** — `param_save_profile_count,2`를 픽스처에 넣어 두고
   `SaveManager`를 한 번도 부르지 않아 리터럴 `3`이 드러나지 않았다.

**교정·게이트·픽스처를 만드는 것과, 그것이 실제로 작동함을 보이는 것은 별개 작업이다.**
전자만 하고 후자를 건너뛰면 "고쳤다"는 기록만 남고 보호는 없다.

## 5. 현재 커버리지와 다음 공격 각도

**닫힌 축:** D13 확정값 전사(약 220칸 대조) · 구조적 0 축(효과 축 대장) · 봉인 5경로(다수 스핀 +
공개 표면 diff + 값 도메인) · 아키텍처 정적 규칙(정책 층 우회·코어 표준출력) · 데이터 주입 6종.

**남은 각도 (독립 레인 제안 — MS-3 착수 시):**
- **픽스처가 덮지 않는 표** — 현재 `core_params`·`crew`·`symbol_distribution` 3종만 오버라이드한다.
  나머지 20종의 소비부는 "데이터를 실제로 읽는가"가 미검증이다.
- **구조 JSON 값의 소비부** — 서킷·무대·캘린더의 값도 같은 방식으로 갈아 끼울 수 있어야 한다.
- **실기 판정(G-1·G-2·G-5)** — 눈과 실기기가 판정 주체라 원격에서 반증할 수단이 없다. 주력 머신 몫.

## 6. 실행 명령

```bash
bash tools/validators/validate.sh    # 검증기 V1~V8 + 혼입 0 + ARCH
bash tools/validators/run_tests.sh   # 컴파일 게이트 + 스위트 + 검사 수 하한
```

두 명령의 **종료코드로** 판정한다. 파이프(`| tail`)를 걸면 종료코드가 가려진다 —
실제로 그렇게 실패 상태를 커밋한 사례가 있다.
