## 작업 범위 (In)
1. **프로젝트 골격** — `godot/`에 Godot 4.7 프로젝트 생성 (Compatibility 렌더러, 디렉토리 = CLAUDE.md의 디렉토리 계약 준수). 어댑터 인터페이스 7종(D12 §2.2)을 추상 계약으로 배치하고 데스크탑 널/최소 구현만 채운다.
2. **검증기 + CI (TL-1)** — `tools/validators/`에 V1~V8(D12 §4.2 룰 대장) + 혼입 0 스캔(core 디렉토리 내 플랫폼 API 호출 검출) 구현. 로컬 단일 명령으로 실행 가능해야 하며, 빌드 전 단계에 고정한다 — 위반 1건 = 빌드 실패. [가안] CI 러너는 GitHub Actions로 결속(로컬 스크립트가 정본, Actions는 래퍼).
3. **데이터 파이프라인** — 스키마 로더(CSV/TSV·JSON·스트링 CSV) + MS-1 필요분 테이블 충전. 값은 전량 D13에서 옮긴다: 심볼 6분류 분포(A4)·매치 강도 효과·게이지·펄스 차지·섀시(A5)·듀얼 판정·AI 파라미터·시작 그리드 식·턴 시간(A1). **D13에 없는 값이 필요해지면 중단·보고.**
4. **GP 상태 머신** — `GP_START → LAP_LOOP → SECTOR_TURN(T1~T6) → {DUEL 복귀 | RETIRE | 다음 SECTOR_TURN} → 랩 종료 분기 → GP_FINISH → RESULT` (D12 §3.2). 상태 enum + 전이 표는 코드 상수. 고아 상태 0·미정의 전이 0.
5. **턴 시퀀스 T1~T6** — D12 §3.3 표 그대로. T4 개입 창은 홀드/리스핀(턴당 1회 한도)·펄스 차지 개입·확정을 커맨드 큐 직렬 처리로.
6. **정산 8단계** — D12 §3.4의 ①~⑧을 코드 상수 고정 순서로 구현 (C-2: 단계 신설·데이터화 금지).
7. **RNG 6스트림 + 세이브 골격** — 마스터 시드 파생, reel 소비 = 스핀 커밋 시점. 세이브에 전 스트림 시드+상태 직렬화(JSON+체크섬 골격 — D12 §7.1) → 재로드 시 동일 릴 결과 재현.
8. **디버그 실행 UI (최소)** — 1 GP를 사람이 처음부터 끝까지 돌릴 수 있는 화면 1장. D09 레이스 4존 골격의 자리 배치만 차용, 아트·사운드·VN·애니메이션 없음. 중계 로그는 T5 규격대로 **텍스트 키를 발행**하되, 프로토타입은 키에 대응하는 스텁 문구로 스트링 CSV를 최소 충전한다 (V2 참조 무결성 통과 유지 — 실텍스트 집필은 범위 외).
